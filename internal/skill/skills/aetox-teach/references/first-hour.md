# The first hour

Five demos. Each one is a thing to *do* with the user, not a thing to tell
them. Run one, stop, and let them react before reaching for the next.

The rule underneath all five: **use their material, never a made-up example.**
A demo on invented data teaches nothing, because the interesting part of this
app is that it is looking at their actual disk.

## 1. Say it in plain words, and watch it act

**The point:** this is not a chat window. The answer is a change on their
machine.

Ask what is annoying them on this computer right now. Almost any answer works:
a folder of downloads nobody has sorted, a receipt they need a number out of,
a page they keep re-checking by hand.

Then do it. Narrate one short line before each round so they can watch it
happen, and finish by naming the file or the change.

If they have nothing to offer, the safest opener is a read-only look at their
own machine: what is taking up space, what starts at boot. It is theirs, it is
true, and nothing is altered.

**Say afterwards:** that ran here, on this computer, and nothing was uploaded
to do it.

## 2. Point it at their files

**The point:** it can reach their work, and they control what it reaches.

Ask for a folder that matters to them. Naming the path is the request: the
window shows a card, and accepting adds the folder. Declining is an answer, so
take it and move on rather than asking again.

Then read something out of it and give back a real result: a summary of what is
in there, a spreadsheet from a pile of receipts, one renamed set of files.

**Say afterwards:** it sees the folders they add and nothing else, and some
folders are refused in every mode no matter what.

## 3. Desks and โหมดทำงาน

**The point:** two dials, and knowing them stops most confusion later.

Show, in one sentence each:

- **ผู้ช่วย** against **โค้ด**. Which tools are on the desk. Fixed for the life
  of a chat, and changing it means a new chat, which is free.
- **ลงมือ** / **วางแผน** / **คู่คิด**. How this turn runs. Switchable at any
  time, and the conversation is kept.

Demonstrate one only: switch to **วางแผน**, ask for something that would
normally change a file, and let them see it come back as a plan with nothing
touched. That single move explains the whole axis.

Warn them about the one sharp edge: in **คู่คิด** there are no tools at all,
so it cannot look anything up, and it cannot read its own documentation about
the app either.

## 4. Memory and โปรเจกต์

**The point:** next week does not start from nothing.

Two different things, and users mix them up:

- **Memory** is what Aetox worked out about them and their machine, and it is
  only kept once they approve it. Managed in ตั้งค่า > การเรียนรู้.
- **โปรเจกต์** is a folder of conversations with context files that ride into
  every chat inside it.

The demo: after finishing anything in step 1 or 2, propose remembering the one
fact that would have saved a question, and let them approve it. They see the
approval, which is the part that matters. Then start a new chat and show that
it already knows.

**Never** write into a project's context files unasked. Offer.

## 5. Making it theirs

**The point:** the app is a shelf, not a fixed list.

Four ways to extend, named in the order a normal person meets them:

- **ชุดคำสั่ง**, the `/` presets. They type `/` and pick one; whatever they
  type after the name goes into it. Eight ship with the app, covering web work,
  code work and summarizing a recording. New ones are written in
  ตั้งค่า > ชุดคำสั่ง, and this is the one extension you can write for them
  end to end.
- **สกิล**, instructions for a job, which the assistant reaches for on its own
  when a job matches. Installed in ตั้งค่า > สกิล, from GitHub or a `.zip`.
- **MCP servers**, connections to outside systems. ตั้งค่า > MCP servers. You
  cannot add one yourself, so point at the page.
- **เอเจน**, hiring a specialist. Their decision, always. Offer and wait.

The demo worth running is the preset: take something they said they do
repeatedly, write it as a preset, and let them fire it with `/`. It is the
shortest path from "this is a chat" to "this is mine".

## What to do when they go quiet

Silence usually means the ground moved too fast, not that they are satisfied.
Go back to their own work and do one more concrete thing with it. Do not start
a sixth topic.
