# มาตรฐานของเทมเพลตในคลังนี้

เอกสารนี้เขียนขึ้นหลังจากรื้อคลังกับเจ้าของงานหนึ่งรอบเต็ม และข้อสรุปที่แพงที่สุด
ของรอบนั้นคือประโยคเดียว:

> เทมเพลตที่เข้ารหัส "ค่ากลาง" เอาไว้ ไม่ได้ช่วยโมเดลที่เก่งอยู่แล้ว มันตรึงให้อยู่ที่ค่ากลาง

คลังรุ่นแรกมี 37 ส่วน หน้าตาเดียวกันหมด ขอบเส้นผมเหมือนกัน รัศมีเดียวกัน ไม่มีการ
เคลื่อนไหวสักชิ้น ทุกไฟล์คือของที่โมเดลเล็กเจนได้ในสิบวินาที การมีอยู่ของมันจึงไม่ได้
เพิ่มอะไร แต่ไปกดเพดานของงานที่ควรจะดีกว่านั้น เอกสารนี้คือเส้นที่ยกขึ้นมาใหม่

---

## ข้อ 0 — บททดสอบสิบวินาที

ก่อนเขียนไฟล์ใหม่ ถามข้อนี้ก่อนเสมอ

> ถ้าปล่อยให้โมเดลเจนเองโดยไม่มีไฟล์นี้ ผลจะต่างจากไฟล์นี้ไหม

ถ้าตอบว่า "ไม่ต่าง" **ไฟล์นั้นไม่ควรมีอยู่** เพราะมันไม่ได้เพิ่มอะไรนอกจากพันธะที่จะ
ต้องดูแลต่อ เทมเพลตมีค่าก็ต่อเมื่อมันถือของสามอย่างที่เจนสด ๆ ไม่ได้:

1. **ค่าที่วัดมาแล้ว** — พาเลตต์ที่ผ่านเครื่องตรวจตาบอดสี เรขาคณิตที่แก้สมการมา
   สีที่ดูดจากภาพจริง ไม่ใช่ค่าที่กะเอา
2. **เทคนิคที่ไม่ชัดเจน** — สิ่งที่ต้องลองผิดสิบรอบกว่าจะได้ และมีบันทึกว่าอะไรพัง
3. **ทิศทางศิลป์ที่เลือกได้** — ไม่ใช่ค่าเริ่มต้นอันเดียวที่ทุกงานหน้าตาเหมือนกัน

## ข้อ 1 — สามชั้น เลือกจากงาน ไม่ใช่จากหลักการ

คลังรุ่นแรกตั้งกฎ "ไฟล์เดียว ไม่มีรูป ไม่มีฟอนต์" ไว้กับทุกอย่าง แล้วเอากฎนั้นมาอธิบาย
ว่าทำไมงานถึงออกมาไม่สวย ซึ่งกลับหัวกลับหาง กฎนั้นซื้อความง่ายในการส่งมอบมา
ด้วยราคาที่แพงกว่าที่ยอมรับได้ในงานหลายประเภท ตอนนี้จึงมีสามชั้น และ**ไม่มีชั้นไหน
เป็นชั้นที่ต้องขออนุญาตใช้**

| | ชั้น A · ไฟล์เดียวจริง ๆ | ชั้น B · ไฟล์เดียว + โฟลเดอร์ของ | ชั้น C · โปรเจกต์เต็ม |
|---|---|---|---|
| อยู่ที่ | `sections/*.html` | `kits/<ชื่อ>/` | `projects/<ชื่อ>/` |
| ข้างในมี | HTML+CSS+JS+GLSL ในไฟล์เดียว | ไฟล์นั้น + `assets/` (รูป ฟอนต์ วิดีโอ) | โครง npm เต็ม |
| เปิดยังไง | ดับเบิลคลิก | ดับเบิลคลิก | `npm i && npm run dev` |
| พึ่งพา | ศูนย์ | ศูนย์ | ระบุได้ |
| เหมาะกับ | ส่วนประกอบที่เอาไปแปะที่ไหนก็ได้ | หน้าที่ความงามอยู่ที่ภาพถ่ายและตัวอักษร | สามมิติจริง ฟิสิกส์ postprocess หลายพาส |

**สิ่งที่เรียนมาแพงที่สุดของรอบแรก**: เพดานไม่เคยอยู่ที่ "ไฟล์เดียว" WebGL2 กับ GLSL
เขียนอยู่ในไฟล์เดียวได้โดยไม่ต้องมีไลบรารีสักตัว สิ่งที่กฎเดิมกั้นไว้จริง ๆ มีสองอย่าง
เท่านั้นคือ **ภาพถ่าย** กับ **ฟอนต์** และสองอย่างนั้นคือครึ่งหนึ่งของความสวยบนเว็บ
ชั้น B จึงมีอยู่เพื่อคืนสองอย่างนั้นกลับมาโดยไม่ต้องแลกกับการ build

เลือกชั้นจากคำถามเดียว: **ความงามของงานนี้อยู่ที่อะไร** อยู่ที่โครงกับการเคลื่อนไหว
เลือก A · อยู่ที่ภาพและตัวอักษร เลือก B · อยู่ที่พื้นที่สามมิติที่เดินเข้าไปได้ เลือก C

**บทเรียนจากรอบที่สอง (4 ก.ย. 2569)** — คลังรุ่นนี้สร้างงานหน้าขายไป 104 ส่วน
ที่ชั้น A ทั้งหมดโดยไม่เคยถามคำถามข้างบนสักครั้ง ผลคือหน้าที่ผ่านทุกข้อบังคับ
แต่เจ้าของงานตัดสินว่า "ต้นฉบับดีกว่านี้มาก" ซึ่งถูก และสาเหตุตรงกับที่ย่อหน้า
ข้างบนนี้ทำนายไว้เป๊ะ: งานประเภทหน้าขาย **ความงามอยู่ที่ภาพกับตัวอักษร**
จึงเป็นชั้น B ตั้งแต่แรก ไม่ใช่ชั้น A

**การเลือกชั้นไม่ใช่การตัดสินใจของคนเขียนเทมเพลต** มันเป็นการตัดสินใจของงาน
ถ้าไม่แน่ใจ ให้ถามเจ้าของงานก่อนเขียนบรรทัดแรก ไม่ใช่หลังเขียนไปแล้วร้อยไฟล์

## ข้อ 2 — ข้อบังคับ ทุกข้อต้องผ่าน

### โครงสร้าง
- **ไม่มี CDN ในชั้น A และ B** ของทุกชิ้นต้องอยู่ข้างไฟล์ เปิดจากดิสก์ จากยูเอสบี
  จากไฟล์แนบในเมลได้ ชั้น C ระบุ dependency ได้ แต่ต้องเขียนเหตุผลไว้ต่อหนึ่งตัว
- **คลาสรากขึ้นต้น `w-`** และกฎ CSS ทุกข้อต้องถูกจำกัดขอบเขตด้วยคลาสรากนั้น
  สองเทมเพลตในเอกสารเดียวกันต้องเอื้อมถึงกันไม่ได้ (หน้ารวมที่เอา 37 ส่วนมากอง
  ในไฟล์เดียวคือการทดสอบข้อนี้ ถ้าพังจะเห็นทันที)
- **สีมาจากโทเคน** ประกาศครบสามสถานะเสมอ: `:root` เปล่า (สว่าง) →
  `prefers-color-scheme` ที่กันด้วย `:not([data-theme="light"])` → `[data-theme="dark"]`
  ห้ามมีสีที่นิยามอยู่ในบล็อกธีมบล็อกเดียว
- **แลนด์มาร์กจริง** `<nav>` `<main>` `<footer>` `<table>` ที่มี `scope`
  `<blockquote>` ที่มี `<cite>` `<ol>` เมื่อลำดับคือความหมาย
- **รูปต้องมี `width`/`height` เสมอ** ชั้น A ชี้ไป `imgs/…` เป็นตัวยึด ชั้น B ใส่ไฟล์จริง
  ใน `assets/` ได้ ทุกชั้นห้ามลิงก์ไฟล์จากเซิร์ฟเวอร์คนอื่น และห้ามฝัง base64 ของภาพถ่าย
- **ฟอนต์** ชั้น A ใช้สแตกของระบบ ชั้น B แนบไฟล์ฟอนต์ใน `assets/` แล้วประกาศ
  `@font-face` เอง ทุกชั้นต้องมีสแตกสำรองที่จบด้วยฟอนต์ไทยจริง ไม่ใช่ generic เปล่า

### การเข้าถึง
- ป้ายชื่อมองเห็นเสมอ ไม่ใช่ `placeholder` ที่หายไปตอนพิมพ์
- โฟกัสเห็นชัดทุกตัวที่กดได้
- **สถานะห้ามบอกด้วยสีอย่างเดียว** ต้องมีคำหรือสัญลักษณ์กำกับ
- กราฟทุกใบต้องมีทางออกเป็นตัวเลข — `<title>` ต่อ mark และตารางเดียวกันใน `<details>`
- ตัวควบคุมใช้ของพื้นเมือง ห้ามเอา `<div>` มาแกล้งเป็น checkbox

### การเคลื่อนไหว
- **ทุกเทมเพลตต้องมีการเคลื่อนไหวอย่างน้อยหนึ่งชั้น** เว้นแต่จะเขียนเหตุผลไว้ในหัวไฟล์
  ว่าทำไมชิ้นนี้ต้องนิ่ง ส่วนที่นิ่งสนิทโดยไม่มีเหตุผลถือว่าไม่ผ่าน
- ทุกอย่างอยู่หลัง `@media (prefers-reduced-motion:no-preference)`
- **สถานะพักคือหน้าที่ครบ** ไม่ใช่หน้าว่างที่รออนิเมชัน คนที่ปิดการเคลื่อนไหวต้องเห็น
  ทุกอย่างเหมือนคนที่เปิด แค่ไม่ขยับ

### ความทนทาน
ทุกอย่างที่ใหม่กว่าปี 2020 ต้องมีทางลง ไม่ใช่ทางตัน — `@supports` หรือด่านใน
สคริปต์ และสิ่งที่เหลือเมื่อมันไม่ทำงานต้องยังเป็นหน้าที่ใช้ได้ ไม่ใช่จอดำ
รายการที่เจอบ่อย: WebGL2 · `backdrop-filter` · `mask-image` · `offset-path` ·
`animation-timeline` · `color-mix()` · `100svh`

## ข้อ 3 — ทิศทางศิลป์ อย่างน้อยสามทางต่อหนึ่งบทบาท

บทบาทสำคัญ (hero, ราคา, ฟีเจอร์, footer, แดชบอร์ด) ต้องมีอย่างน้อยสามทิศทางให้เลือก
แต่ละทิศทางมีชุดโทเคนและภาษาการเคลื่อนไหวของตัวเอง ไม่ใช่ไฟล์เดิมเปลี่ยนสี

ทิศทางที่คลังนี้รับรองแล้ว

| รหัส | ชื่อ | ลายเซ็น |
|---|---|---|
| `ed` | เอดิทอเรียล | ตัวอักษรคือภาพ ชิดซ้าย เส้นตารางบาง แถบเครดิตเลื่อน ไม่มีรูปก็อยู่ได้ |
| `gl` | กระจก | หมอกสีไหล แผ่นโปร่งซ้อนกัน ผลิตภัณฑ์เป็นพระเอก แสงกวาดตอนชี้ |
| `br` | บรูทัลลิสต์ | ขาวดำกับสีแสบหนึ่งสี ขอบหนา เงาเป็นบล็อกทึบ ไม่มีอะไรโค้ง |
| `gpu` | เชเดอร์ | พื้นหลังคำนวณบนการ์ดจอ ตอบสนองเมาส์ ไม่มีไฟล์รูปเลย |
| `ob` | วัตถุเป็นพระเอก | ของชิ้นเดียวใหญ่กว่าเฟรม ถูกขอบล่างครอปเหลือยอดโค้ง ~30% ของจอ ของถัดไปโผล่ที่ขอบ เปลี่ยนฉากด้วยการซูมทะลุ ตัวอักษรเบาและใหญ่กลางจอ พื้นลึกกว่าหน้า |

`ob` เพิ่มเมื่อ 5 ก.ย. 2569 จากคลิปอ้างอิงที่เจ้าของงานให้มา (หน้าสำรวจดาวเคราะห์) ตัวอย่าง
ใช้งานจริงคือ `pages/space-explorer.html` ซึ่งไม่มีไฟล์ภาพเลย — วัตถุวาดด้วย gradient
ทิศทางนี้จึงใช้ได้กับของที่วาดด้วยเรขาคณิตได้ (ดาว ลูกบอล นาฬิกา ขวด) หรือของที่มีภาพ
ถ่ายพื้นโปร่งอยู่แล้ว (ชั้น B) ไม่ใช่ทิศทางสำหรับหน้าที่ยังไม่มีวัตถุให้โชว์

เพิ่มทิศทางใหม่ได้ แต่ต้องมาพร้อมชุดโทเคนครบและตัวอย่างที่ใช้งานได้จริงอย่างน้อยหนึ่งชิ้น

## ข้อ 4 — คลังคำศัพท์การเคลื่อนไหว

ประกาศครั้งเดียว ใช้ซ้ำทุกที่ ชื่อคือสัญญา ไม่ใช่การตกแต่ง

| ชื่อ | ทำอะไร | ใช้ตอน |
|---|---|---|
| `rise` | เลื่อนขึ้นเข้าที่ | เข้าฉากของบล็อกข้อความ |
| `wipe` | กวาดเปิดจากซ้าย | ไฮไลต์ทับคำ เส้นคั่น ป้าย |
| `lift` | ลอยขึ้นพร้อมย่อเล็กน้อย | การ์ดหรือแผงใหญ่ |
| `slide` | เลื่อนไม่จบ | แถบวิ่ง แถบโลโก้ |
| `drift` | ลอยช้ามาก | หมอกสี พื้นหลัง |
| `sheen` | แสงกวาดผ่าน | ปุ่มหลักตอนชี้ |
| `grow` | งอกจากฐาน | แท่งกราฟ แถบความคืบหน้า |
| `draw` | ลากเส้นตัวเอง | เส้น SVG ใช้ `pathLength="1000"` |
| `spin` | หมุนรอบตัว | ตรา เข็ม ของประดับ |
| `blink` | กะพริบเป็นขั้น | จุดสถานะ เคอร์เซอร์ |
| `zoom` | ขยายทะลุเฟรมเพื่อเปลี่ยนฉาก | พระเอกของทิศทาง `ob` เท่านั้น ไม่ใช่การ์ด |
| `peek` | ของถัดไปโผล่ครึ่งชิ้นที่ขอบ | ตัวนำทางของ carousel แทนจุดใต้ภาพ |

**จังหวะที่ใช้จริง** เข้าฉาก 0.45–0.7 วิ · ไล่กันทีละ 60–90 มิลลิวินาที ·
hover 0.15–0.22 วิ · ของที่วนไม่จบ 8 วิขึ้นไป · easing เข้าฉากใช้
`cubic-bezier(.2,.7,.3,1)` กวาดใช้ `cubic-bezier(.7,0,.2,1)`

**`zoom` ไม่มีวินาที** มันผูกกับตำแหน่งเลื่อน (`animation-timeline`) ไม่ใช่เวลา
สิ่งที่ตั้งแทนคือ *ระยะ*: ต้องขยายจนล้นเฟรม **ทุกด้าน** ก่อนฉากจบ ที่ 1.5 เท่า
วัตถุยังอยู่ในเฟรม ตาอ่านว่า "โตนิดหน่อยแล้วเลื่อนไป" ที่ 2.6 เท่า (วัตถุกว้าง 150vw)
จึงอ่านเป็น "ทะลุ" และมีสองครึ่งเสมอ — มาถึง (entry, .62→1) กับทะลุ (exit, 1→2.6)
คนละ range ส่วน `peek` เป็นการจัดวางมากกว่าท่า จึงไม่มีคีย์เฟรมของตัวเอง
ตอนเข้าฉากใช้ `rise` ตามปกติ

## ข้อ 4.5 — พื้นผิว: รัศมี เส้นขอบ และระดับความสูง

ข้อ 4 คุมว่าของ **เคลื่อน** ยังไง ข้อนี้คุมว่าของ **วาง** อยู่ยังไง ประกาศครั้งเดียว
ที่ `page-shell.html` เหมือนกัน

### รัศมี — สี่ขั้น
| โทเคน | ค่า | ใช้กับ |
|---|---|---|
| `--radius-sm` | 10px | ของเล็กในการ์ด ป้าย ปุ่มไอคอน |
| `--radius` | 18px | การ์ด แผง ช่องกรอก |
| `--radius-lg` | 26px | กล่องเด่น แถบลอย ของที่ใหญ่กว่าครึ่งจอ |
| `--radius-pill` | 999px | ทรงเม็ดยา ชิป สวิตช์ ปุ่มหลัก |

ก่อนมีข้อนี้ คลังมีรัศมีเล็กอยู่ห้าค่า (6 7 8 9 10px) และทรงเม็ดยาเขียนสองแบบ
(`99px` กับ `999px`) ไม่มีใครตั้งใจให้ต่างกัน มันแค่ถูกพิมพ์คนละครั้ง

### เส้นขอบ — สองตัว ใช้ผิดคือบั๊กการเข้าถึง
| โทเคน | ใช้กับ | เกณฑ์ |
|---|---|---|
| `--line` | เส้นคั่น เส้นแบ่ง ขอบการ์ด | ไม่มี เพราะไม่ได้บอกตำแหน่งของอะไร |
| `--field` | ขอบของสิ่งที่กดหรือพิมพ์ได้ | **3:1 ขึ้นไปเสมอ** (WCAG 1.4.11) |

ก่อนมีข้อนี้ ทุกอย่างใช้ `--line` ตัวเดียว ซึ่งทำได้ 1.25:1 บนพื้นขาว แปลว่า
ขอบช่องกรอกทุกช่องในคลังมองแทบไม่เห็น คนสายตาเลือนหาไม่เจอว่าต้องพิมพ์ตรงไหน

### ระดับความสูง — สี่ขั้น ทุกขั้นเป็นเงาสองชั้น
| โทเคน | ใช้กับ |
|---|---|
| `--e1` | การ์ดที่วางนิ่ง |
| `--e2` | การ์ดตอนถูกชี้ · ปุ่มลอย |
| `--e3` | เมนู แผงลอย popover |
| `--e4` | กล่องโต้ตอบ แผงที่ทับทั้งหน้า |

**กฎสามข้อของเงา**
1. **สองชั้นเสมอ** ชั้นแคบเข้ม = เงาสัมผัส บอกว่าวางอยู่บนพื้น · ชั้นกว้างจาง =
   เงาบรรยากาศ บอกว่าสูงแค่ไหน เงาชั้นเดียวได้แค่ "ลอย" หรือ "แปะ" ไม่เคยเป็น "วางอยู่"
2. **ระยะเบลอโตเป็นเท่าตัวทุกขั้น** (6→18→36→68) ไม่ใช่บวกทีละนิด เพราะตาอ่าน
   ความสูงเป็นสเกลลอการิทึม สองขั้นที่ห่างกัน 4px ตาแยกไม่ออก
3. **offset แนวตั้ง = ครึ่งหนึ่งของเบลอเสมอ** นั่นคือมุมแสงคงที่ทั้งระบบ ของสองชิ้น
   บนหน้าเดียวกันที่เงาทอดคนละมุมคือสิ่งที่อ่านออกทันทีว่าผิด

**โหมดมืดไม่ใช่โหมดสว่างที่เงาเข้มขึ้น** บนพื้นมืด เงาดำแทบไม่มีผลเพราะพื้นก็ดำอยู่แล้ว
สิ่งที่บอกความสูงจริง ๆ คือ **เส้นสว่างบางที่ขอบบน** (`inset 0 1px 0 rgb(255 255 255/.05)`)
ซึ่งเลียนแบบแสงที่ตกลงบนสันของวัตถุ ทุกขั้นในโหมดมืดจึงมีทั้งเงาและเส้นสว่าง

## ข้อ 5 — สมุดกับดัก เก็บจากของจริงที่พังมาแล้ว

| อาการ | สาเหตุ | ทางแก้ |
|---|---|---|
| เฟรมแรกของหน้าว่าง ภาพย่อออกมาเป็นหน้าเปล่า | เข้าฉากเริ่มจาก `opacity:0` พร้อม `fill-mode:both` | ขยับ `transform` อย่างเดียว หรือไม่ก็ไม่ใส่ดีเลย์ |
| ความสูงขั้นต่ำไม่ทำงานทั้งข้อ | `100svh` อยู่ใน `clamp()` แล้วเอนจินไม่รองรับ ทั้ง `clamp` เลยเป็นโมฆะ | เขียน `vh` ก่อน แล้วยกระดับด้วย `@supports (height:100svh)` |
| วงแหวน/ส่วนโค้งไม่เรนเดอร์เลย | `conic-gradient` + `mask-image` + `filter` ซ้อนกัน บางเอนจินทิ้งทั้งชั้น | วาดเป็น SVG แทน ระบุพิกัดตรง ๆ |
| พื้นกลายเป็นหมอกเทาทั้งจอ | `mix-blend-mode:overlay` บนพื้นดำสนิท ผลต่างกันมากระหว่างเอนจิน | ใช้ `opacity` ต่ำ ๆ ตรง ๆ หรือทดสอบทั้งสองธีมก่อน |
| เลขในหน้าต่างเลื่อนไม่ขยับ | `white-space:pre` กันการตัดบรรทัด แถบตัวเลขเลยอยู่บรรทัดเดียว | `white-space:normal` + `word-break:break-all` + `width:1ch` |
| จุดหัวข้อโผล่ในเมนู | `[class*="w-"]` จับ substring ไปโดน `show-panel`, `arrow-nav` | `:is([class^="w-"],[class*=" w-"])` |
| เครื่องหมาย ฿ ชนเลขตัวแรก | `letter-spacing` ติดลบเกิน −0.02em บนตัวเลขใหญ่ | ไม่เกิน −0.015em เมื่อขึ้นต้นด้วยสัญลักษณ์สกุลเงิน |
| ป้ายแกน Y ถูกแท่งกราฟทับ | วาดแท่งเริ่มที่ x=0 ไม่มีรางซ้าย | เว้นราง แล้วเลื่อนหัวคอลัมน์ HTML ตามสัดส่วนเดียวกัน |
| ตัวหนังสือจมหายในพื้นหลังจัดจ้าน | ไม่มีม่านคั่นระหว่างพื้นกับข้อความ | วางไล่เฉดมืดจาง ๆ ใต้บล็อกข้อความเสมอ |
| `animation-timeline:view()` ไม่ขยับเลย ค้างที่สถานะจบตลอด | บรรพบุรุษตัวใดตัวหนึ่งมี `overflow` (แม้แต่ `hidden` ที่ใส่ไว้ตัดมุมโค้ง) กล่องนั้นกลายเป็น scroll container แล้วลูกทั้งสายก็ "อยู่ในสายตาเต็มใบ" ตลอดเวลา progress เลยเป็น 1 ทุกเฟรม | ถ้าตัด `overflow` ออกไม่ได้ ให้เปลี่ยนไปเข้าฉากตอนโหลดแทน หรือผูก `view-timeline-name` ไว้ที่บรรพบุรุษที่อยู่ในสายการเลื่อนจริง |
| ท่ากวาดกระโดดกลางทางแทนที่จะกวาด | คีย์เฟรมเขียนแต่ `from{clip-path:inset(...)}` แล้วปล่อยให้ `to` เป็นค่าเดิมของ element ซึ่งคือ `none` — `inset()` กับ `none` คำนวณระหว่างทางไม่ได้ เบราว์เซอร์เลยสลับทีเดียวที่ 50% | เขียน `to{clip-path:inset(0 0 0 0)}` ให้ครบเสมอ |
| ตั้ง `animation-range` ทีละชิ้นแล้วไม่มีผล ทุกชิ้นเริ่มพร้อมกัน | กฎรวมใช้ shorthand `animation:` ซึ่งรีเซ็ต `animation-range` กลับเป็น `normal` ด้วย และถ้ากฎรวมเฉพาะเจาะจงกว่า มันจะกลบค่าที่ตั้งทีละชิ้น | เขียนกฎรวมเป็น longhand (`animation-name`, `animation-fill-mode`, …) อย่าใช้ shorthand ในกฎที่จะถูกเสริมทีหลัง |
| ตัวอักษรในกราฟ SVG เล็กจนอ่านไม่ออกในบางคอลัมน์ | เขียนขนาดฟอนต์ในระบบพิกัดของ viewBox เป็นขนาดที่อยากได้ตรง ๆ แล้วพอ SVG ถูกย่อตามความกว้างคอลัมน์ ตัวอักษรก็ถูกย่อไปด้วย | เขียนเป็น (ขนาดที่อยากได้ ÷ อัตราย่อที่แคบสุดที่จะเจอ) เช่น อยากได้ 11px ในคอลัมน์ที่ย่อ 0.6 เท่า ต้องเขียน 18 |
| ของที่ position:absolute ลอยไปโผล่คนละที่ของหน้า | กล่องครอบเป็น position:static มันจึงไปยึดกับ initial containing block แทน | ตั้ง position:relative ที่กล่องครอบ · จับได้เฉพาะตอนกองรวมหลายเทมเพลตในหน้าเดียว ซึ่งเป็นเหตุผลที่ข้อ 7 บังคับการทดสอบแบบนั้น |
| ตรวจใน headless แล้วรายงานว่าไม่มีอนิเมชันสักตัว ทั้งที่ CSS ถูก | headless Chrome ตั้ง `prefers-reduced-motion: reduce` เป็นค่าเริ่มต้น บล็อก `no-preference` จึงไม่ถูกใช้เลย | สั่ง `emulateMediaFeatures` ให้เป็น `no-preference` ก่อนวัด แล้วค่อยสลับเป็น `reduce` เพื่อตรวจสถานะพักแยกอีกรอบ |
| ตั้งชื่อทิศทางว่า "กระจก" แล้วออกมาเป็นการ์ดทึบธรรมดา | แผ่นทึบ 82% และ **ไม่มี `backdrop-filter` เลย** ในส่วนส่วนใหญ่ · ถึงใส่ครบก็ยังไม่เป็นกระจกเพราะข้างหลังเป็นพื้นเรียบ ไม่มีอะไรให้มองทะลุ | กระจกต้องการสองอย่างพร้อมกัน: ความทึบไม่เกิน ~60% กับ **พื้นหลังที่มีลวดลายอยู่จริงข้างหลังแผ่น** ถ้าให้ไม่ได้ทั้งสองอย่าง อย่าเรียกมันว่ากระจก |
| `animation-timeline:view()` ใน carousel แนวนอน ไม่ขยับเลย ค้างที่สถานะจบ | `view()` วัดแกน block (แนวตั้ง) เป็นค่าเริ่มต้น ฉากทุกฉากอยู่ในสายตาแนวตั้งเต็มใบตลอด progress จึงเป็น 1 ทุกเฟรม ไม่มี error ไม่มีคำเตือน | เขียน `view(inline)` เมื่อแกนที่เลื่อนคือแนวนอน และ `@supports (animation-timeline:view(inline))` ให้ตรงกัน |
| แก้เป็น `view(inline)` แล้ว วัตถุยังค้างที่ scale 0.966 ตอน scrollLeft 0 ไม่ใช่ 1 | `view()` วัด*กล่องของ element ที่ถูกอนิเมต* ไม่ใช่ฉาก วัตถุที่กว้างกว่าจอ (150vw) ล้นสองข้าง จึง "เข้ามาไม่ครบ" ตลอดเวลา และข้อความกับ peek ก็วัดกันคนละกล่อง จางไม่พร้อมกัน | ประกาศ `view-timeline:--ชื่อ inline` ที่*ฉาก* แล้วให้ลูกทุกตัว `animation-timeline:--ชื่อ` — ทุกตัววัดจากกล่องเดียวกันที่กว้างเท่าจอพอดี |
| ครอปวัตถุด้วย `overflow:hidden` แล้ว `view()` วัดผิดกล่อง | `overflow` ที่ไม่ใช่ `visible` ทำให้กล่องนั้นเป็น scroll container วัตถุข้างในเลยไปวัดกับกล่องครอปแทน carousel (กับดัก `view()` ข้างบนในอีกรูป) | `clip-path:inset(0)` ครอปเหมือนกันแต่ไม่สร้าง scroll container |
| hero มีแถบเลื่อนแนวตั้งโผล่ ทั้งที่ตั้งแค่ `overflow-x:auto` | ค่าที่ไม่ใช่ `visible` บนแกนเดียว บังคับอีกแกนเป็น `auto` ตามสเปก วัตถุที่จมใต้ขอบล่างจึงเปิดแถบเลื่อน | เขียน `overflow-y:hidden` ให้ชัดคู่กัน |
| วัตถุที่ "จมใต้ขอบ 62%" โผล่มาทั้งชิ้นทับข้อความ | ระยะจมคิดเป็น % ของ*วัตถุ* ซึ่งกว้าง 150vw — 38% ของ 1,400px คือ 530px สูงกว่าจอ 450px | ยึดส่วนที่โผล่กับ*ความสูงจอ* (`top:calc(100% - 30vh)`) ไม่ใช่กับขนาดวัตถุ |
| ดาวหมุนแล้วแสงเงาหมุนตาม กลายเป็นลูกบอลกลิ้ง | `rotate` ทั้ง element ไฮไลต์กับขอบมืดที่วาดไว้เลยหมุนไปด้วย | แยกชั้น: พื้นผิวเลื่อนด้วย `background-position-x` (tile กว้าง 200% `repeat-x` เลื่อน 0→200% ลูปพอดี) แสงเงาเป็นชั้นบนที่นิ่ง |
| กฎใน `@media` จอแคบไม่มีผล ของยังอยู่ตำแหน่งเดสก์ท็อป | กฎเดสก์ท็อป `.a .b.next` เฉพาะเจาะจงกว่ากฎในมีเดีย `.a .b` มีเดียไม่ได้เพิ่ม specificity ให้ | เขียน selector ในมีเดียให้เฉพาะเจาะจงเท่ากันหรือมากกว่า (`.a .b,.a .b.prev,.a .b.next`) |
| ใส่อนิเมชันครบทุกส่วนแล้วหน้ายังนิ่งสนิท | ท่าเข้าฉากขยับ `translateY(14px)` ซึ่งเป็นระยะที่ตาแยกไม่ออกจากการเรนเดอร์ปกติ นับจำนวนอนิเมชันได้ 49 ตัวแต่ไม่เห็นสักตัว | ของที่ควรเห็นว่าเคลื่อนต้องมีระยะอย่างน้อย ~10% ของขนาดตัวเอง หรือมาตราส่วนเปลี่ยนอย่างน้อย .1 · ของประดับใช้ 14px ได้ ของที่เป็นพระเอกใช้ไม่ได้ |

## ข้อ 6 — หัวไฟล์ต้องมีบันทึกเหตุผล

ทุกไฟล์เปิดด้วยคอมเมนต์ที่ตอบสามคำถาม ไม่ใช่คำอธิบายว่าไฟล์นี้คืออะไร

1. **ทำไมชิ้นนี้ถึงมีอยู่** — ต่างจากชิ้นที่ใกล้เคียงที่สุดในคลังยังไง
2. **ค่าไหนมาจากไหน** — วัดมา คำนวณมา หรือรันเครื่องตรวจมา
3. **อะไรที่ลองแล้วพัง** — เพื่อคนต่อไปจะได้ไม่เสียเวลาซ้ำ

บันทึกพวกนี้คือส่วนที่โมเดลเจนเองไม่ได้ และเป็นเหตุผลจริง ๆ ที่คลังนี้ควรมีอยู่

## ข้อ 8 — สิ่งที่ห้าม

- ข้อความหลอกแบบ lorem ipsum และตัวเลขที่ไม่มีหน่วยหรือที่มา
- การ์ดสามใบเรียงเหมือนกันสามแถวรวด
- สถานะที่บอกด้วยสีอย่างเดียว
- hero สูง `100vh` ที่ดันเนื้อหาจริงออกนอกเฟรมแรก — **ยกเว้น** เมื่อ hero *คือ*
  เนื้อหา และมีวัตถุตัดขอบล่างชัดเจน (ทิศทาง `ob`) การครอปนั้นเป็นสัญญาณเลื่อน
  ในตัว ข้อห้ามนี้มีไว้กันหน้าที่เอาที่ว่างมาแทนเนื้อหา ไม่ได้กันวัตถุที่ใหญ่กว่าเฟรม
- คัดลอกโค้ดหรือไฟล์ของเว็บอื่นมาทั้งชิ้น — ศึกษากลไกแล้วเขียนใหม่เองเท่านั้น
  และห้ามลิงก์ asset จากเซิร์ฟเวอร์ของเขา
- เพิ่มไฟล์ใหม่ที่ทำสิ่งเดียวกับไฟล์เดิมโดยเปลี่ยนแค่สี — นั่นคือทิศทางศิลป์
  ไม่ใช่เทมเพลตใหม่ ให้ไปเพิ่มในระบบทิศทางแทน
