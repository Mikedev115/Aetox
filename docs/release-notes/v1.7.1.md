## opencode-go / muse-spark-1.3-contributor ตอบ 400 ทุกเทิร์น

**เรื่องเดิม** ผู้ใช้รายงานว่าโมเดลนี้ใช้ไม่ได้เลย 2 วัน 2 เครือข่าย — ระดับคิด xhigh ได้ 400
`Thinking mode does not support this tool_choice`, minimal ได้ 500, ขณะที่โมเดลกับแพลนเดียวกัน
ผ่าน opencode CLI ใช้ได้ปกติ คนรายงานชี้ไปที่ `reasoning_effort` ที่ Aetox แปะทุก request

**ที่ไล่เจอจริง** บันไดรีเพลย์ของ Aetox ถอด `reasoning_effort` แล้วส่งซ้ำอยู่แล้วตั้งแต่เห็นคำว่า
thinking ใน 400 — และสิ่งที่ผู้ใช้เห็นคือ error ของรอบที่สอง ซึ่งไม่มี effort แล้วก็ยังพัง ประโยคนั้นเป็นของ
DeepSeek-stack ที่ปลายทาง: โมเดลอยู่ในโหมดคิดไม่ว่าจะส่ง effort หรือไม่ และโหมดคิดปฏิเสธฟิลด์
`tool_choice` สิ่งเดียวที่ Aetox ส่งต่างจาก opencode CLI คือ `tool_choice:"auto"` ทุกเทิร์นที่มีเครื่องมือ

**รุ่นนี้** `"auto"` คือค่าปริยายของสเปกอยู่แล้ว จึงไม่ส่งบนทุกแถว OpenAI-compatible (`"required"`
และชื่อฟังก์ชันยังส่ง เพราะเป็นข้อบังคับจริง) และบันไดรีเพลย์ได้ขั้นใหม่: 400 ที่เอ่ยชื่อ `tool_choice`
ถอดฟิลด์นั้น จำต่อโมเดล แล้วส่งซ้ำ — ถาม*ก่อน*ขั้น thinking เพราะประโยคเดียวกันมีทั้งสองคำ อ่านสลับกัน

**ที่ยังไม่ได้พิสูจน์** ยังไม่ได้ยิงจริงกับ opencode-go: ในเซสชันที่แก้ไม่มีคีย์ และการลองของเจ้าของ
ได้ 403 ก่อนถึงโมเดล — รุ่น `-contributor` ต้องกดยินยอมให้เก็บข้อมูลต่อ workspace ที่
opencode.ai/workspace/…/go ครั้งเดียวก่อน (คนรายงานผ่านตรงนี้แล้ว) ส่วน 500 ที่ minimal

`TestAutoToolChoiceStaysOffTheWire`, `TestARefusedToolChoiceIsReplayedWithoutIt`

## แจ้งปัญหา แล้ว GitHub ตอบ "Whoops, something went wrong"

**เรื่องเดิม** (v1.6.3 portable, Windows 10) กดแจ้งปัญหาที่ ตั้งค่า › เกี่ยวกับ หน้า issues/new
ไม่ขึ้น GitHub ตอบ 500 งบความยาว URL ตั้งแต่ 18 ส.ค. คือ 8,000 ตัวอักษร ตั้งไว้เทียบเพดานคำสั่งของ
Windows (32,767) โดยไม่มีใครวัดเพดานของ GitHub เอง

**วัดแล้ว** (15 ก.ย. 2026, curl กับ issues/new) ล็อกอินอยู่: 6,934 เปิดได้ / 7,012 เป็น 500 ·
ยังไม่ล็อกอิน: GitHub เด้งไปหน้าล็อกอินพร้อม `return_to` ที่เข้ารหัสซ้ำอีกชั้น (ยาวขึ้น ~1.6 เท่า)
และ*ทิ้งมันเงียบ ๆ* เหนือ 4,534 — ล็อกอินเสร็จเจอฟอร์มว่าง · เหนือ ~8,000 เป็น 414/502
ล็อกดีบักเต็มหนึ่งชุดพา URL ไปชนงบ 8,000 ทุกครั้ง รายงานจากคนที่ล็อกอินอยู่จึงเป็น Whoops ทุกใบ

**รุ่นนี้** งบ 4,000 พ้นทั้งสองเพดาน ส่วนที่ถูกตัดคือล็อก (ตัดจากปลายเก่า ตัวปัญหากับเวอร์ชันเขียนก่อนเสมอ)

## แท็บเบราว์เซอร์ทับอวตาร

**เรื่องเดิม** เจ้าของส่งภาพมา: แผงเบราว์เซอร์วาดทับตัว companion "ซึ่งไม่ปกติ" — z-index ช่วยไม่ได้
เพราะแท็บเบราว์เซอร์เป็นหน้าต่าง Win32 จริงที่ติดกาวไว้บนแผง และ compositor วาดหน้าต่างเนทีฟทับทุกชั้น
ของ DOM โดยไม่ถาม DOM

**รุ่นนี้** ขึ้นทับไม่ได้ก็ก้าวหลบ: ทะเบียนสี่เหลี่ยมของหน้าต่างเนทีฟบนจอ (`workbench/nativeRects`)
แผงเขียนตอนแท็บมองเห็น ล้างตอนซ่อนหรือปิด ตัว companion หาจุดใกล้สุดที่พ้นทุกสี่เหลี่ยม —
ทางออกซ้าย/ขวา/บน/ล่างที่ยังอยู่ในหน้าต่าง ทางที่พ้นทุกอันชนะทางที่แค่ย้ายไปทับอีกอัน สั้นสุดชนะ —
ก้าวหลบเมื่อแท็บมา/โต/ย้าย ลากเข้าไปใต้แท็บไม่ได้ และจุดที่ถูกดันไม่บันทึกทับจุดที่ผู้ใช้ลากไว้
แท็บเต็มจอ = ไม่มีที่ไป ก็อยู่ที่เดิม ตัวบนเดสก์ท็อป (หน้าต่างแยก) ไม่เกี่ยวเพราะอยู่เหนือทั้งแอปอยู่แล้ว
เทสต์ที่เพิ่มในรุ่นนี้: `stands clear of a native browser window, and comes back when it goes`
และ `keepOut` สี่กรณี

## ที่ตั้งใจไม่ทำ

- ไม่เสนอระดับ `off` ให้ opencode-go: บนแถวนี้การละ `reasoning_effort` ไม่ได้ปิดการคิด
  สวิตช์ที่ไม่ทำอะไรคือสิ่งที่ thinking_capabilities.go ปฏิเสธมาตลอด
- ไม่แตะฟองข้อความของ companion ที่ยื่นไปทางซ้ายของตัว — ฟองใต้ขอบแท็บผิดน้อยกว่าตัวใต้แท็บ
- แม่แบบตัวตน (th.ts / zh.ts ที่ค้างในทรี) เป็นงานที่เจ้าของยังคิดไม่จบ ไม่ได้อยู่ในรุ่นนี้
