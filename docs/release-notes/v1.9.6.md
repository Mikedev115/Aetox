รุ่นนี้จัดหน้าเลือกผู้ให้บริการใหม่ให้แยกตามชนิดสิทธิ์ที่คุณมี (API key, Subscription Key, OAuth, รันในเครื่อง)

## ผู้ให้บริการแยกตามชนิดสิทธิ์ และเลือกเป็นการ์ดสองขั้น

**เดิม** หน้าตั้งค่าโมเดลรวมทุกเจ้าไว้ในรายการเดียว แยกไม่ออกว่าอันไหนใช้ API key อันไหนเป็นแพ็กเกจที่สมัครไว้
และปุ่มเพิ่มปลายทางของตัวเองหาไม่เจอ
**รุ่นนี้** เลือกผู้ให้บริการเป็นการ์ดแบ่งหมวดก่อน แล้วค่อยเข้าหน้าของเจ้านั้น

- ห้าหมวด: แพ็กเกจที่สมัครไว้ · API ผู้ผลิตโมเดล · ตัวกลางรวมหลายเจ้า · รันในเครื่อง · ปลายทางของคุณเอง
  สถานะเป็นคำ เจ้าที่แชตใช้อยู่มีป้ายและปักหมุดขึ้นบนสุดได้
- หน้าของเจ้านั้นเต็มความกว้าง มีทางกลับ ‹ ผู้ให้บริการ และคืนตำแหน่งเลื่อนเดิม ที่เคยเด้งไปมาเพราะการ์ดสูงตามเนื้อหา
  ตอนข้อมูลบัญชีกับรายการโมเดลมาถึง (903 ↔ 1105px) แยกสองขั้นแล้วไม่มีอะไรวางข้างหน้ารายละเอียด
- "เพิ่มปลายทางของคุณเอง" อยู่ท้ายหน้าต่างเพิ่ม provider ของทุกหมวด ไม่ซ่อนอยู่หมวดสุดท้าย
- ชนิดสิทธิ์: API / Subscription Key / OAuth / runtime / ในเครื่อง พร้อมเงื่อนไขใช้ได้เฉพาะแชต ใช้ได้เฉพาะงานโค้ด หรือถูกบล็อก
  Subscription Key ของ MiniMax (`sk-cp-`) ถูกแยกจาก API key ก่อนส่งคำขอใด ๆ
- แพ็กเกจใหม่: `minimax-m-plan`, `zai-coding-plan` (บันทึกค่าได้ แต่ใช้ไม่ได้จนกว่า Z.AI รับรอง Aetox) และ `chutes`
  (API key หรือ OAuth ปุ่ม sign in ขึ้นเมื่อตั้ง `CHUTES_OAUTH_CLIENT_ID`) Kilo ดูยอดคงเหลือบนเว็บเท่านั้น

  (ข้อความ commit แบ่ง commit ร่างและรีวิว PR รีวิวแชต) ยังใช้ได้ เพราะเป็นงานที่คุณสั่ง
- worker ที่โปรไฟล์ระบุผู้ให้บริการเอง ถูกบันทึกและคิดราคาที่ผู้ให้บริการนั้น
- บรรทัดโมเดล "codex · gpt-6.1-sol · high" เป็นคอมโพเนนต์เดียว โลโก้สีจริง ชื่อผู้ให้บริการ โมเดล และระดับคิด

## Git: เปลี่ยนแปลง ประวัติ สาขา เป็นสามมุมมองในแท็บเดียว

**เดิม** working tree ซ้อนอยู่เหนือไทม์ไลน์แล้วเบียดกัน ไฟล์ 100 ไฟล์ทำให้ไทม์ไลน์เหลือแถบเดียว
และมีปุ่ม `main ▾` สองปุ่มหน้าตาเหมือนกันแต่ทำคนละอย่าง
**รุ่นนี้** แถบรีโปบนสุดบอกสาขาครั้งเดียว พร้อมสถานะ remote และปุ่มดึงลง ส่งขึ้น fetch ในแถวเดียว

- เปลี่ยนแปลง: กล่องคอมมิตเป็นช่องพิมพ์ก่อน แยกด้วย AI เหลือปุ่มเดียวใต้กล่อง การ์ดที่แยกไว้ยังอยู่เมื่อกลับมา
- ประวัติ: ค้นหาและเมนูกรองชนิดปุ่มเดียวแทนชิปเจ็ดอัน เมื่อดูสาขาอื่นมีแถบบอกพร้อมทางกลับ
- สาขา: ทุกสาขากับ worktree ที่เดียว สลับ เปิด worktree ดูประวัติ เทียบ รวม (อ่านผลเทียบก่อนแล้วยืนยันอีกครั้ง) และสร้างสาขา
- สามมุมมองเปิดค้างไว้ ข้อความที่พิมพ์ค้างกับการ์ดที่ AI กำลังเขียนไม่หาย มุมมองที่ไม่ได้ดูไม่อ่าน git

## แผงขวาปิดได้จริง และหน้าเริ่มชูเบราว์เซอร์

**เดิม** ปิดแผงขวาแล้วมันเปิดกลับเองทุกครั้งที่เอเจนเปิดเบราว์เซอร์ ไฟล์ หรือเทอร์มินัล
รวมถึงตอนสลับไปแชตที่มีแท็บค้างหรือเปิดแอปใหม่
**รุ่นนี้** ถ้าคุณกดปิดเอง แผงปิดค้าง (จำข้ามการเปิดแอปใหม่ด้วย) แท็บที่เอเจนเปิดระหว่างนั้นขึ้นเป็นจุดบนปุ่มแผง
แผงกลับมาเปิดเมื่อคุณกดปุ่มเอง หรือกดเปิดของที่อยู่ในแผงเอง เช่น ชิปไฟล์ หรือ "เปิดแผนเต็ม"

- หน้าเริ่มของแผงที่ยังไม่มีแท็บ ชูเบราว์เซอร์เป็นการ์ดกล่องช่องพิมพ์ ตามด้วยเทอร์มินัล ไฟล์ สไลด์ ชิ้นงาน
  และแถวแผน ห้องทำงาน ห้องตัด บนพื้นตารางกับเงาโลโก้แบบเดียวกับหน้าแชท
- ตัดแสงฟุ้งกับ backdrop-filter ออกเพื่อความลื่น วัดใน Chrome headless เทียบรุ่นมีเบลอ ยัง 60fps ทั้งคู่
  ตอนลากขยายแผง raster ลด 20% layerize ลด 33%

## ชี้ให้เอเจนดู: วงรอบอะไร เอเจนได้สิ่งที่อยู่ในวง

**เดิม** โหมดวาดบนหน้าเว็บอ่านทุกรอยเป็นเส้น คือเก็บชิ้นที่อยู่ใต้ปลายปากกา แต่การวงลากปากกาอ้อมด้านนอกของสิ่งที่วง
เอเจนจึงได้ของรอบ ๆ (วงรอบปุ่ม Save ได้ `#bar` วงการ์ดใบแรกได้ `#grid` กับการ์ดข้าง ๆ)
**รุ่นนี้** ถ้ารอยเป็นวงที่ปลายกลับมาใกล้จุดเริ่ม (ไม่ต้องบรรจบสนิท) เอเจนได้ชิ้นที่อยู่ในวง
ถ้าในวงไม่มีชิ้นไหนอยู่ครบ ได้ชิ้นที่อยู่กลางวง ส่วนเส้นเปิดยังอ่านใต้ปากกาเหมือนเดิม

แต่ละชิ้นบอกพิกัด เลขรอย และว่าอยู่ในวงหรือใต้เส้น เพื่อให้โมเดลเทียบกับภาพที่แนบได้
ชุดทดสอบเดิมหลังแก้: วงปุ่มได้ `#target` วงการ์ดได้ `#c1` วงสองการ์ดได้ทั้งสองใบ วงไม่บรรจบยังได้ `#target`
และขีดเส้นใต้ย่อหน้ายังได้ `#para`

## เครื่องระยะไกล: ตั้งพอร์ต ไฟล์คีย์ และเครื่องกลางต่อเครื่อง

**เดิม** แต่ละเครื่องกรอกได้แค่ที่อยู่ ชื่อ และโฟลเดอร์ พอร์ต คีย์ และ jump host ต้องไปเขียน `~/.ssh/config` เอง
**รุ่นนี้** กล่องเพิ่ม/แก้ไขมีส่วนพับ "การเชื่อมต่อ ssh" และปุ่ม "เลือกจาก ~/.ssh/config"

- พอร์ต (1–65535) ไฟล์คีย์ และเครื่องกลาง ถูกส่งให้ ssh ทุกครั้ง ทั้งตรวจเครื่อง ติดตั้ง สตาร์ต หยุด log และอุโมงค์
- ไม่มีช่องรับตัวเลือก `-o` อิสระ เพราะ `ProxyCommand` กับ `LocalCommand` สั่งรันโปรแกรมบนเครื่องนี้ได้
- ไฟล์คีย์ที่ไม่มีอยู่ถูกปฏิเสธ และ token ถูกลืมเมื่อเครื่อง พอร์ต หรือเครื่องกลางเปลี่ยน
- ไฟสถานะขึ้น "กำลังต่อใหม่" เฉพาะเมื่อสายหลุดจริง เดิมฟังก์ชันราว 260 ตัวที่ไม่คืน error ส่งสถานะนี้ทุกครั้งที่เรียกไม่สำเร็จ
  รวมถึง "no such method" ของแอปกับ engine คนละรุ่น (log เครื่องหนึ่งมี DevServers 110 ครั้ง DeskStarters 36 ครั้ง)
  และส่งไปโดยไม่มีเครื่องปลายทาง หน้า เครื่องระยะไกล จึงเคยขึ้น "เครื่องยนต์อยู่ที่เครื่องนี้" ทั้งที่ต่อ wsl อยู่

## Undo ไม่หายเมื่อมี lock ค้าง

**เดิม** lock ของ git ที่ค้างตั้งแต่ 12 ก.ย. ทำให้ทุกเทิร์นไม่มีจุด Undo ใหม่ และ Undo ย้อนไปเทิร์นเก่าที่บังเอิญจับได้
**รุ่นนี้** snapshot ใช้ index ส่วนตัวต่อการทำงาน ไม่ลบหรือแย่ง lock ของ process อื่น และต่อ chain ด้วย
`update-ref` แบบ compare-and-swap ไม่ให้ link ของอีก engine หาย

- ถ้า capture ล้ม Undo หมายถึงเทิร์นนี้ ไม่ใช่เทิร์นที่จับได้ล่าสุด
- เปิด engine ใหม่ไม่ช้า: เก็บสำเนา index ไว้ใน `<gitDir>/aetox-index` วัดบนรีโปที่มี 10,415 ไฟล์ เทิร์นแรกหลังเปิดใหม่ 1.87 → 0.40 วินาที
- สอง store บน shadow repo เดียวกัน (CLI กับเดสก์ท็อป) เขียน object เดียวกันชนกันบน Windows ลองซ้ำได้สองครั้ง
  เทสต์ที่เคยล้ม 3/4 เมื่อรันขนานสี่ชุด หลังแก้ล้ม 0 ใน 12 ชุดขนาน

## เอเจนไม่ส่งซ้ำสิ่งที่ประวัติมีอยู่แล้ว

**เดิม** เมื่อแชตเปิดกลับมา (สลับแชต รีสตาร์ต เปลี่ยนโหมด) engine ใหม่เริ่มด้วยบันทึกว่าง ขณะที่ประวัติที่คืนมามีของเดิมครบ
จึงส่งซ้ำ ตัวเลขจากฐานข้อมูลเครื่องหนึ่ง (4 ก.ย.–2 ต.ค. 2026):

| สิ่งที่ส่งซ้ำ | ครั้ง | ขนาด |
|:--|:--|:--|
| คำแนะนำเครื่องมือแบบ "sent once" | 333 ครั้งจาก 238 คู่เซสชัน/เอเจน | ไม่ได้วัด |
| เนื้อหาเต็มของ `skill_view` | 82 ครั้ง | ~620 KB |
| บรรทัดเดิมที่ `read` อ่านซ้ำ | 141 ครั้ง | ~230 KB |

**รุ่นนี้** ก่อนส่ง เอเจนถามประวัติว่าของนั้นยังอยู่ใน context ไหม ประวัติคือความจริง ไม่ใช่บันทึกแยก
ยังอยู่ก็ไม่ส่ง ถูกบีบอัดหายหรือสร้างจาก transcript ก็ส่งใหม่ `read` ยังเทียบเลขบรรทัดและข้อความกับไฟล์ตอนนี้ทุกครั้ง

## ค้นหาไม่เดินเข้าโฟลเดอร์ที่ git ignore

**เดิม** `grep`/`glob`/`fs find`/`search_files`/`diagnostics` ข้ามแค่รายชื่อตายตัว ไม่ถาม `.gitignore`
`grep` เดียวกับตอนเกิดเหตุ ("sendChatAction|Telegram|telegram" `*.go`) เดินเข้า `output/` ที่มีสำเนาซอร์สจาก bench
ใช้เกิน 10 นาทียังไม่จบและผลซ้ำหลายชุด
**รุ่นนี้** ถาม git ว่าอะไรถูก ignore (`ls-files --others --ignored`, 0.15 วินาที, cache 30 วินาที) ไม่ parse `.gitignore` เอง
`grep` เดิมเหลือ 1.0 วินาที 22 ไฟล์ `glob **/*telegram*` 2.9 → 0.1 วินาที

- ระบุ path เข้าไปในโฟลเดอร์ที่ ignore ตรง ๆ ยังค้นได้ นอก git repo ทำงานเหมือนเดิม
- ลูกมือที่เดา path เต็มจากชื่อโปรเจกต์ (เคยได้ "ไม่พบ" แล้วค้นทั้ง `D:\Aetox` ราวหนึ่งนาที) ได้ error ที่บอกทาง:
  "this project is <root>, where internal/engine exists; pass the project-relative path"
- เมื่อเซสชันจำกัดในโปรเจกต์ เดิมตอบว่า "the user has to add it first" ซึ่งชี้ผิดทาง ตอนนี้บอกว่า path ไม่มีอยู่จริงพร้อมทางที่ถูก

## ตรวจโค้ดหลังแก้ไฟล์ไม่รอเปล่า

**เดิม** ตั้งแต่ 30 ก.ย. เวลากลางของ edit/write ขึ้นจาก ~0.4 เป็น ~8.4 วินาที
**รุ่นนี้** สองสาเหตุถูกแก้:

- `marksman` ส่ง diagnostics เฉพาะเมื่อมันเปลี่ยน ไฟล์ markdown ที่สะอาดจึงรอครบ 8 วินาทีแล้วจบ "timed_out, not checked"
  ตอนนี้การตรวจอัตโนมัติข้ามทันทีพร้อมบอกเหตุผล เรียก diagnostics เองยังตอบได้
- `typescript-language-server` ตกไปใช้ TypeScript global ซึ่งบนเครื่องหนึ่งเป็น TS 7 (ไม่มี tsserver) ทุก `.ts` จึง "never answered"
  เสีย 3.4 วินาที ตอนนี้ใช้ `tsserver.js` ของโปรเจกต์ (ที่ root หรือลึกสองชั้น ไม่เอาของ dependency)
  วัดจริงจับ type error ได้ 0.39 วินาที

## เชลล์: ปฏิเสธเฉพาะสิ่งที่เป็นปัญหาจริง และบอกรหัสออก

- `$(...)` ที่แค่จัดข้อความแสดงผล เช่น `"HTTP $($r.StatusCode)"` ไม่ถูกปฏิเสธว่า "builds a path while it runs" อีก
  ในฐานข้อมูลเซสชันเครื่องหนึ่งมีการปฏิเสธด้วยเหตุนี้ 68 ครั้ง 49 ครั้งไม่มี path เลย ตอนนี้ปฏิเสธเฉพาะเมื่อกลายเป็น path
- บรรทัดถูกตรวจแบบเข้มว่า "ส่งต่อให้ shell" เฉพาะเมื่อ shell ได้รับข้อความไปรันจริง (`sh -c`, `cmd /c`, `pwsh -Command`, `-ArgumentList`)
  `Get-ChildItem -Recurse cmd` กับ `.StartsWith('//')` ไม่ถูกนับอีก เล่นซ้ำ 68 คำสั่งจริงที่เคยถูกปฏิเสธ เหลือ 4 ซึ่งถูกต้องทั้งหมด
- คำสั่งที่ไม่พิมพ์อะไรแล้วจบด้วยรหัสไม่ใช่ศูนย์ ขึ้น "(no output, exit status 3 in PowerShell)" แทน "(command failed)"
  ทั้ง shell และ git (เคยเกิด 29 ครั้งกับการค้นที่ไม่เจอ `Get-Command` ที่ว่าง และ `diff` ของไฟล์ที่ต่างกัน)

## สิทธิ์มอบงาน: ตัวหลักสามตัวมีลูกมือของตัวเอง และเลือกทีมมาลงทั้งทีม

**เดิม** หน้าสิทธิ์มอบงานเป็นรายชื่อจ้างที่ติ๊กเป็นรายตัว และสวิตช์ลูกมือเป็นของส่วนกลาง ปิดทีเดียวทั้งผู้ช่วยและโค้ด
**รุ่นนี้** หน้านี้แสดงตัวหลักสามตัว (ผู้ช่วย · โค้ด · เลขา) แต่ละตัวมีลูกมือของมันเอง กับทีมที่คุณเลือกมาลงให้มัน

- ลูกมือเป็นของใครของมัน ปิดลูกมือของผู้ช่วยไม่ปิดของโค้ด เลขาไม่มีมือในตัว งานที่ต้องลงมือส่งให้ทีมเสมอ
- เลือกทีมทั้งทีม ไม่เลือกสมาชิกทีละคน ทีมที่มีหัวหน้า งานไปที่หัวหน้าทีม ทีมไม่มีหัวหน้า ตัวหลักจ้างสมาชิกเอง
  ทีมที่ไม่ได้เลือกไม่ถูกเสนอให้ `task` และไม่ขึ้นใน chip รายชื่อของแชต
- เครื่องที่ไม่เคยเปิดหน้านี้ถึงเท่าที่เคยถึงก่อนมีหน้า ค่าที่เลือกมีผลเมื่อมีคนตอบเท่านั้น
- ลูกมือออกจากหน้าบุคลากร (ยศลูกมือถูกถอด) ไฟล์เอเจนที่โหลดไม่ผ่านยังโชว์ที่นั่นพร้อมเหตุผลจนกว่าจะแก้
- หัวของแผนกหรือบริษัทไม่สืบการเลือกของตัวหลัก เพราะทีมใต้หน่วยเป็นของหน่วย

## เอเจนที่คุมคอมพิวเตอร์และเบราว์เซอร์: ไม่พิมพ์ผิดที่ ไม่คลิกมุมจอ

**เดิม** รายงานผู้ใช้ v1.9.5: เกมที่ capture อย่างเดียวไม่เคย read แล้ว `type` ที่ระบุหน้าต่างถูกตอบว่า
"ยังไม่ได้บอกว่าหน้าต่างไหน" สามครั้ง และไคลเอนต์ที่ส่งทุกช่องใน schema (`"x":0,"y":0`, `"text":""`) ทำให้เกิดคลิกที่มุมซ้ายบน
(โลโก้ของเว็บ หน้าไปหน้าแรกพร้อมข้อความ) หรือล้างช่องก่อนกด Enter
**รุ่นนี้**

- `type` ที่มี `keys` แต่ไม่มี `ref` ใช้หน้าต่างที่ระบุใน `window` ผ่านทางตรวจสิทธิ์เดียวกับ action อื่น
- หน้าต่างที่ capture อย่างเดียวถูกจำไว้ ลำดับ capture → click_at → type keys ไปถึงหน้าต่างนั้นแม้ไม่ระบุ window
- `ref` + `keys` ที่ `text` ว่าง โฟกัสช่องแล้วกดปุ่ม ไม่ล้างช่อง (ช่องรหัสผ่านและช่องที่ปิดยังถูกปฏิเสธ)
- บนเบราว์เซอร์ พิกัด (0,0) ถือว่าไม่ได้ส่งพิกัด จุดริมขอบอื่น เช่น (0,40) ยังเป็นพิกัด
- รายการโปรแกรมไม่สัญญาว่าจะถามผู้ใช้กลางเทิร์น (ไม่มีอะไรถามตั้งแต่ 9 ก.ย.) และการปฏิเสธเพราะยังไม่ได้อนุญาต
  ไม่กลายเป็นการ์ดให้แจ้งนักพัฒนาเรื่องค่าที่ผู้ใช้ตั้งเอง

ยังไม่ได้ลองกับเกมหรือโปรแกรมจริง

## บอท Telegram บอกว่ากำลังคิด และรับข้อความที่ต่อคิว

**เดิม** ข้อความที่ส่งเข้าบอทเงียบจนคำตอบมา และข้อความที่มาซ้อนระหว่างเทิร์นรอคิวโดยไม่มีอะไรบอก
**รุ่นนี้** typing ซ้ำทุก 4 วินาที หลัง 2 วินาทีโพสต์ "กำลังสร้างคำตอบ…" แล้วแก้ข้อความนั้นเป็นคำตอบจริง
เทิร์นสั้นไม่โพสต์สถานะ ข้อความที่ต่อคิวได้ใบรับก่อนเริ่มทำ

- ถ้า Telegram ยืนยันว่าแก้ไม่ได้ ส่งเป็นข้อความใหม่ แต่ถ้าผลไม่แน่ชัด (หมดเวลา สายหลุด) ไม่ส่งซ้ำ เพราะคำตอบอาจถึงแล้ว
- คำตอบเกิน 4000 ตัวอักษรแบ่งส่งต่อ คำขอฝั่งสถานะมีเวลา 2 วินาที ไม่ถ่วงคำตอบจริง error ไม่พก token
- แพลตฟอร์มอื่นยังได้ typing ครั้งเดียวเหมือนเดิม

## โปรแกรมที่เพิ่งติดตั้งหาเจอโดยไม่ต้องรีสตาร์ต และ error ของ PowerShell ไม่มีรหัสสี

- เชลล์ลูกของ Aetox (shell tool, background shell, เทอร์มินัลในแผงขวา) สืบ PATH ที่ Aetox ได้มาตอนเริ่ม
  ติดตั้งโปรแกรมระหว่างที่เปิดอยู่จึงหาไม่เจอแม้ในเทอร์มินัลใหม่ ตอนนี้ต่อ PATH ของเครื่องและของผู้ใช้จาก registry เข้ามา
  โดยไม่เปลี่ยนลำดับเดิม (รายการที่มีเฉพาะโปรเซส เช่น virtualenv ยังมาก่อน) อ่านไม่ได้ก็ใช้ค่าเดิม
- PowerShell 7 ส่ง escape สีใน error stream แม้ลงท่อ ผลที่จับไว้ตอนนี้เป็นข้อความล้วน เทอร์มินัลจริงยังมีสี

## ค่าใช้จ่าย: รอบที่ไม่รายงาน cache ไม่ถูกนับเป็น miss

**เดิม** ผู้ให้บริการที่ผ่านตัวกลาง (เช่น 9router แปล Gemini) เว้นช่อง cache เมื่อไม่มีค่าบวก ช่องที่หายคือ "ไม่ทราบ"
แต่แผงค่าใช้จ่ายนับอินพุตของรอบนั้นเป็น miss ทั้งก้อน
**รุ่นนี้** แผงโชว์ "ไม่ทราบ" แทนตัวเลขที่ไม่ได้วัด ถ้ารายงานบางรอบ โชว์ยอด hit เท่าที่ทราบ ส่วน miss รวมและเปอร์เซ็นต์ยังไม่ทราบ
เอนจินรุ่นเก่าที่ไม่ส่ง `cacheComplete` ไม่ทำให้แผงเปลี่ยนพฤติกรรม

## การ์ดเซิร์ฟเวอร์ในเครื่อง อยู่ใต้งานที่เอเจนเริ่มไว้

**เดิม** เอเจนสั่งเปิดเซิร์ฟเวอร์ในเบื้องหลัง แล้วในแชทเห็นแต่แถวคำสั่งกับแถวตรวจหน้าเว็บ ต้องอ่านพอร์ตเอง
และไม่มีทางหยุดโดยไม่ถามเอเจน
**รุ่นนี้** คำสั่งเบื้องหลังที่ประกาศที่อยู่ใน ready line มีการ์ดหนึ่งใบใต้ช่วงของเทิร์นที่แตะที่อยู่นั้น
การ์ดบอกว่ากำลังรันหรือหยุดแล้ว เปิดในแท็บข้างแชท เปิดในเบราว์เซอร์ของเครื่อง คัดลอกลิงก์ หยุด และรันอีกครั้ง
ด้วยคำสั่งและโฟลเดอร์เดิม

- ไม่มีอะไรใหม่รัน การ์ดอ่านจากคำสั่งเบื้องหลังที่มีอยู่แล้ว คำสั่งที่ไม่เคยประกาศที่อยู่ไม่มีการ์ด
  Python ที่บัฟเฟอร์ stdout อ่านแบนเนอร์ได้ระหว่างรัน
- `page_check` ที่ตรวจที่อยู่ของเซิร์ฟเวอร์เก็บภาพหน้าไว้ใต้แถวของมัน การ์ดแสดงภาพนั้นและจำนวนปัญหา
- การตรวจที่สะอาดการ์ดบอกเอง ("ตรวจแล้ว ไม่พบปัญหา") แถวนั้นจึงไม่ถูกวาดซ้ำ ส่วนการตรวจที่เจอปัญหายังมีแถวของมัน
  เพราะปัญหาคือสิ่งเดียวที่ห้ามถูกพับเป็นสรุป
- แถวของ `impact`, `trace`, `design_check`, `page_check` ในไทม์ไลน์มีชื่อไทยของตัวเอง
