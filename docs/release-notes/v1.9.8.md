# 🧩 Aetox v1.9.8

รุ่นนี้แก้เรื่องเดียวที่โผล่หลายหน้าตา: หน้าต่างถามเอนจินโดยไม่บอกว่าถามแทนแชตไหน เอนจินจึงตอบแทนแชตที่มัน
บังเอิญอยู่ ซึ่งไม่ใช่แชตที่อยู่บนจอเสมอไป ภาพที่แชตหนึ่งวาดจึงขึ้นเป็นไอคอนเสียในอีกแชต ลูกมือของแชตหนึ่งไปโผล่ใต้
คำตอบของอีกแชต และไฟล์ใหม่ลงผิดโฟลเดอร์ นอกจากนั้นเอเจนเลิกบอกว่า "ผู้ใช้เห็นอยู่" ทั้งที่ไม่เห็น
และหน้าแรกของ README เล่าว่า Aetox คืออะไรให้ตรงกับที่มันเป็น

## ภาพและไฟล์ของแชต: ตามแชตที่เป็นเจ้าของ

**เดิม** ภาพที่แชตผู้ช่วยเพิ่งวาด (อยู่บนดิสก์ 3.3 MB) ขึ้นเป็นไอคอนเสีย และแผงบอกว่าไฟล์หาย เพราะเอนจินอยู่ในแชตโค้ด
ที่โฟกัสอีกโปรเจกต์ แล้วหาไฟล์จากโฟลเดอร์ของแชตนั้น (3 ต.ค. 2026) เกิดเมื่อดูแผงอีกฝั่งของแบ่งจอ เมื่อเปิดอ่านแชตหนึ่ง
ระหว่างอีกแชตทำงาน หรือเมื่อแชตหนึ่งปลุกอีกแชต
**รุ่นนี้**

- แอดเดรสไฟล์ทุกอันบอกว่าเป็นของแชตไหน (`?s=<เซสชัน>`) และเอนจินหาโฟลเดอร์จากแชตนั้น แชตที่เอนจินไม่ได้ถืออยู่
  อ่านที่ตั้งจากแถวในฐานข้อมูล
- ไฟล์ที่ถูกลบจริงขึ้นว่า "ไฟล์ภาพนี้ถูกลบไปแล้ว" แทนปุ่มลองใหม่ที่ไม่มีทางสำเร็จ
- ภาพใน markdown ที่ชี้ด้วย `file://` เปิดผ่านโฮสต์ไฟล์ได้ เดิมขึ้นเป็นไอคอนเสียเหมือนกัน
- ส่งออกรูป (`PictureBytes`) หาไฟล์จากโฟลเดอร์ที่แชตสร้างไว้จริง

## ถาดงานเบื้องหลัง: ลูกมือไม่ข้ามแชต

**เดิม** ลูกมือของแชตโค้ดวาดอยู่ใต้คำตอบของแชตผู้ช่วย ("แม่งบั๊คแสดงข้ามเซสชั่น") เพราะรายการลูกมือที่อ่านมาเป็นของ
แชตที่เอนจินอยู่ ไม่ใช่แชตที่กำลังวาด
**รุ่นนี้** ทุกทางที่อ่านรายการลูกมือและปุ่มหยุดระบุแชต (id เป็นของแต่ละแชต task_1 มีในทุกแชตที่เคยมอบงาน)
ลูกมือที่ทำงานเกินรอบของแชตไหนเข้าถาดของแชตนั้น และเมื่อสลับแชต หน้าต่างขอรายการของแชตที่ไปถึง
เทิร์นของแชตที่หน้าต่างรู้จักอยู่แล้วที่มาถึงระหว่างอีกเทิร์นทำงาน ไม่ถูกยึดมาวาดใต้แชตบนจอ

## ไฟล์ใหม่ลงโฟลเดอร์ของแชตตัวเอง

**เดิม** แชตที่ทำงานเบื้องหลังถามหาโฟลเดอร์เอาต์พุตด้วยธงโปรเจกต์ของหน้าต่าง ซึ่งตอบให้แชตที่อยู่บนจอ
โฟลเดอร์ชื่อตามแชตผู้ช่วยจึงโผล่ในโปรเจกต์เกมที่แชตโค้ดกำลังสร้าง (3 ต.ค. 2026)
**รุ่นนี้** แชตจำเองว่าเอนจินของมันถูกสร้างในโปรเจกต์หรือไม่ และตอบจากนั้น

## `desk_open` บอกเฉพาะที่จริง

**เดิม** ตอบโมเดลว่า "ผู้ใช้เห็นอยู่ตอนนี้" ทุกครั้ง แม้แชตไม่ได้อยู่บนจอหรือผู้ใช้ปิดแผงขวาไว้ โมเดลที่เชื่อแบบนั้น
ไม่ใส่ภาพในคำตอบ ผู้ใช้ตอบว่า "ไหนภาพอ่ะ มองไม่เห็น"
**รุ่นนี้** หน้าต่างบอกเอนจินว่าแผงขวาแสดงอยู่ไหม และ `desk_open` พูดเฉพาะที่จริง: แชตนอกจอบอกว่าผู้ใช้จะเห็นเมื่อเปิดแชตนั้น
แผงที่ปิดอยู่บอกให้ใส่ไว้ในคำตอบถ้าเขาต้องเห็นตอนนี้

## "เจน UI" ในแชตเกมได้โค้ด ไม่ใช่รูปวาด

**เดิม** คำอธิบายเครื่องมือ `image_make` เขียนว่า "Draw a picture" ซึ่งครอบถึงหน้าจอของซอฟต์แวร์ที่กำลังสร้าง
คำขอ "เจน UI" ในแชตเกมถูกตอบด้วยรูปวาดสองครั้ง ผู้ใช้ตอบว่า "ไม่ใช่เจนรูป กุให้เจน โค้ด 3D"
**รุ่นนี้** คำอธิบายเครื่องมือเป็น "an illustration or a texture" และแนวทางของเครื่องมือบอกว่าหน้าจอของซอฟต์แวร์ที่กำลังสร้างคือโค้ด

## README: Aetox คือ agent harness

หัวข้อแรกบอกว่า Aetox คือ agent harness แบบเนทีฟบน Windows ที่ห่อโมเดลด้วยเครื่องมือ พื้นที่ทำงาน สิทธิ์ ความจำ
และวงจรตรวจสอบ โค้ดเป็น use case หลัก ผู้ช่วยกับทีมเป็นหน้าใช้งานของ harness เดียวกัน (เลิกเรียก "ประตู" ในหัวข้อแรก)
ทั้งฉบับอังกฤษและไทย

ที่จงใจไม่ทำ: ไม่เปลี่ยนค่าเริ่มต้นของผลิตภัณฑ์ และไม่เปลี่ยนวิธีที่เอนจินเลือกโฟลเดอร์ของแชตที่อยู่บนจอ
(ยังตอบด้วยธงของหน้าต่างเมื่อไม่มีเอนจินสร้างไว้ให้แชตนั้น)
