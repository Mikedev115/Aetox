# 🧭 Aetox v1.7.2

รุ่นนี้ทำให้ Aetox อธิบายตัวเองและพาใช้งานได้จริง เพิ่มเครื่องมือทำความเข้าใจโค้ดก่อนลงมือแก้
และปิดช่องโหว่ด้านความทนทานที่พบหลัง 1.7.1 โดยเฉพาะประสบการณ์ของผู้ติดตั้งผ่าน Microsoft Store

---

## ไกด์อยู่บนหน้าจอจริง

- เพิ่ม **ไกด์** เป็นยศที่สี่ของ Aetox เปิดได้จากปุ่ม “ปรึกษาไกด์”, หน้าเริ่มต้น หรือ `F1`
- ไกด์รู้ว่าผู้ใช้อยู่หน้าไหน เดินตามเส้นทางจริง ชี้ปุ่มจริง และเฝ้าตำแหน่งเป้าหมายเมื่อหน้าจอขยับ
  โดยไม่ยึดเมาส์หรือขวางการใช้งานปกติ; `Shift+คลิก` ใช้ถามถึงสิ่งที่ชี้อยู่ได้
- เลือกสมอง ภาษา และเสียงของไกด์ได้ แผงไกด์ลากไปวางตำแหน่งที่ต้องการได้ และคำอธิบายอ้างอิง
  เหตุผลจากแคตตาล็อกกลางแทนการเดาจากข้อความบนหน้าจอ
- แผนที่หน้า เส้นทาง และแคตตาล็อกมีเทสต์ตรวจความตรงกัน พร้อมเอกสาร
  [GUIDE-MAP.md](../GUIDE-MAP.md) และ
  [guide-architecture.md](../architecture/guide-architecture.md)

## เข้าใจโค้ดก่อนแก้

- เพิ่ม `impact` เพื่อดูว่าสัญลักษณ์หนึ่งส่งผลต่อไฟล์ ผู้เรียก และผู้บริโภคใดบ้างก่อนแก้ไข
- เพิ่ม `trace` สำหรับไล่หลักฐานข้ามขอบเขตระบบ พร้อม semantic code map ที่ใช้ข้อมูลจริงจาก repository
- repo map รองรับการเปิดโฟลเดอร์ย่อยภายใน Go module แล้ว และ harness รู้จักการไล่ trace แบบมีขอบเขต
- Workbench เลือก branch ได้ รายงานคอมมิตด้วยข้อมูลที่ตรวจสอบได้ เลื่อนแถบแท็บด้วยล้อเมาส์
  และพาแท็บที่เลือกกลับเข้ามาในมุมมอง

## แชท เอเจนต์ และการเชื่อมต่อ

- บีบอัด context ได้จากแชทและเปิดดูผลคำสั่งที่รันอยู่ได้โดยตรง
- จำ context ของแต่ละห้องไว้ในฐานข้อมูล ทำให้กลับมาแชทเก่าแล้วโมเดลได้ความจำของห้องเดิมจริง
- รูปที่แนบระหว่างเทิร์นไปถึงโมเดลแล้ว; การตอบคำถามของโมเดลและข้อความใหม่พากลับลงท้ายแชทถูกต้อง
- เพิ่มรหัสงานมอบหมาย การแสดงผลคำสั่งที่ทำงานนาน และ workflow ของเอเจนต์ที่เชื่อมต่อผ่าน Telegram/Discord
- เลือก persona preset ได้ แยกบริบทของโต๊ะให้อ่านง่าย และส่งความสามารถ Codex ที่ cache ไว้ให้ remote engine
- ปรับหน้าโปรเจกต์ การเชื่อมต่อ โปรไฟล์ และการตั้งค่าให้ใช้ทางนำทางชุดเดียวกัน

## Microsoft Store: ติดตั้งและอัปเดตตามช่องทางเดิม

แพ็กเกจ Store ยังคงเป็น `.msix` ที่ Microsoft เซ็นและ Windows สลับทั้ง `aetox.exe` กับ
`aetox-engine.exe` พร้อมกัน รุ่นนี้ตรวจเส้นทางดังกล่าวครบขึ้น:

- manifest ใช้ identity ของ listing `AetoxAI.Aetox` / Store ID `9N4KKBRRSCZZ`; release workflow
  stamp เวอร์ชัน `1.7.2.0`, สร้าง `resources.pri`, ตรวจโลโก้หลายสเกล และปฏิเสธแพ็กเกจที่เล็กหรือขาดไฟล์
- แอปจำแนกไฟล์ใต้ `Program Files\WindowsApps` เป็น Store ก่อน NSIS จึงไม่เสนอ installer จาก GitHub
  ซึ่งจะติดตั้ง Aetox ซ้ำอีกชุด
- หน้า **ตั้งค่า › เกี่ยวกับ** และแถบโปรไฟล์ไม่แสดง “ปิดการตรวจอัปเดตไว้” ให้ผู้ใช้ Store แล้ว
  แต่บอกตรง ๆ ว่า **Microsoft Store อัปเดตให้เอง** และมีปุ่มเปิดหน้าร้าน
- มีเทสต์ยืนยันว่า Store channel ไม่เรียก GitHub API, ไม่ stage ไฟล์อัปเดตเอง และเปิด listing ที่ถูกต้อง

> การอัปขึ้น Store ยังเป็นขั้น manual ใน Partner Center หลัง workflow สร้าง artifact ตาม
> [RELEASING.md](../RELEASING.md); การ push tag เพียงอย่างเดียวยังไม่ทำให้ Store เผยแพร่รุ่นใหม่

## ความทนทานและความปลอดภัยของตัวโปรแกรม

- ถ้า WebView2 ของหน้าต่างหลักตาย แอปสร้าง view ใหม่บนหน้าต่างเดิมแทนการปิดทั้งโปรแกรม
- แก้การลงทะเบียน `EnumWindows` callback ซ้ำทุกครึ่งวินาทีจน runtime ล้มด้วย
  `too many callback functions`
- การเชื่อมต่อโมเดลที่ถูกตัดด้วย `io.ErrClosedPipe` ลองใหม่เหมือนกรณีสายหลุด
- การปฏิเสธของเครื่องมือแก้ไฟล์เมื่อ `find` ไม่พบหรือซ้ำหลายจุดยังคงป้องกันการแก้ผิดตำแหน่งเหมือนเดิม
  แต่ถูกจัดเป็นความผิดของคำเรียก (`caller`) แล้ว จึงไม่ถูกนำไปสร้างการ์ด “ปัญหาระบบ” หลังเกิดซ้ำ
- ตั้งชื่อ `aetox-engine.exe` ด้วย version resource, manifest และ icon ก่อน build พร้อมแฮชของแต่ละ exe
  แยกบรรทัดใน `checksums.txt` เพื่อลด false positive และให้ตรวจไฟล์ที่ Defender กักได้
- เอกสารปล่อยรุ่นกำหนดชัดว่าหนึ่งรุ่นต้องเปลี่ยนสอง exe พร้อมกัน และต้องส่งไฟล์จริงให้ Microsoft Defender
  ตรวจทุกครั้งหลัง workflow สำเร็จ
