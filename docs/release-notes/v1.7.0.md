เจ้าของเจอเอง: *"ไม่รู้ว่าตัวหลักปรับแต่งได้"*

**รุ่นนี้** ระหว่างเลือกภาษากับต่อสมอง ทัวร์เก้าฉากวาดบนริกจริงของแอป: แอปคือหน้าต่างสี่ห้อง

privacy.html) · ยศสามชั้นและเหตุผล · ตั้งทีมแล้วหัวส่งงานออก · เบากว่า harness ข้างนอก · พร้อม

## ยศสามชั้น หน้าโปรไฟล์เดียวกัน และตัวตนต่อหัว (§266 §267 §270)

**เรื่องเดิม** หน้าจอเรียก "เอเจน" กับ "ซับเอเจน" ปนกัน หัวผู้ช่วยกับหัวโค้ดแชร์ตัวตนไฟล์เดียว
หน้าตั้งค่าของหัว ของพนักงาน และของลูกมือเป็นสามหน้าคนละโครง และการเรียนรู้เป็นหน้าของตัวเอง
ที่ไม่มีใครหาเจอ

**รุ่นนี้**
- **ยศ** ผู้ช่วย (หัวโต๊ะ) / พนักงาน (เอเจนเฉพาะทาง จ้างผ่านทีม) / ลูกมือ (ซับเอเจน มือของผู้ช่วยเอง)
  ตราอยู่ที่มุมหน้าทุกที่ที่มีหน้า — ประตูบนแถบบน ชิป "ใครตอบ" ข้างช่องพิมพ์ การ์ด สมาชิกทีม
  และคำยศถึงโมเดลด้วย ไม่ใช่แค่จอ (สคีมา `task` ข้อความปฏิเสธ บรรทัดทีมในพรอมต์)
- **หน้าโปรไฟล์เดียวกัน** ทั้งสามชั้น: หน้า 80 px มียศที่มุม ชื่อเป็นหัวเรื่อง หนึ่งบรรทัดว่าทำอะไร
  แล้วแท็บของแต่ละชั้น (เจ้าของ: *"ทั้ง 3 หน้านี้ต้อง UI มาตรฐานเดียวกัน"*) หน้าบนหัวหน้าหายใจ
  หันตามเมาส์ กดแล้วมีท่า
- **ตัวตนต่อหัว** ผู้ช่วยกับโค้ดมีโฟลเดอร์ของตัวเอง: `identity.md` (เป็นใคร) `thinking.md` (คิดยังไง)
  และไฟล์โต๊ะ (โต๊ะทำอะไร) สามคำถามอยู่บนหน้า แถวบอกว่าไฟล์ไหนตอบ `context.md` ว่างเป็นค่าเริ่มต้น
  ชื่อของหัวเปลี่ยนได้และเป็นคำแรกของพรอมต์ ไม่มีในไฟล์ไหน
- **หน้า เกี่ยวกับคุณ** ข้อมูลของคุณเป็นชั้นเดียวที่ทุกหัวและทุกพนักงานอ่านเหมือนกัน แยกจากตัวตน
  ของผู้ช่วย และแยกจากสิ่งที่มันสรุปเองจากงาน หน้าการเรียนรู้หายไป — ข้อเสนอความจำไปอยู่บนหน้าของ
  คนที่ตัดสิน และเลข "1" บนแถบข้างชี้ไปหน้านั้น ไม่ใช่ขึ้นที่ตัวหลักเสมอ (§273)
- **ความจำของโค้ดสองชั้น** ความจำของโต๊ะ แล้วความจำรายโปรเจกต์ใต้หัวข้อของมันเอง
- **`about: self`** เครื่องมือความจำได้คำที่สาม — สิ่งที่งานสอนผู้ช่วยเอง วิธีที่ได้ผลหรือไม่ได้ผล
  กับคนนี้ กติกาที่มันยึด (เจ้าของ: *"มันจดทุกอย่างลงเกี่ยวกับผม แต่ไม่ค่อยเห็นมันจำอะไรเกี่ยวกับ
  ตัวเองเลย"*) และชื่อที่รู้อยู่แล้วไม่ถูกเสนอเป็นความจำอีก
- **พนักงานใหม่เปิดบนแผ่นเทมเพลต** โครงเปล่า 4 แบบ + บทบาท 42 จาก agency-agents (MIT) แบ่ง 7 กลุ่ม
  กดแล้วลงชื่อ คำอธิบาย บทบาทให้ ติ๊กข้ามได้ (§284)

**ที่ยังไม่ได้ทำ** ร่างเทมเพลต identity/thinking ชุดใหม่ ("Name: Aetox …") ยังอยู่ในทรี ไม่อยู่ในรุ่น
เพราะสามภาษาต้องเท่ากันและยังตัดสินไม่ได้ว่าเอาร่างไหน

## คอนโซลเป็นจอที่สาม (§268)

**เรื่องเดิม** `aetox chat` มีลูปของตัวเอง ต่างจากแอปทั้งพรอมต์ เครื่องมือ และความจำ พฤติกรรมที่วัด
ในคอนโซลจึงไม่ใช่พฤติกรรมของแอป

**รุ่นนี้** คอนโซลนั่งโต๊ะโค้ดบนเครื่องยนต์ตัวเดียวกับหน้าต่าง ลูปของตัวเองหายไป `--report` ให้ JSON
หนึ่งบรรทัดต่อเทิร์น (โทเค็น รอบ เครื่องมือ) สั่งครั้งเดียวไม่รับคำตอบปลอม Ctrl-C ตัด console read
ไม่ใช่ปิด stdin และ stdin ที่ปิดกลางเทิร์นทำให้ทุกคำถามถูกปฏิเสธแทนที่จะแขวน — นี่คือถนนที่ใช้วัด
สกิลกับโมเดลจริงในรุ่นนี้ (`--approval unsafe-only </dev/null`)

## ปุ่มปรับได้ระหว่างเทิร์นกำลังวิ่ง (§275 §289)

**เรื่องเดิม** กดเปลี่ยนระดับคิดใต้เทิร์นที่กำลังรันได้ "รอบถัดไปจะใช้ <โมเดลเดิม>" ทั้งที่ไม่ได้
เปลี่ยนโมเดล และเปลี่ยนโหมดอนุมัติกลางแชทถึงแค่ตัวหลัก — โมเดลที่ถูกปฏิเสธ shell ส่งลูกมือไปรัน
คำสั่งเดิมแทนได้โดยไม่มีใครถาม (ASI03 ของเช็กลิสต์ที่เขียนไว้สองชั่วโมงก่อนหน้า พบโดยการรัน
ครั้งแรกของเช็กลิสต์เอง)

**รุ่นนี้** ระดับคิดเป็นฟิลด์บนรีเควสต์ที่ลูปเครื่องมือสร้างใหม่ทุกรอบอยู่แล้ว executor อ่านมันสด
ทุกรอบ กดแล้วรอบถัดไปอ่านค่าใหม่ทันที ไม่มีคิว โหมดอนุมัติเช่นกัน — ลูกมือทุกตัวอ่านโหมด "ตอนนี้"
ทุก dispatch และการกดหลังคิวโมเดลไม่ถูกคิวทับตอนถึงขอบเทิร์น ที่ยังต้องรอขอบเทิร์น: เปลี่ยนโมเดล
ผู้ให้บริการ และท่าที (ลงมือ/วางแผน/มุ่งเป้า) เพราะสามอย่างนั้นเปลี่ยนพรอมต์กับรายการเครื่องมือ

## วางแผน ได้ยินเสียงเดียว และ มุ่งเป้า รับไม้เป็นสกิล (§288 §290)

**เรื่องเดิม** เทิร์นวางแผนได้พรอมต์ครึ่งลงมือของโต๊ะ ชั้นสกิลทั้งชั้น กติกาถามก่อนทั่วไป ชั้นวาดรูป
และเช็กลิสต์ที่สอง — 28,295 ตัวอักษรต่อรีเควสต์ ที่พูดกันคนละทาง และการกดปุ่มรันแผนสร้าง
เครื่องยนต์ใหม่ทั้งตัว

**รุ่นนี้** พรอมต์วางแผนเหลือเสียงเดียว 14,632 ตัวอักษร กดปุ่ม = ส่งไม้: กฎของรันเป็นสกิล
`aetox-run-plan` เล่มเดียว เครื่องยนต์แนบให้โมเดลกับข้อความแรกของรัน ไม่สร้างเครื่องยนต์ใหม่
รันเหลือเกตสองตัว และ Stop ของแชทปลดรันด้วย — ข้อความถัดไปไม่โดนเกตบังคับติ๊ก step อีก
**ไม่มีเพดาน** จำนวนรอบ ตามคำของเจ้าของ

## ห้องความสามารถ และชั้นสกิลที่อ่านตัวเองได้ (§265 §280)

**เรื่องเดิม** MCP สกิล เครื่องมือในตัว การใช้คอมพิวเตอร์ และการเชื่อมต่อ กระจายอยู่หลายหน้า
สกิลที่แอปร่างเองไม่มีใครตรวจก่อนเสนอ

**รุ่นนี้** ห้องเดียว รางหกหัวข้อ: MCP · สกิล · เครื่องมือในตัว · การใช้คอมพิวเตอร์ · การเชื่อมต่อ ·
ชุดคำสั่ง (หน้า Hooks ถูกถอดออกโดยเจ้าของ) `internal/skilllint` กับ `aetox skill lint` อ่านสกิล
ด้วยโปรแกรมก่อนคนตัดสิน สามระดับ สกิลที่มากับแอปทั้ง 44 ผ่านระดับ error ทุก `go test` และสกิลที่
แอปร่างเองทุกใบผ่านด่านเดียวกัน ผลขึ้นบนการ์ด ดัชนีสกิลอยู่ในพรอมต์ ตัวร่างนิสัยเห็นชั้นวางก่อนเสนอ

**สกิลใหม่บนชั้น**
- `aetox-security` (§286) — เส้นทางโจมตีที่บรรทัด ไม่งั้นคือคำแนะนำ พอร์ตวิธีจาก
  claude-code-security-review (MIT) กับ differential-review (วิธี ไม่ใช่ข้อความ) และรายการ OWASP
- `aetox-performance` (§287) — ตัวเลขที่บรรทัด และการแก้คือตัวเลขเดิมที่ผ่าน noise ของมัน
- `aetox-orient` (§276) — วินัยเข้าโค้ดเบสจากชั้นถูกไปแพง หลังแก้ให้ repomap ให้เครดิตระดับ symbol
  สำหรับ Go และไม่ให้เครดิตไฟล์เทสต์ (แผนที่ถูกสร้างไว้แล้วจัดอันดับผิดไฟล์ และไม่มีใครเรียก)
- แก่นแปดตัวของ obra/superpowers (§274) เป็นสกิลของเรา — brainstorm, run-plan, และเพื่อน
- `aetox-motion` (พอร์ต gsap-skills) กับ `aetox-web-3d` (เขียนเอง r186) สำหรับหน้าที่ความสวยคือ
  canvas หรือไทม์ไลน์ตามสกรอลล์ (§278)
- `aetox-idea-to-architecture` และ `aetox-code-review` เขียนใหม่บนวินัยของ `aetox-architect`
- `codebase design` (§276.3) — ตัวจับ tell ของ UI ที่เขียนตามนิสัย 12 กฎ พอร์ต detector จาก
  pbakaus/impeccable (Apache-2.0) วัดบน frontend ของแอปเอง: 72 ไฟล์ 14 ข้อ 60 ms อ่านทุกข้อด้วยมือ
  และ `aetox design [--hook]` จากเทอร์มินัล

## มิเตอร์ที่บอกความจริงตั้งแต่ข้อความแรก (§285)

**เรื่องเดิม** "ข้อความแรกจะใช้ประมาณ" มาจากตัวอักษร ÷ 4 แล้วรอบแรกมาหักหน้า และความคิดที่ส่งกลับ
เข้าไปกับสกรีนช็อตที่โมเดลดูไปแล้วไม่ถูกนับ

**รุ่นนี้** จดค่าเดาคู่กับค่าที่ผู้ให้บริการนับทุกรอบแล้วฟิต แชทแรกบนโมเดลที่ยังไม่มีรอบส่งคำขอ "พื้น"
ไปวัดเองหนึ่งครั้ง (system prompt + บล็อกเครื่องมือ + ping ขอ 1 โทเค็น) เอาค่าที่นับจริงเป็นแถวแรก
ความคิดที่ส่งกลับนับเข้างบด้วย สกรีนช็อตเก็บรูปล่าสุดรูปเดียว

## แชทสรุปแล้วไปเริ่มใหม่ และการรอที่ไม่ใช่การแขวน (§282 §269 §277)

- **สรุปแล้วไปเริ่มแชทใหม่** compaction ที่ผู้ใช้เห็นและเลือกเอง: ปุ่มใต้คำตอบล่าสุด → โมเดลสรุป
  เป็นประเด็น → การ์ดติ๊กเลือก → แชทใหม่ที่สถานีเดิมพร้อมประเด็นที่เลือก
- **หมดหน้าต่าง 5 ชั่วโมงของ Codex / opencode-go** เทิร์นรอรีเซ็ตบนหน้าจอ นับถอยหลัง แล้วทำต่อจาก
  รอบเดิม ไม่จบแดง
- **overloaded ที่ผู้ให้บริการเขียนลงในสตรีม** ถูกถามซ้ำบน backoff ไม่ใช่จบเทิร์น (รายงานจากลูกค้า
  14 ก.ย.) และสำเนาสกิลที่ติ๊กให้พนักงานเป็นฉบับที่รันจริง
- **ask_user ทั้งคืน** รอ 30 นาทีแล้วขอปิดเทิร์นเอง และการตายทุกแบบทิ้งร่องรอย: crash file, log ของ
  Wails, รอยเท้าปิดปกติ
- **กดหยุดผู้ช่วยกลางทาง** เก็บงานที่ทำไปแล้ว ไม่ใช่ `task_result` ล้มเหลว

## หน้าจอที่ขยับให้ถูก

- **ช่วงงานเครื่องมือพับเมื่อ "จบ"** ไม่ใช่เมื่อ "เงียบ" — ลูปเครื่องมือยี่สิบรอบเคยพับ/เปิดยี่สิบครั้ง
  ตอนนี้ค้างเปิดทีละรอบเป็นกล่องต่อรอบ พับครั้งเดียวเมื่อโมเดลพูด ผู้ใช้แทรก หรือเทิร์นจบ และแถบ
  ไฮไลต์ไม่ทำให้กล่องงอกพื้นโล่งใต้การ์ดขนานอีก (§291)
- **`codebase symbol` มองข้าม doc comment** — หา `CancelTurn` เคยได้ "knows nothing" เพราะไปเจอชื่อใน
  คอมเมนต์เหนือฟังก์ชันก่อน ตอนนี้เจอที่ประกาศจริง และ error ของ gopls ถึงโมเดล
- **แท็บเบราว์เซอร์ตามแผงครั้งเดียวต่อเฟรม** ไม่ repaint เพราะ region ที่ไม่มี ค้างนิ่งระหว่างลากจน
  ปล่อยค่อยตาม เกิดมาซ่อนและมืด (§283)
- **รายการโปรเจกต์ในแถบข้าง** อ่านง่ายเมื่อเยอะ สร้างโปรเจกต์จากหัวข้อได้เลย
- **companion** อวตารมีเลเยอร์ของตัวเองและไม่แบกฟิลเตอร์ของทั้งหน้า

## เครื่องระยะไกล เฟส 4 (§248)

ประตูของหน้าต่างเมื่อเครื่องยนต์อยู่บน host: ไฟล์ที่เลือกที่นี่ขึ้นสายไปก่อน โฟลเดอร์เลือกที่นั่นผ่าน
picker ของ host `reveal` บอกว่าอยู่เครื่องไหน เครื่องยนต์ที่ต่อเองผ่าน `AETOX_ENGINE_ADDR` ไม่ถูก
supervisor ฆ่า และดู OS ก่อนชื่อเครื่อง (WSL ตอบ hostname เดียวกับ Windows)
