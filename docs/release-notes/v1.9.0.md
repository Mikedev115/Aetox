## ประตูทีม: คุยกับเลขา แล้วงานไปถึงทีม แผนก และบริษัท

**เดิม** ประตูทีมเป็นห้องที่ยังไม่มีใครให้คุย ทีมเป็นแค่รายชื่อ และงานของสมาชิกขึ้นในแชทเป็นแถวเครื่องมือ
ต่อกันยาว
**รุ่นนี้** เลขาเป็นโต๊ะที่สาม อยู่ชั้นเดียวกับผู้ช่วยและโต๊ะโค้ด หน้าที่คือรับคำสั่ง ถามถ้าจำเป็นหนึ่งข้อ
ตัดสินว่างานควรไปถึงชั้นไหน แล้วส่งต่อ รายงานผล และไม่ทำงานซ้ำเอง

- **องค์กรมีสี่ชั้น** คือ เอเจน · ทีม · แผนก · บริษัท แต่ละชั้นมีหัวหน้าหนึ่งคนที่คิดเอง รู้ว่าลูกทีมทำอะไรได้
  และสั่งงานเป็นภาษาคน แผนกระบุเองว่ามีทีมไหน ทีมหนึ่งอยู่ได้หลายแผนก บริษัทระบุแผนกเอง
  และหัวหน้าบริษัทจ้างทีมตรงได้ กลไกของหัวหน้าอยู่ที่ระบบที่เดียว ไฟล์หัวหน้าเหลือแค่ตัวตน
- **หัวหน้าเห็นคำที่คนพิมพ์ตรงตัว** เลขาไม่เขียนบรีฟใหม่ทับ หัวหน้าไม่ถือช่องรันไว้เอง
  (แผนกแจกงานให้ 3 ทีม บริษัทแจกให้ 3 แผนกพร้อมกัน) และเอเจนที่ถูกจ้างไม่ได้รายงานถึงชื่อเจ้าของ
- **การ์ดบนแถบซ้ายเลือกได้ว่ายืนอยู่ชั้นไหน** ทีม แผนก หรือบริษัท เลขาได้รับชั้นนั้นทุกข้อความ
  เปลี่ยนชั้นแล้วเริ่มแชทใหม่ และประวัติแชทยังเป็นรายการเดียว แต่ละแถวติดป้ายว่าเริ่มที่ไหน
  ("แปะป้ายก็พอ") แชทเก่าได้ป้ายจากข้อความแรกของตัวเอง (migration 39)
- **งานที่มอบเป็นผังเดียว** ลูกมือ เอเจน และทีม เป็นแถวแบบเดียวกันทุกชั้น หน้า · ชื่อ · งาน ·
  บรรทัดเดียวที่บอกว่ากำลังทำอะไร ทีมมีหัวหน้าอยู่บนสุดและสมาชิกห้อยลงมาใต้ คำถามอยู่ใต้คนถามและตอบได้ตรงนั้น
  แต่ละแถวที่ทำงานอยู่มีปุ่มหยุด กดที่แถวแล้วงานเต็มเปิดในแผงขวา
- **ชิ้นงานของทีมเป็นไฟล์จริง** อยู่ในโฟลเดอร์ของทีม ถ้าโฟกัสโปรเจกต์อยู่ ไฟล์ที่เอเจนเขียนจะขึ้นการ์ด
- **ห้องทำงาน** เขียนสายงานที่บันทึกไว้ได้ แต่ละขั้นบอกว่าทีมไหนรับชิ้นไหน กดเริ่มแล้วสายเดินทีละขั้น
  ขั้นไหนหยุดถาม คำตอบจะไปถึงขั้นนั้นแล้วเดินต่อ ชื่อทีมในแต่ละขั้นถูกตรวจตอนบันทึก ไม่ใช่ไปพังตอนรัน
- **แผนกสตูดิโอ** สำหรับช่อง YouTube ที่ไม่มีคนออกกล้อง มีเสียงพากย์ (voice_make) ตัวเฝ้าข่าวเทค
  ที่ส่งงานให้แผนกเองพร้อมแจ้งเตือน และ video record ที่อัดหน้าเว็บเลื่อนลงเป็นคลิป
- ตัวติดตั้งใส่มาให้แค่ **ทีมคอนเทนต์** ทีม แผนก และบริษัทอื่นสร้างเองจากหน้าตั้งค่า › องค์กร
  หรือจากแผ่นเทมเพลต ซึ่งตอนนี้เติมให้ครบสามช่อง คือ ตัวตน · วิธีคิด · หน้าที่ พร้อม MCP ที่แนะนำต่อบทบาท

## ออฟฟิศ: ห้องที่มีชีวิต เวลา และมือถือแชทเลขา

- ห้องบริษัทเป็นโมเดล 3D เลือกแมพได้สองแบบ คือวิทยาเขตกับตึก ถ้าเครื่องไม่มี WebGL จะถอยไปใช้ห้อง 2.5D
- หุ่นมีชีวิต ท่าทางเปลี่ยนตามเครื่องมือที่ใช้ หันเข้าจอ มีอารมณ์ ล้อมวงกาแฟ เดินต่อแถวไม่เดินซ้อนกัน
  หัวหน้ามีโต๊ะของตัวเอง และยศขึ้นบนหัว
- เวลาในห้องตามนาฬิกาของคุณ มีเช้า เย็น กลางคืน และรุ่งสาง ผนังมีหน้าต่าง นาฬิกา และธงของทีม
  งานที่เสร็จจะถูกยกเป็นกล่องไปศูนย์ส่งงาน กลางคืนมีหุ่นดูดฝุ่น และป้ายไฟวิ่งอ่านจาก log ของห้อง
  บอร์ดสถิติบอกงานเสร็จวันนี้ · ทำงานอยู่ · รอคุณ
- **หน้าเว็บ :8317 เป็นคอนโซลขององค์กร** ตั้งค่าทีม แผนก และบริษัทได้ และมี **มือถือแชทเลขา**
  ซึ่งไม่ใช่แชทที่สอง แต่แสดงแชทที่หน้าต่างเปิดอยู่และพิมพ์ผ่าน composer ของหน้าต่าง ห้องกับชั้นของแชทอยู่ที่เดียวกันเสมอ
- ห้อง 2.5D ไม่กระตุกแล้ว ภาพหุ่นถูกอบตอนเครื่องว่างและเก็บลงดิสก์ อบครั้งเดียว

## ติดตั้ง MCP กับสกิล: บอก AI แล้วกดการ์ด

**เดิม** เจ้าของบอกว่า "MCP ใหม่ สกิลใหม่มาตลอด ผมตามอัปเดตไม่ไหว"
**รุ่นนี้** วางอะไรก็ได้ในแชทหรือในห้องความสามารถ เช่นลิงก์ JSON แบบ mcpServers คำสั่ง `claude mcp add`
npx/uvx TOML ของ Codex ปุ่ม Cursor/VS Code หน้า GitHub/npm/PyPI/skills.sh หรือแค่ชื่อ ระบบเลือกตัวทางการ
จากทะเบียนที่ยืนยันโดเมน ตรวจก่อนว่าต้องใช้ OAuth หรือคีย์ แล้วขึ้นการ์ดให้คุณกด **ทุกการติดตั้งต้องมีคนกด
ทุกระดับการอนุมัติ**

- ผู้ช่วยติดตั้งเป็นตัวตนของ Aetox เอง อยู่ในแผงข้างหน้า MCP และสกิลเสมอ ลากขยายได้ จัดที่ของที่ลงไว้แล้วได้
- การ์ดสกิลบอกว่าแต่ละตัวทำอะไร (อ่านจาก SKILL.md ของมันเอง) และถามว่าใครได้ใช้ รายการ "ใครได้ใช้"
  เป็นรายชื่อเอเจนรายตัวที่ค้นหาได้
- ห้องสมุดเพิ่ม blender · pixellab · testsprite · hostinger · n8n และสกิล Next.js ของ Vercel
  จงใจไม่ใส่ Google Stitch เพราะเซิร์ฟเวอร์ต้องใช้ Google OAuth client ที่ไม่มีทางลงทะเบียน

## Aetox ในเทอร์มินัล (ก้อนแยก)

`aetox` ในเทอร์มินัลเป็นจอเต็มสำหรับโต๊ะโค้ด พิมพ์ต่อท้ายและมีแถบล่าง ใช้เอนจินเป็นโปรเซสลูกผ่านซ็อกเก็ต
แบบเดียวกับหน้าต่าง **แยกเป็นก้อนของตัวเอง** คือ `aetox-cli-windows-amd64.zip` และ `scoop/aetox-cli.json`
ตัวติดตั้งและแพ็กเกจ Store จึงยังเหมือนเดิม ถ้าเครื่องมีแอปอยู่ คอนโซลจะใช้เอนจินของแอป

## แชท

- **แบ่งจอ** เปิดสองแชทข้างกันในหน้าต่างเดียวผ่านเมนู "เปิดใน ›" บนแถวแชท หรือกด Ctrl+\ สลับฝั่งแล้วไม่ต้องโหลดใหม่
  เพราะเอนจินถือทั้งสองแชทไว้
- **แผนเป็นกล่องเดียวกันทุกที่** การ์ดในแชท แถบบน composer หน้าแผน และรายการในชิ้นงาน อ่านสถานะจากที่เดียว
  การ์ดมีปุ่มเริ่มกับทำต่อ ส่วน "ขอแก้แผน" พิมพ์ใน composer เดิม
- **หน้าแรกของแชทว่าง** ใช้ภาษาเดียวกับหน้าเปิดตัว กล่องพิมพ์อยู่กลางจอ การ์ดเริ่มงานเรียงเป็นแถว
  และมีปุ่มเล็กมุมซ้ายล่างสลับไปอีกแบบได้
- **ปุ่มหยุด** หยุดแค่งานของเทิร์นนี้ มีปุ่มหยุดทีละคำสั่งและปุ่ม "ไม่รอ" ส่วนลองใหม่หลัง error จะทำต่อจากจุดที่ค้าง
- ประโยคบนการ์ดเริ่มงานเคยพูดแทนคุณว่า "ผม" ตอนนี้ใช้ "ฉัน" แล้ว
- แท็บในแผงขวาที่คลิกจะอยู่ที่เดิม ไม่เด้งไปหัวแถว แท็บที่เปิดใหม่ยังไปหัวแถวเหมือนเดิม

## ความปลอดภัยและความเสถียร

- **ค่าลับไม่ไปถึงโมเดลอีก** ผลเครื่องมือทุกชิ้นผ่าน Scrub ชุดเดียวกับ debug log, shell audit และ tool_runs
  ก่อนหน้านี้มีสกิลที่สั่ง `printenv VERCEL_TOKEN` ทำให้ค่าจริงไปถึงผู้ให้บริการได้
- **ด่านอนุมัติรู้จักเครื่องมือจากตารางเดียว** เครื่องมือที่ไม่มีใครประกาศว่าทำอะไรต้องถามก่อน ใน tool_runs ของเจ้าของ
  ช่วง 3–24 ก.ย. มี 4,940 จาก 13,542 ครั้งที่ตกทางไม่ถามเดิม MCP ตัดสินจาก annotation ที่เซิร์ฟเวอร์ประกาศ
  เบราว์เซอร์ถามก่อนโพสต์ แชร์ ส่ง หรือตอบกลับ และการปิดโปรเซสตามชื่อถามก่อนในทุกโหมด
- **แอปดับเงียบกลางงาน** สาเหตุคือ handler ของ WebView2 ถูก GC เก็บไปทั้งที่ WebView2 ยังถืออยู่ แก้แล้ว
  และ crash แบบ native ทิ้งร่องรอยไว้แล้ว (WER กับไฟล์ crash)
- แท็บเบราว์เซอร์ของเอเจนมีงบหน่วยความจำ แท็บที่ไม่ได้ใช้ 10 นาทีถูกปิด เปิดพร้อมกันได้ไม่เกิน 4 แท็บ
  สื่อไม่เล่นเอง และแท็บที่กำลังมีเสียงจะไม่ถูกปิด
- เปิดแอปซ้ำแล้วดึงหน้าต่างเดิมขึ้นมา หนึ่งแอปต่อหนึ่งตัวที่ติดตั้ง ส่วน dev · Program Files · Store ยังเปิดพร้อมกันได้
- คำสั่ง shell ที่กลายเป็นเซิร์ฟเวอร์ (เช่น `"build": "vite"`) ถูกหยุดพร้อมบอกว่าสคริปต์ผิด และ STILL RUNNING
  แนบบรรทัดท้ายของคำสั่งมาด้วย
- ถ้าเจอ TLS handshake timeout หรือ HTTP/2 stream reset ระบบจะถามผู้ให้บริการใหม่ ไม่จบเทิร์น

- การ์ดดึงข้อมูลเป็นตารางของโต๊ะผู้ช่วยลดจาก 15.7 นาทีเหลือ 3:54 นาที เพราะข้อมูลส่งต่อเป็นไฟล์
  (`sheet_write` รับ `rows_file`) และรายชื่อทีมไม่ถูกอ่านซ้ำในทุกรอบ
- คุมเครื่อง: ตาราง ref เป็นของแชท (เดิม read แล้ว click พลาดทุกครั้ง) และ click/type ตอบพร้อมผลอ่านหน้าต่างใหม่
  ประหยัดไปหนึ่งรอบต่อการกด
- ความจำ: ตัวตรวจโปรไฟล์พักบรรทัดที่เจอครั้งเดียวไว้ก่อนจนกว่าแชทอื่นจะพูดซ้ำ และทุกบรรทัดต้องบอกว่าจะเปลี่ยน
  การทำงานอย่างไร เครื่องมือ learn_* ก็ต้องบอกเหมือนกัน
- ไกด์พาไปได้ทุกปุ่ม รวมประตูทีม บริษัท ห้องทำงาน โปรเจกต์ วิดีโอ และหน้าตั้งค่าทั้งหมด
- ห้องความสามารถโหลดเฉพาะส่วนที่วาด แท็บเอเจนลดจาก 60 คำขอเหลือ 12 หน้าสรุปองค์กรมี index ของ tool_runs
  และนับเฉพาะงานของทีม ไม่รวมโต๊ะผู้ช่วยกับโต๊ะโค้ด
- หน้าเปิดตัวเป็นปากกาเขียนตัว A แล้วแนะนำทีละประตู ผู้ช่วย · โค้ด · ทีม และปากกาเริ่มเขียนเมื่อแอปบูตเสร็จ
- โต๊ะโค้ด: `codebase action page` โหลดหน้าเว็บแบบ headless แล้วรายงาน error, codebase errors จับ error ของ JS/TS
  บน Windows ได้จริง และตัวติดตั้งตรึง typescript@5
- ข้อความตอนต่อผู้ให้บริการไม่ติดบอกเป็นประโยค
