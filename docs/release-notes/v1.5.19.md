# 🧩 Aetox v1.5.19

รุ่นนี้เป็นรุ่นของ **เพดานที่เราสร้างเอง แล้วเพิ่งรู้ตัวว่าสร้าง** — คลังฉากวิดีโอที่เปิดได้
แค่ชั้นเดียวจากสี่ชั้น, การเรนเดอร์ที่ติดอยู่ที่ 1080p ทั้งที่เอนจินทำ 4K ได้มาตลอด,

## พิมพ์แทรกตรงไหน ข้อความอยู่ตรงนั้น

**เรื่องเดิม** ข้อความที่พิมพ์ใส่เทิร์นที่กำลังตอบ เป็นบับเบิลของตัวเองในบทสนทนา แล้วถูกดัน
ลงใต้บล็อกสดด้วย CSS ซึ่งถูกสำหรับการแทรกครั้งเดียวและผิดตั้งแต่ครั้งที่สอง — ทุกอย่าง
ที่โมเดลพูดระหว่างเทิร์นอยู่ในบล็อกก้อนเดียวกันหมด คำตอบของคำถามแรกจึงถูกวาดเหนือคำถาม
และข้อความที่สองที่สามกองรวมกันอยู่ก้นสุด (เจ้าของ 7 ก.ย.: *"มันกองแบบนี้หมด ทั้งที่
ความเป็นจริง พิมพ์ไว้ตรงไหนควรจะอยู่ตรงนั้น"*)

และมันไม่ถูกเก็บไว้เลย `Interject` ไม่เขียนแถวไหนลงบันทึก คำถามที่พิมพ์ใต้เทิร์นที่วิ่งอยู่
จึงอยู่ได้เท่าที่หน้าต่างยังเปิด เปิดเซสชันเก่ากลับมาแล้วเจอคำตอบของคำถามที่แสดงไม่ได้

**รุ่นนี้** ข้อความแทรกเป็นชิ้นหนึ่งของเทิร์นนั้น เก็บไว้ในลำดับตรงจุดที่ลูปพับมันเข้า
คอนเท็กซ์ วาดเป็นบับเบิลของผู้ใช้เองพร้อมนาฬิกา และคำตอบต่อมันอยู่ใต้มัน

- **หน้าตาเหมือนคำถามของคุณทุกที่ในแอป** พื้นยกขึ้น ขอบเดียวกัน มุมขวาบนตัดเหมือนกัน
  เวลาอยู่ข้างใต้เหมือนกัน — พูดที่ไหนไม่ควรเปลี่ยนว่ามันหน้าตาเป็นยังไง
- **รูป คลิป และแท็บที่ลากเข้ามา ยังขี่มากับมันได้** เหมือนข้อความอื่นทุกข้อความ
- **แถวขึ้นทันทีที่พิมพ์** ไม่รอเอนจินยืนยัน เพราะเอนจินพับมันเข้าในรอบถัดไปซึ่งอาจห่าง
  ยี่สิบวินาที และข้อความที่หายไปยี่สิบวินาที สำหรับคนพิมพ์คือข้อความที่หายไปแล้ว
  อีเวนต์ที่ตามมาจับคู่กับแถวเดิม ไม่ใช่เพิ่มแถวที่สอง
- **เปิดเซสชันเก่ากลับมายังอยู่ครบ** พร้อมเวลาที่พิมพ์ ซึ่งขี่มากับ part เอง เพราะ part
  คือบันทึกเดียวที่ข้อความนี้มี

**สองรอยที่โผล่มาพร้อมกัน** ข้อความที่เอนจินพับเข้าไม่ทันแล้วส่งคืนมา ถูกถอนแถวออกจาก
เทิร์นที่ไม่ได้รับมันก่อนจะออกไปเป็นเทิร์นของตัวเอง ไม่งั้นประโยคเดียวขึ้นจอสองครั้ง ครั้งหนึ่ง
อยู่ในบทสนทนาผิดตัว · และการล้างแถวเครื่องมือถูกย้ายขึ้นไปอยู่ลมหายใจเดียวกับการตั้งธง
จากเดิมที่อยู่ใต้การหาเซสชันซึ่ง await ในเทิร์นแรกของการเปิดเย็น — ช่วง await นั้น
อะไรที่พิมพ์เข้ามาจะลงในลิสต์ที่กำลังจะถูกทิ้ง แล้วหายจากจอทั้งที่เอนจินตอบมันอยู่

**ที่จงใจไม่ทำ** สิ่งที่แนบมากับข้อความแทรกยังไม่ถูกเก็บลงบันทึก มีแต่ตัวข้อความ —
ซึ่งก็ไม่ได้เสียอะไรที่เคยมี เพราะก่อนหน้านี้ไม่มีอะไรถูกเก็บเลยสักอย่าง

## คลังฉากวิดีโอเปิดครบทั้งสี่ชั้น และมีฉากเปล่าให้เริ่ม

**เรื่องเดิม** สารบัญของคลังสอนชื่อฉากไว้เจ็ดสิบห้าชื่อ และเครื่องมือเปิดได้ห้าสิบ
มีแค่ชั้น `motion` ที่ถูกตัดคำนำหน้า อะไรที่มี `/` เหลืออยู่ถูกปฏิเสธทั้งหมด เอเจนที่ทำตาม
ตารางตรงตัว — `video new graphic-scenes/social-cover-editorial.html` — จึงถูกบอกว่า
ฉากที่มันเพิ่งอ่านเจอไม่ใช่ฉาก ยี่สิบห้าจากเจ็ดสิบห้า ซึ่งคือปก อินโฟกราฟิก สไลด์ข้อมูล
และหน้าจอจำลองทั้งหมด

เหตุผลที่กันไว้เป็นเรื่องจริง — ฉากนิ่งที่เรนเดอร์เดี่ยว ๆ คือวิดีโอของรูปถ่าย — แต่มันไม่
ครอบคลุมงานที่สารบัญอธิบายฉากพวกนั้นไว้เอง: "หน้าจอที่ดูจริงโดยไม่ต้องเอาภาพจริง
มาเปิดเผยข้อมูลจริง" ซึ่งต้องเอาไฟล์เข้าโปรเจกต์ให้ได้ก่อน `product-launch-30s`
ใส่ PNG โปร่งใส 1x1 ไว้สามรูปตรงที่ควรเป็นภาพผลิตภัณฑ์ วัสดุที่จะแทนมันอยู่บนชั้นมาตลอด

**รุ่นนี้** ทั้งสี่ชั้นเปิดได้ ด้วยทุกวิธีสะกดที่สารบัญสอน และไม่มีชื่อไหนซ้ำกันสองชั้น
ชื่อเปล่าจึงไม่เคยกำกวม เหตุผลที่เคยเป็นประตูล็อกกลายเป็นประโยคเดียวในรายงานแทน

- **`video new blank`** คือคอมโพสิชันเปล่าของตัวเรนเดอร์เอง สำหรับงานที่ไม่มีฉากไหน
  เป็นรูปทรงนั้น ไม่ใช่ไฟล์ที่เราเขียน เพราะคอมโพสิชันเปล่าคือคำแถลงเรื่องสัญญาของเอนจิน
  และสำเนาเดียวที่การันตีว่าตรงกับเอนจินที่ติดตั้งอยู่ คือสำเนาที่มาข้างมัน
- **ฉากที่ไม่มีกรอบคอมโพสิชัน ได้กรอบตามขนาดที่มันวาดตัวเอง** ปกออกมา 1200x510
  อินโฟกราฟิก 1080x1920 สไลด์ 1920x1080 หน้าจอ 1440x900 ขนาดถูกอ่านจากกติกา CSS
  ที่ตั้งค่า `body` — ไม่ใช่กล่องที่ใหญ่ที่สุด ไม่ใช่กล่องแรก แต่กล่องที่ **เป็น** เอกสาร
- **เติมกรอบไม่สำเร็จไม่เงียบอีกต่อไป** "เติมแล้ว" กับ "เติมไม่ได้" เคยเป็นคำตอบเดียวกัน
  และโปรเจกต์ที่ไม่มีกรอบจะถูกเรนเดอร์เป็น 1080x1920 ครอปทิ้ง แล้วกลับมาจาก `check`
  ด้วยรายงานว่างที่อ่านเหมือนผ่าน

## การเรนเดอร์ไม่ได้ติดอยู่ที่ 1080p — เราแค่ไม่เคยส่งตัวเลือกให้มัน

**เรื่องเดิม** `video render` ส่งต่อสี่จากราว ๆ สี่สิบตัวเลือกของเอนจิน คลิปทุกตัว
ที่ออฟฟิศนี้เคยผลิตจึงเป็น 1080p mp4 30fps เพราะไม่มีใครขออย่างอื่นได้

**รุ่นนี้** ส่งต่อเพิ่มอีกห้า

- **`resolution`** — `landscape` `portrait` `square` และ `-4k` ของทั้งสาม
  (3840x2160, 2160x3840, 2160x2160) มันขึ้น deviceScaleFactor ของ Chrome
  ฉาก 1080p จึงออกมาเป็น 4K โดยไม่ขยับ CSS สักไบต์ สิ่งที่มันทำไม่ได้คือเปลี่ยนสัดส่วน
- **`format`** — `mov` กับ `webm` แบกอัลฟา ซึ่งเป็นความต่างระหว่างการ์ดไตเติล
  กับโอเวอร์เลย์ที่วางบนฟุตเทจคนอื่นได้ · `png-sequence` เขียนเฟรม RGBA ให้
  After Effects, Nuke, Fusion · `gif` เล็กพอจะแปะลง pull request
- **`fps`** — รับ ffmpeg rational เป็นข้อความด้วย `"24000/1001"` คือ 23.976
  ซึ่งเป็นเรตที่ฟุตเทจถ่ายฟิล์มมาถึง เดิมสกีมาของเราประกาศเป็น `integer` — เพดานที่
  ออฟฟิศนี้สร้างเองและเอนจินไม่มี
- **`variables`** — JSON ที่ merge ทับค่าตั้งต้นของคอมโพสิชัน อ่านกลับในฉากผ่าน
  `window.__hyperframes.getVariables()` คอมโพสิชันเดียว คำคนละชุด ไม่ต้องแก้มาร์กอัป
  ระหว่างการเรนเดอร์
- **`strict`** — ให้ lint error หยุดการเรนเดอร์ ปิดไว้เป็นค่าตั้งต้น เพราะครึ่งหนึ่ง
  ของสิ่งที่ตัวตรวจเลย์เอาต์รายงานกับคลังนี้คือดีไซน์ของฉาก

**ที่ไม่ส่งต่อ และบอกว่าไม่ส่ง** `--crf` `--video-bitrate` `--gpu` `--workers`
และทุกอย่างใต้ cloud/lambda/cloudrun — การเรนเดอร์เกิดบนเครื่องนี้หรือไม่เกิดเลย

**ช่องว่างที่เขียนไว้แทนการกลบ** สี่สัดส่วนที่ใช้กันทั่วไปคือ 16:9, 9:16, 1:1 และ 4:5
ชั้นนี้ครอบคลุมสามอันแรก และ**ไม่มีฉาก 4:5 เลยสักฉาก** ไม่มีพรีเซ็ตไหนทำให้ได้ด้วย

## ความยาว ถูกพูดออกมาเมื่อมันไม่ใช่ของคนขอ

**เรื่องเดิม** `seconds` ถึงสี่ในห้าสิบฉาก — ฉากที่ผู้เขียนใส่ `__VIDEO_DURATION__`
ไว้เพราะคีย์เฟรมถูกสร้างมาให้ยืด อีกสี่สิบหกมันไม่ทำอะไรเลยและไม่พูดอะไรเลย เอเจนขอ
คลิป 20 วินาทีจึงได้ 30 รายงานว่า 20 และไม่มีใครรู้จนกว่าจะมีคนดู

**รุ่นนี้** `video new` บอกออกมาว่าตัวเลขที่ขอมาไม่ได้ถูกใช้ ฉากนี้ยาวเท่าไหร่ที่เขียน
ไว้ในไฟล์ และจะเปลี่ยนต้องแก้อะไรบ้าง ส่วน `render` ตอบว่า `seconds` ไม่ใช่ตัวเลือก
ของมันแทนที่จะเงียบ — และคำตอบนั้นขี่ไปกับความล้มเหลวด้วย ไม่ใช่แค่ทางสำเร็จ:
คำแก้ที่มาถึงเฉพาะตอนไม่มีอะไรผิดพลาด คือคำแก้ที่ไปไม่ถึงคนที่กำลังทำผิดซ้ำ

## รูปที่แทรกกลางผลลัพธ์ ทำให้ทั้งเทิร์นตาย

**เรื่องเดิม** เทิร์นที่วิ่งมา 187 วินาที ขับเบราว์เซอร์ผ่านมาสิบเอ็ดรอบ ตายด้วย
`400: messages.52: tool_use ids were found without tool_result blocks immediately after`
ต้นเหตุเป็นของเราเอง รูปของเครื่องมือขี่ไปใน `tool_result` ไม่ได้ (Anthropic ยอม
ฝั่งที่เข้ากันได้กับ OpenAI ไม่ยอม Ollama ไม่มีรูปทรงนั้นเลย) มันจึงถูกส่งเป็นข้อความ
ตามหลัง — แล้วไปคั่นกลุ่ม: รอบที่มี `browser capture` ตามด้วย `browser console`
ถึงสายเป็น `tool_result A → รูป → tool_result B` ทั้งที่ Anthropic บังคับว่า
ทุก `tool_result` ต้องอยู่หน้าสุดของเทิร์นตอบ

คอมเมนต์ตรงนั้นเขียนว่าใช้ได้ทั้งสามภาษา และมันใช้ได้จริง — ตราบใดที่หนึ่งรอบมีการเรียกเดียว

**รุ่นนี้** รูปถูกพักไว้จนกว่าผลลัพธ์ของ response นั้นจะถูกเขียนครบ ผูกกับ response
ไม่ใช่กับกลุ่มที่วิ่งขนาน ซึ่งเป็นตัวแก้ไม่ใช่รายละเอียด: id ที่ต้องถูกตอบพร้อมกันคือ id
ในข้อความผู้ช่วยก้อนเดียว ส่วนกลุ่มขนานแบ่งข้อความนั้นเป็นหลายชุดได้ และแก้ที่ชั้นภาษาด้วย
— `tool_result` ของเทิร์น user ถูกยกขึ้นหน้าแบบรักษาลำดับเดิม เทิร์นที่เรียงถูกอยู่แล้ว
คืนกลับทั้งก้อนโดยไม่แตะ

กระทบทุกแถวที่เป็น Anthropic runtime: `deepseek` ซึ่ง endpoint ตั้งต้นคือ
`api.deepseek.com/anthropic/v1` และ `anthropic` เอง

## หน้า ผลงาน กรองตามชนิดได้ และเลิกนับซอร์สทรีเป็นผลงาน

**เรื่องเดิม** หน้า ผลงาน อ่านสดจากโฟลเดอร์ output แล้วเดินลงไปทุกชั้น มีชิปกรอง
สองปุ่ม — ไฟล์ กับ วิดีโอ — ซึ่งเขียนไว้ตอนที่กองนั้นมีแต่ภาพหน้าจอ นับดิสก์จริง
เมื่อ 8 ก.ย.: 55 เซสชัน 8,567 ไฟล์ โดย **เซสชันเดียวกินไป 8,269** ข้างในมีผลงานจริง
สองไฟล์ แล้วมีเช็คเอาต์ของรีโปนี้ทั้งก้อนวางอยู่ข้าง ๆ อีก 8,267 ไฟล์ (`third_party`
6,508) อีก 54 เซสชันรวมกันมีของจริง 300 ไฟล์

มันไม่ได้มาเป็นการ์ดผิดใบเดียว การจัดกลุ่มใช้พาธโฟลเดอร์เป็นคีย์ ซอร์สทรีก้อนเดียว
จึงกลายเป็นเด็คหลายร้อยใบที่ชื่อตามไดเรกทอรีของซอร์สคนอื่น และทะลุเพดาน 5,000 ไปแล้ว

**รุ่นนี้** สองอย่าง

- **เช็คเอาต์ไม่ใช่ผลงาน** กติกาที่จับตัวจริงคือ *มี `.git` อยู่ข้างในไหม* ไม่ใช่ลิสต์ชื่อ
  โฟลเดอร์ — ของบนดิสก์เจ้าของชื่อ `Aetox` เฉย ๆ ไม่มีลิสต์ชื่อไหนที่จะมีมันอยู่
  บวกชื่อที่เป็นเครื่องมือของคนอื่นชัด ๆ (`node_modules`, `third_party`,
  `__pycache__`) ไม่ใช้กติกาขนาดหรือความลึก เพราะผลงานจริงใหญ่และลึกได้
- **ชิปกรองเจ็ดชั้น** ทั้งหมด · รูป · วิดีโอ · สไลด์ · ฉากวิดีโอ · เว็บ · เสียง ·
  เอกสาร · ตาราง โดยโชว์เฉพาะชั้นที่มีของอยู่จริงในช่วงเวลาที่เปิดอยู่

**สไลด์ ฉากวิดีโอ และเว็บ เป็น .html เหมือนกันทั้งสาม** และไม่มีอะไรในชื่อแยกมันออก —
`index.html` เป็นชื่อที่สมเหตุสมผลของทั้งสามอย่าง ชนิดจึงถูกตัดสินที่เอนจินด้วยการเปิด
หัวไฟล์อ่าน 64KB ไม่ใช่ regex บนชื่อไฟล์ในหน้าต่าง และการตัดสินว่าอะไรเป็นเด็คใช้คู่
`deck.Whole` + `deck.Count` ชุดเดียวกับห้องสไลด์ เพราะสองห้องที่นิยามเด็คไม่ตรงกัน
คือหน้าที่วางไฟล์ไว้บนชั้นสไลด์ที่ห้องสไลด์ปฏิเสธจะเปิด

**ไม่มีไฟล์ไหนถูกลบ** ของที่ถูกวางไว้ยังอยู่บนดิสก์ครบ หน้านี้แค่เลิกเรียกมันว่าผลงาน

## แถบแท็บ

**เรื่องเดิม** เจ้าของบอกว่า *"ของเรามันกลืนไป"* เทียบกับเบราว์เซอร์ที่แท็บสดเป็นรูปทรง
สว่างที่ชี้ได้ ที่นี่เส้นใต้แบกงานอยู่คนเดียว และเส้นใต้มองไม่เห็นจนกว่าจะรู้อยู่แล้วว่า
ต้องมองตรงไหน

**รุ่นนี้** แถบจมลง แท็บที่ยืนอยู่ยกขึ้นเป็นชิปที่ลอยอยู่ในแถบ (มีอากาศบนล่าง —
รอบแรกทำเต็มความสูงและถูกตีกลับ *"ชิดบนชิดล่างเกินไปไม่ผ่าน"*) เส้นใต้หายไป เพราะ
เส้นใต้เป็นของแท็บที่ติดกับพื้นข้างล่าง อันนี้ไม่ได้ติดกับอะไร เครื่องหมายจึงวิ่งรอบตัวมัน

- **พื้นยกขึ้นบวกเส้นขอบกลาง ๆ** เพราะพื้นอย่างเดียวไว้ใจข้ามธีมไม่ได้ — raised-over-sunken
  ได้ 1.45 บน nord และ 1.09 บน rose-pine ซึ่งที่ 1.09 ชิปเป็นแค่ข่าวลือ ขอบสีแอคเซนต์
  ลองแล้วอ่านเป็นวงโฟกัส สีไปอยู่ที่ไอคอนแทน ตรงที่มันบอกชื่อแท็บ ไม่ใช่ล้อมแท็บ
- **แท็บกว้างเท่าชื่อของมัน** เลน 200px เดิมคือตัวที่ตัดชื่อให้สั้นทั้งที่แถบยังว่างครึ่งหนึ่ง
- **ปุ่มปิดเป็นเป้ากลม หรี่ไว้ ไม่ใช่ซ่อน** แถบที่ × โผล่ตอนโฮเวอร์เท่านั้น บังคับให้กวาด
  ทั้งแถวเพื่อดูว่าอันไหนปิดได้
- **เปิดกับปิดมีจังหวะ** `sidle` ยืดที่ความกว้าง ไม่ใช่ opacity — ชิปที่จางเข้ามาเต็มขนาด
  ยังผลักเพื่อนบ้านในเฟรมเดียวอยู่ดี ซึ่งคือการกระโดดนั้นเอง (เจ้าของ 7 ก.ย.:
  *"อนิเมชั่น แบบเพิ่มและลบ อ่ะควรจะมีนะ แบบไม่ใช่โดดพึบพับ"*)

## คู่มือของเอนจินเรนเดอร์ 20 เล่ม ที่ยังไม่มีใครได้

hyperframes เขียนคู่มือของตัวเองเป็น Agent Skills 20 โฟลเดอร์ 904 ไฟล์ และแพ็กเกจ
npm ที่เราโหลดมาแบกมาแค่สอง อีก 18 อันเขาให้ดึงตอนใช้งานผ่าน GitHub ซึ่งเราพิน
`HYPERFRAMES_NO_AUTO_INSTALL=1` ไว้ ประตูนั้นปิด และ 18 อันนั้นไม่เคยมาถึงเครื่องใคร

รุ่นนี้เปิด **ชั้นที่สาม** ของสกิล — ความรู้ที่มาเป็นดาวน์โหลดพิน อยู่ถัดจากของผู้ใช้
และของที่ติดมากับไบนารี อยู่นอกบ้านของเวิร์กเกอร์โดยตั้งใจ เพราะ Dest ของคอมโพเนนต์
ถูกลบก่อนแตกทุกครั้ง ชี้ดาวน์โหลดไปที่บ้านจึงเท่ากับลบสกิลที่ผู้ใช้เขียนเองทิ้งในครั้งแรก
ที่พินขยับ อ่านได้ครบทั้งสามระดับ: รายชื่อ ตัวเล่ม และไฟล์ `references/` ที่ตัวเล่มชี้ไป
พร้อม job ที่แพ็กจาก upstream ที่แท็กเดียวกับเอนจินที่ติดตั้ง นับไฟล์สองรอบ และ
ปฏิเสธแท็กที่ปล่อยไปแล้ว

**ยังไม่มีใครได้ก้อนนี้** job ยังไม่เคยรัน ยังไม่มีแถวใน `Manifest()` และไม่มีปุ่มไหน
ในแอปที่ติดตั้งได้ AGENT.md ของเอเจนวิดีโอจึงเขียนไว้ให้รับสภาพนั้นได้ — ให้ดู
`skills_list` ก่อน แล้วถ้าไม่มีก็บอกไปตรง ๆ ว่าไม่มี ไม่ใช่ประกาศว่ามียี่สิบอันแล้ว
ให้ไปหาของที่ไม่มีอยู่ (ซึ่งเป็นสิ่งที่มันทำอยู่จนถึง 8 ก.ย.) รายละเอียดทั้งหมดอยู่ที่

## อื่น ๆ ในรุ่นนี้

- **GSAP ถูกชี้แบบ root-relative จากทุกไฟล์ รวมซับคอมโพสิชัน** เดิมมันสัมพัทธ์จาก
  ไฟล์ที่โหลด ด้วยเหตุผลว่าซับคอมโพสิชันอยู่ลึกลงไปหนึ่งชั้นจึงควรไต่ขึ้นหนึ่งชั้น
  มันอยู่ลึกลงไปหนึ่งชั้น **บนดิสก์** แต่ตัวเรนเดอร์เสิร์ฟมันโดยใช้รากโปรเจกต์เป็น base URL
  `../` จึงไต่เหนือราก และ `check` ปฏิเสธ ฉากโฟลเดอร์เก้าในสิบสามโดนหมด — 8 ข้อผิดพลาด
  บน `product-launch-30s` — เรนเดอร์ยังทำงานเพราะตัวเรนเดอร์เขียนพาธใหม่เอง เอเจนจึง
  ได้รายงานที่บอกว่าเทมเพลตดีพัง เทมเพลตแบนสะอาด แล้วมันก็เลิกหยิบโฟลเดอร์
- **ความยาวของโปรเจกต์อ่านจากธาตุรากจริง ๆ** เดิมหยิบตัวแรกที่มี `data-duration`
  ซึ่งใน `grain-texture-hero` (2.5s) กับ `structured-grid` (1.86s) เป็นซับคอมโพสิชัน
  และถูกมาก่อนเพียงเพราะตัวเติมค่าวิ่งไปแล้ว
- **`png-sequence` ได้โฟลเดอร์เฟรม ไม่ใช่ไฟล์** การตรวจขนาดกับโฟลเดอร์อ่านได้ 0
  บนวินโดวส์ และจะเรียกการส่งออกเฟรมที่สำเร็จทุกครั้งว่าล้มเหลว
- **แท็บไฟล์ถูกใส่คีย์** ไม่งั้น Svelte ปิดแท็บ **ตัวสุดท้าย** ไม่ว่ากดตัวไหน — มองไม่เห็น
  ตอนแท็บโผล่และหายในเฟรมเดียว และเห็นชัดทันทีเมื่อมันใช้เวลาจากไป 180ms
- **แถบรูปในคำตอบปิดแท็ก `<div>` ครบ** รอยที่ v1.5.18 เปิดค้างไว้ตอนเอารูปหลายใบ
  มาเรียงเป็นแถว
- **`tools:` ของเอเจนวิดีโอถูกเขียนลงโปรไฟล์** แทนการรับมรดกทั้งโต๊ะ 27 ตัว ซึ่งเคยยัด
  n8n, windmill, plugin_install, sheet_write ให้คนทำฉาก ทุกตัวคือน้ำหนักพรอมป์ต่อคำขอ
- **`.gitignore`** ไม่ตาม `.vscode/` และ worktree ที่วางซ้อนไว้เทียบรุ่น
