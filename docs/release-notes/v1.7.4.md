# 🧭 Aetox v1.7.4

รุ่นแก้ไขเร่งด่วนนี้คืนการวาดและการรับอินพุตของเบราว์เซอร์ในตัวให้ WebView2 จัดการสเกลตามจอ
โดยตรง หลังการบังคับ raster scale จากโฮสต์ทำให้หน้าเว็บวัด viewport และตำแหน่งล้อเลื่อนผิดบนจอ
ที่ตั้งสเกลไว้ 175%

---

## หน้าเว็บกลับมาวัดและเลื่อนได้ตรงกรอบ

- เอาการบังคับ `RasterizationScale` จาก HWND ออก เพราะ bounds ของแท็บเป็นพิกเซลจริงอยู่แล้ว และ
  การกำหนดสเกลซ้ำทำให้ขนาด CSS viewport กับพื้นที่ที่เห็นไม่ตรงกัน
- คืนให้ WebView2 ติดตาม monitor scale และ text scale เอง เหมือนเส้นทางที่ใช้งานได้ก่อนเกิด regression
- คง raw-pixel bounds สำหรับตำแหน่งและขนาดของ native browser window จึงไม่ทำให้กรอบแท็บขยายหรือ
  หดซ้ำเมื่อ Windows ใช้สเกลมากกว่า 100%
- binding ของ `PutShouldDetectMonitorScaleChanges` ส่งค่า `BOOL` เป็น `0/1` จริงที่ขอบ COM และมี
  fake-vtable regression test ป้องกันการส่ง pointer แบบเดิมกลับมา

## การตรวจสอบ

- ชุดทดสอบของ vendored `go-webview2` ผ่าน
- ชุดทดสอบ Go ของ desktop ผ่าน
- production build ของ Wails ผ่าน และสร้าง executable ทดสอบได้
- `scoop/aetox.json` ชี้ไป `v1.7.4` แล้ว ส่วน `hash` ยังเป็นของรุ่นก่อนตามขั้นตอนปกติ และจะเติม
  จาก `checksums.txt` ของ artifact ที่ workflow เผยแพร่จริง
