## ระดับความคิดของเอเจนและซับเอเจนแต่ละตัว

**เรื่องเดิม** ตัวช่วยทุกตัวคิดตามระดับที่แชทตั้งอยู่ตอนสั่งงาน ตัวค้นไฟล์จึงคิดระดับ `ultra`
ตอนแชทกำลังวางแผน และตัววางแผนคิดระดับ `low` ตอนแชทกำลังอ่านผ่าน ๆ เจ้าของ:
*"ทำให้เราปรับระดับความคิดได้"*

**รุ่นนี้** `think:` ใน frontmatter ของโปรไฟล์ เว้นว่าง = ตามแชท เหมือนที่ทุกไฟล์เป็นมา
บนหน้าตั้งค่าเป็นแถวที่สามใต้ผู้ให้บริการกับโมเดล เรียงแบบเดียวกับ picker ของแชท และ
**โผล่เฉพาะเมื่อโมเดลที่เลือกคิดได้จริง** (เคยขึ้นเป็นสีเทากดไม่ได้ทุก runtime ในเครื่อง
ซึ่งอ่านว่าพัง) ระดับถูกตรวจกับผู้ให้บริการและโมเดล**ของตัวช่วยเอง** ไม่ใช่ของแชท เพราะแชท
อาจอยู่ที่ระดับที่โมเดลนั้นไม่มี (`ultra` ของ Codex บนตัวช่วยที่ใช้ DeepSeek) และหน้าแชทกับ
หน้าตั้งค่าเอเจนอ่านบันไดเดียวกัน — มีเทสต์ยืนยันว่าสองหน้าไม่มีวันตอบต่างกัน ไฟล์ที่มี `think:`
อยู่แล้วบนโมเดลที่ไม่มีระดับยังเห็นแถวของตัวเองพร้อมคำเตือน สลับโมเดลไปดูอย่างอื่นไม่ทำให้
บรรทัดที่เขียนไว้หาย

**ยังไม่ได้ทำ** — โมเดลบน Ollama/LM Studio ยังไม่ได้ปุ่มนี้ ตารางความสามารถบอกว่าสองตัวนี้
เรียกเครื่องมือได้แต่ไม่คิด และการเปิดต้องให้ทางส่ง request ของ Ollama ส่ง `think` จริง
ไม่งั้นได้ปุ่มที่กดแล้วไม่เกิดอะไร

## Codex: ความคิดของโมเดลกลับไปครบ และ `prompt_cache_key` ที่ถอนออกเพราะตัวเลข

**เรื่องเดิม** ปลายทางของ Codex เป็น `store:false` เซิร์ฟเวอร์ไม่เก็บอะไร ความคิดของรอบที่แล้ว
ถูกส่งกลับมาแบบเข้ารหัสเพื่อให้รอบถัดไปแบกกลับไป เราขอมันมาตั้งแต่วันที่เขียน provider
และคอมเมนต์ข้างบรรทัดนั้นก็เขียนไว้เองว่าต้องส่งกลับ — แต่ไม่เคยมีโค้ดเก็บหรือส่งกลับเลย
สิ่งที่เซิร์ฟเวอร์เห็นจึงต่างจากที่ตัวเองผลิตไว้ตั้งแต่คำตอบแรกของทุกบทสนทนา

**รุ่นนี้** ส่งกลับครบไบต์ ลำดับถูก ติดชื่อผู้ให้บริการไว้ด้วยเพราะแชทที่สลับโมเดลกลางทางถือ
บล็อกของอีกค่าย และส่งข้ามค่ายคือ 400 ทั้งเทิร์น ยิงจริงกับ tool round trip แล้วไม่ล้ม

**และเรื่องที่ถอนออก** ตอนเช้าใส่ `prompt_cache_key` เข้าไปเพราะ CLI ตัวจริงส่ง และเอกสาร
ระบุมันไว้สำหรับอาการที่วัดได้พอดี (แคชติด 0%, 0%, 67%, 0% สี่เทิร์นติดโดย prefix ไม่เปลี่ยน)
ตอนเย็นวัดในแอปจริงบน `gpt-5.6-luna` คำถามชุดเดียวกัน ต่างแค่มี key กับไม่มี:

| | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| มี key | 0% | 0% | 0% | 0% | 0% |
| ไม่มี key | 0% | 87% | 98% | 97% | 84% |

เมื่อไม่ส่ง key ปลายทางเลือกเครื่องจาก prefix ของคำขอเอง และพรอมต์ระบบของ Aetox เหมือนกัน
ทุกแชท (~8.9k โทเค็น) ทุกแชทจึงใช้แคชของกันและกันได้ key สุ่มต่อแชทคือส่งแต่ละแชทไปเครื่อง
ของตัวเองที่ไม่มีอะไรอยู่เลย ถอนออก ถ้าจะกลับมาต้องเป็นค่าที่ผูกกับ prefix ที่ใช้ร่วมกัน
ไม่ใช่ค่าสุ่มต่อบทสนทนา (§263.3)

## หน้าเอเจนเฉพาะทางเป็นห้องคุย ตั้งค่ากลับมามีแถวของตัวเอง (§262)

**เรื่องเดิม** หน้ารายชื่อเอเจนมีเฟืองทุกการ์ด ปุ่มจ้าง ลิงก์โฟลเดอร์ และป้ายชี้ไปสามหน้า ส่วนตัว
แก้ไขอยู่ในตั้งค่าโดยไม่มีแถวในเมนู เข้าได้ทางเดียวคือเฟืองบนการ์ด เจ้าของ: *"ตอนนี้มันยัง
มีฟุ้งนิดๆ"*

**รุ่นนี้** หน้าเอเจนเฉพาะทางเหลือการ์ดกับปุ่มคุย ประตูเดียวไป **ตั้งค่า › เอเจนเฉพาะทาง**
ซึ่งเป็นแถวใหม่ในกลุ่มโมเดล AI: รายการ ปุ่มเพิ่มสีหลักแบบสร้างทีม ตัวแก้ไขปิดกลับมาที่รายการ
ในตัวแก้ไข แท็บ "ตั้งค่า MCP สำหรับเอเจน" กับ "สกิลเฉพาะสำหรับเอเจน" ลิสต์ของจริง: MCP ทุกตัว
พร้อมสวิตช์ (บันทึกแล้วเขียนทันทีผ่านทางเดียวกับห้องความสามารถ ตัวใหม่ติ๊กแล้ววางตอนบันทึก)
สกิลของโฟลเดอร์ (ตัวใหม่ติ๊กจากชั้นแล้วคัดลอกตอนบันทึก) ครบหกแท็บตั้งแต่ตอนสร้าง ไม่มีแว๊บ
"ยังไม่มี" ก่อนดิสก์ตอบ และชื่อ "เอเจนเฉพาะทาง" คำเดียวทุกหน้า (*"เช็คชื่อแต่ละหน้าดีๆนะครับ
เดี๋ยวงง"*) การ์ดโต๊ะที่สังกัดออกจากตัวแก้ไข — โต๊ะเป็นเพดานที่เครื่องยนต์ใช้ ไม่ใช่ของที่ฟอร์ม
ให้ใครเปลี่ยน

## Google Drive, Gmail, Calendar, Docs, Sheets ในห้องสมุด MCP

**เรื่องเดิม** เจ้าของขอ *"จัดระเบียบ Google Drive"* แล้ว *"เชื่อมตัวอื่นๆ ด้วย"* server ของ
Google เองทำข้อแรกไม่ได้ (ยัง preview มีแค่ค้น/อ่าน/สร้าง/คัดลอก ไม่มีย้าย เปลี่ยนชื่อ ลบ)
และต้องการ client id ที่ Google ออกให้แอปโดยไม่มีทางลงทะเบียนอัตโนมัติ

**รุ่นนี้** แถว **google-workspace** แถวเดียว (โปรแกรมเดียวถือทั้งห้าบริการ ห้าแถวคือโปรแกรม
เดียวกันรันห้ารอบ จ่ายค่าล็อกอินห้าครั้ง) กดเพิ่มแล้ว**เปิดฟอร์ม ไม่เซฟ**: บรรทัด env เขียนไว้
ให้แล้ว ช่องที่ว่างคือ OAuth client ที่คุณต้องทำเองใน Google Cloud Console และโน้ตใต้ฟอร์ม
เป็นกล่องเดียวบอกเป็นขั้น ๆ ว่าไปทำที่ไหน ใส่ redirect URI อะไร เปิด API ตัวไหน เครื่องต้องมี
`uv` และครั้งแรกจะเปิดเบราว์เซอร์ให้เข้าบัญชี Google — ท้ายกล่องบอกว่ายังไม่มีอะไรถูกบันทึก
จนกว่าจะกดเพิ่ม (*"ทำ CSS ดีๆหน่อย"*)

**เขียนไว้เป็นข้อยกเว้น** — แถวนี้ผิดกฎ "กดครั้งเดียวรวมล็อกอิน" ของห้องสมุด เพราะต้องไป
สร้าง client กับ Google ก่อน มันอยู่บนชั้นได้เพราะไม่มีทางอื่นที่จัดระเบียบ Drive ได้จริง และ
คอมเมนต์เหนือแถวเขียนว่าเป็นข้อยกเว้น ไม่ใช่กฎใหม่ ยังไม่ติดป้าย "พิสูจน์แล้ว" จนกว่าจะล็อกอิน
จริงกับ Drive จริง ซึ่งต้องใช้ client ที่มีแต่เจ้าของทำได้

## คลังสตูดิโอที่โฟลเดอร์ย้ายไปแล้ว

**เรื่องเดิม** ย้ายโฟลเดอร์คลังออกจาก Downloads แล้ว สารบัญยังจำ 1,855 แถว หน้าเรียกดูวาด
ครบ กดฟังแล้วเงียบ (404 เงียบ ๆ ทุกกด) และเอเจนก็ค้นเจอไฟล์ที่เปิดไม่ได้

**รุ่นนี้** คลังที่โฟลเดอร์ไม่อยู่ถูกกรองออกจากหน้าเรียกดูและ `asset_find` เหลือแค่รายการใน
ตั้งค่าที่ติดป้ายให้ถอดหรือย้ายกลับ สารบัญยังเก็บแถวไว้ — เสียบไดรฟ์กลับมาแล้วใช้ได้เลยโดยไม่
ต้องสแกนใหม่ หน้าเรียกดูขึ้นแถบบอกเหตุที่แถวหาย และแถวที่เล่นล้มเหลวด้วยเหตุอื่นบอกบนแถวเอง
