# 🧩 Aetox v1.5.20

รุ่นนี้เป็นรุ่นของ **การใช้โปรแกรมที่คุณเปิดอยู่แล้ว** — Aetox อ่านและกดในหน้าต่าง
ของโปรแกรมอื่นได้ ตามที่คุณเลือกเองว่าโปรแกรมไหน ปิดไว้เป็นค่าเริ่มต้น และตอนปิดอยู่
โมเดลไม่ได้รับเครื่องมือนี้เลย ไม่ใช่ได้ไปแล้วโดนปฏิเสธ

Aetox เคยมีเครื่องมือแบบนี้แล้วครั้งหนึ่ง มันใช้งานจริงไม่ได้และถูกลบทิ้งเมื่อ
25 ก.ค. 2026 รุ่นนี้ไม่ได้เอาของเดิมมาซ่อม แต่เปลี่ยนวิธีเล็งเป้าทั้งหมด

---

## Aetox ใช้โปรแกรมอื่นในเครื่องคุณได้

**เรื่องเดิม** ถ้างานอยู่ในโปรแกรมที่ไม่มีคำสั่งบรรทัด ไม่มี API และไม่ใช่หน้าเว็บ
Aetox ทำอะไรไม่ได้เลย บอกได้แค่ว่าทำไม่ได้ ตัวที่เคยมีเมื่อกรกฎาคมเล็งด้วยพิกัด
ที่อ่านจากภาพหน้าจอด้วย OCR ซึ่งอ่านตัวหนังสือได้แต่ไม่ได้พิกัดของมันกลับมา
มันจึงอ่านหน้าจอออกแต่ชี้ไม่ถูกโดยหลักการ แยกจากบั๊กที่ทำให้มันพังจริง ๆ

**รุ่นนี้** เครื่องมือ `computer` เจ็ดคำสั่ง ดูว่ามีหน้าต่างอะไรเปิดอยู่ อ่านสิ่งที่อยู่
ในหน้าต่าง ถ่ายภาพหน้าต่าง เรียกขึ้นมาหน้าสุด กด พิมพ์ และขอปิด

- **เล็งที่ปุ่ม ไม่ใช่ที่พิกัด** อ่านผ่าน UI Automation ของ Windows แล้วให้เลข `[n]`
  กับทุกอย่างที่กดหรือพิมพ์ได้ แบบเดียวกับที่ `browser` ทำกับหน้าเว็บมาตลอด
  ปุ่มที่ขยับตำแหน่งไปแล้วยังเป็นปุ่มเดิม
- **ใช้ได้กับโมเดลที่ไม่มีตา** นี่คือเหตุผลที่ไม่ลอกวิธีของ Codex บนวินโดวส์ ซึ่งอ่าน
  ภาพหน้าจอล้วน วิธีนั้นได้ผลเพราะเขามีโมเดลตัวเดียวที่เทรนมาให้ชี้พิกัดบนภาพ ส่วน
  Aetox ต่อกับผู้ให้บริการ 22 เจ้า รวมโมเดลที่รันในเครื่องคุณเอง ซึ่งส่วนใหญ่ทำแบบนั้นไม่ได้
- **พิมพ์ภาษาไทยลงไปแล้วตรงทุกตัวอักษร** ข้อความถูกยื่นให้โปรแกรมปลายทางตรง ๆ ไม่ได้
  แปลงเป็นลำดับการกดปุ่มที่ต้องผ่านผังแป้นพิมพ์ ซึ่งเป็นครึ่งของของเดิมที่เชื่อถือยากที่สุด

## คุณเป็นคนเลือกว่าโปรแกรมไหน

**เรื่องเดิม** ร่างแรกทำแบบที่ Codex กับ Claude ทำ คือเด้งการ์ดถามตอนที่เอเจนต์แตะ
โปรแกรมนั้นครั้งแรก แล้วจำคำตอบไว้ ซึ่งใช้งานได้ แต่มันถามในจังหวะที่แย่ที่สุดเท่าที่
จะเป็นไปได้ การ์ดที่เด้งกลางเทิร์นขอให้คุณตัดสินใจแบบรีบ ๆ เรื่องโปรแกรมที่คุณไม่ได้
กำลังคิดถึง ในขณะที่เอเจนต์รออยู่ ทุกอย่างในจังหวะนั้นเชียร์ให้กดใช่

**รุ่นนี้** เลือกล่วงหน้าที่ **ตั้งค่า > การใช้คอมพิวเตอร์** โดยไม่มีอะไรรออยู่

- **สวิตช์ชื่อ "อนุญาตให้ควบคุมคอมพิวเตอร์" ปิดเป็นค่าเริ่มต้น** และปิดอยู่คือโมเดล
  ไม่มีเครื่องมือนี้เลย ไม่ใช่มีแล้วถูกปฏิเสธ ความต่างไม่ใช่เรื่องเล็ก โมเดลที่อ่านเจอ
  เครื่องมือในรายการจะวางแผนบนสมมติฐานว่าตัวเองคุมเครื่องได้ พอเรียกถึงโดนบอกว่าไม่ได้
  ก็เสียหนึ่งรอบและได้แผนที่ตั้งอยู่บนเรื่องที่ไม่เคยจริง บวกกับที่มันกินโควตาข้อความ
  ประมาณ 280 หน่วยทุกครั้งที่คุยกัน สำหรับความสามารถที่ปิดอยู่
- **รายการโปรแกรมสร้างจากหน้าต่างที่เปิดอยู่จริง** พร้อมไอคอนของโปรแกรมนั้นเอง
  ดึงออกมาจากไฟล์ของมัน เป็นภาพเดียวกับที่วินโดวส์วาดบนแถบงาน คุณจึงเลือกจากการจำได้
  ไม่ใช่จากการอ่านชื่อไฟล์
- **ปุ่ม "เลือกจากเครื่อง…" สำหรับโปรแกรมที่ยังไม่ได้เปิด** ชี้ไปที่ไฟล์โปรแกรมไหนก็ได้
  กฎเดียวกันยังใช้ เลือกเทอร์มินัลจากตรงนั้นก็ยังถูกปฏิเสธเหมือนเลือกจากรายการ
- **สิทธิ์ที่ให้แล้วอยู่ในรายการที่ถอนได้** ไม่ใช่สิทธิ์ที่หมดอายุเงียบ ๆ พร้อมเซสชัน
  แบบที่อีกสองเจ้าทำ สิทธิ์ที่หายไปเองคือสิทธิ์ที่คุณไม่มีวันรู้ว่าเคยให้อะไรไป
- **เทอร์มินัลกับเบราว์เซอร์ถูกปฏิเสธโดยตั้งใจ** และคำปฏิเสธบอกว่าให้ใช้ `shell`
  หรือเบราว์เซอร์ของ Aetox แทน การกดผ่านหน้าต่างเทอร์มินัลคือ shell ที่หน้าตาแย่กว่า
  และไม่มีบันทึกว่ารันอะไรไป

## คุณเห็นมันทำงาน และเมาส์ยังเป็นของคุณ

**เรื่องเดิม** แถบบอกสถานะอยู่ในหน้าต่างของ Aetox เอง แต่โหมดนี้จะยกหน้าต่างที่กำลัง
ถูกคุมขึ้นมาทับ Aetox วินาทีที่แถบนั้นสำคัญที่สุด มันจึงอยู่หลังสิ่งที่มันกำลังเตือน

**รุ่นนี้**

- **ขอบจอมีแสงวิ่งรอบตลอดเวลาที่มันคุมอยู่** เป็นหน้าต่างของตัวเองที่คลิกทะลุได้
  ไม่รับโฟกัส และอยู่บนสุดเสมอ ค้างต่ออีก 2.5 วินาทีหลังจบแต่ละคำสั่ง เพราะคำสั่งหนึ่ง
  ใช้เวลาไม่ถึงวินาที ถ้าดับทันทีขอบจอจะกะพริบเป็นไฟฉุกเฉินแทนที่จะเป็นสถานะ
- **Aetox มีตัวชี้ของตัวเอง** วงแหวนเรืองแสงบนปุ่มที่กำลังกด เคลื่อนเข้าหาในหนึ่งในสี่
  วินาที **เมาส์จริงของคุณไม่ขยับ** Codex บน macOS ให้แต่ละเอเจนต์มีเคอร์เซอร์ของตัวเอง
  ซึ่งวินโดวส์ไม่มีของเทียบเท่า และการย้ายเมาส์จริงคือการแย่งมันไปจากมือคุณกลางประโยค
  ที่วาดแทนจึงเป็นตัวชี้ที่สอง และมันซื่อสัตย์กว่าด้วย เพราะไม่มีอะไรในระบบนี้เล็งด้วยพิกัด
  วงแหวนจึงเป็นการรายงานว่ากดอะไร ไม่ใช่กลไกที่ใช้กด

## เวลาล้มเหลว มันบอกว่าล้มแบบไหน

**เรื่องเดิม** เครื่องมือตัวที่ถูกลบทิ้งมีประโยคความล้มเหลวสองประโยคสำหรับทุกสถานการณ์
คอมมิตที่ลบมันเขียนไว้ว่า *"deleted rather than debugged"* — ลบทิ้งแทนที่จะไล่แก้
เพราะจากบันทึกการสนทนา แยกไม่ออกว่าเกิดอะไรขึ้นกันแน่

**รุ่นนี้** ทุกความล้มเหลวลงเอยเป็นประโยคเดียวที่บอกสิ่งที่เปลี่ยนก้าวถัดไป

| เกิดอะไรขึ้น | คุณต้องทำอะไร |
|---|---|
| จอล็อกอยู่ หรือมีหน้าต่างความปลอดภัยของวินโดวส์ขึ้นมา | ปลดล็อกแล้วสั่งใหม่ |
| หน้าต่างนั้นรันด้วยสิทธิ์สูงกว่า Aetox | ทำเองด้วยมือ หรือเปิด Aetox ด้วยสิทธิ์เดียวกัน |
| ปุ่มนั้นถูกปิดอยู่ | หาว่ามีอะไรต้องทำก่อน |
| ปุ่มนั้นย้ายไปแล้วเพราะหน้าต่างวาดใหม่ | อ่านหน้าต่างใหม่ |
| ปุ่มนั้นไม่รับคำสั่งแบบนั้น | เล็งไปที่ตัวที่รับ |
| โปรแกรมหยุดตอบ | รอแล้วอ่านใหม่ |

ตัวจำแนกนี้จับบั๊กได้เองในวันแรกที่มันมี `SetForegroundWindow` คืนค่าศูนย์ได้จากสาม
สถานการณ์ และวินโดวส์ไม่ตั้งรหัสข้อผิดพลาดใด ๆ เลยตอนที่มันปฏิเสธการแย่งโฟกัส โค้ด
รุ่นแรกจึงตีความความเงียบนั้นว่าเป็น "จอล็อก" และรายงานแบบนั้นทั้งที่หน้าต่างอยู่บนจอ
ตรงหน้าและเครื่องปลดล็อกอยู่ — เป็นความผิดชนิดเดียวกับที่ฆ่าของเดิม แต่ถูกจับได้ใน
หนึ่งบ่ายแทนที่จะหลุดออกไป

## สิ่งที่ตั้งใจไม่ทำในรุ่นนี้

- **ไม่คุมเบราว์เซอร์ของคุณ** UI Automation อ่านหน้าต่าง Chrome ได้ แต่ได้แย่ เพราะ
  โครงสร้างที่เว็บสมัยใหม่เปิดให้ระบบช่วยการเข้าถึงไม่ใช่ DOM แผนสำหรับเบราว์เซอร์ของคุณ
  คือส่วนขยายที่ต่อกับโปรไฟล์ที่คุณล็อกอินอยู่ ซึ่งยังไม่ได้สร้าง จนกว่าจะถึงตอนนั้น
  Chrome กับ Edge อยู่ในหน้าตั้งค่าและบอกตรง ๆ ว่ายังใช้ไม่ได้
- **ไม่คุม Excel ที่เปิดค้างอยู่** การถือเวิร์กบุ๊กที่ผู้ใช้ยังไม่ได้บันทึกคือพื้นที่ที่
  ข้อมูลหายได้ ไม่ใช่ฟีเจอร์ `sheet_write` ตอบคำถามที่พบบ่อยกว่าอยู่แล้ว
- **ไม่มีการเล็งด้วยพิกัดสำหรับโมเดลที่มีตา** เพิ่มได้ในภายหลังโดยไม่กระทบของเดิม
- **ยังไม่รองรับ macOS กับ Linux** UI Automation เป็น API ของวินโดวส์ ครึ่งที่ไม่ใช่
  โค้ดวินโดวส์ (ด่านอนุญาต ตาราง ref การจำแนกความล้มเหลว) คอมไพล์และทดสอบได้ทุกแพลตฟอร์ม
  อยู่แล้ว การพอร์ตจึงเป็นการเขียนครึ่งที่เหลือ ไม่ใช่การรื้อ

## อื่น ๆ ในรุ่นนี้

- **พรอมต์เลิกแนะนำเครื่องมือที่เซสชันนั้นไม่มี** เดิมทุกเซสชันบนบรรทัดคำสั่งและทุก
  เซสชันเดสก์ท็อปที่ปิดสวิตช์ ถูกบอกให้เลือกเครื่องมืออื่นก่อน `computer` ทั้งที่ไม่มีมัน
- **เพิ่มตัวตรวจขนาดบล็อกเครื่องมือฝั่งเดสก์ท็อป** แพ็กเกจที่เป็นเจ้าของกฎนั้นสร้าง
  รายการเครื่องมือมาตรฐาน จึงมองไม่เห็นเครื่องมือที่แอปเดสก์ท็อปเพิ่มเข้าไปเลยสักตัว
  วัดแล้วพบว่ามีสิบตัวเกินมาตรฐานอยู่ก่อน จึงจำกัดตัวตรวจไว้ที่ `computer` (280 จาก
  เพดาน 296) และตั้งเป็นงานแยก การตั้งมาตรฐานใหม่ให้เครื่องมือเดิมสิบตัวในคอมมิตเรื่อง
  คุมเครื่อง คือการเปลี่ยนที่ไม่มีใครรีวิว

## เทสต์ที่เพิ่มในรุ่นนี้

ไม่ได้รันสวีตทั้งหมดสำหรับบันทึกนี้ รายชื่อคือของที่เขียนเพิ่มมาพร้อมงาน

- `TestUIAutomationStartsAndWalksARealTree` เดินต้นไม้ของหน้าต่างจริงบนเครื่อง
  ไม่ใช่ของปลอม เพราะ vtable เป็นของชนิดเดียวกับ input buffer: ตรวจรูปร่างได้ทั้งวัน
  โดยไม่มีทางรู้ว่าช่องที่สี่เป็นฟังก์ชันที่คิดไว้จริงไหม
- `TestLiveComputerTypesThaiAndReadsItBack` เปิดหน้าต่างของตัวเอง พิมพ์ไทย 32 ตัว
  แล้วอ่านกลับ ต้องตรงทุกตัวอักษร เป็นข้อสอบที่ทั้งรุ่นนี้ต้องตอบให้ได้
- `TestNoReachFailureIsJustFailed` ล้มทันทีเมื่อมีรหัสข้อผิดพลาดใหม่ที่ยังไม่มีประโยค
- `TestTheModelIsNotGivenTheToolUntilItIsSwitchedOn` และ `TestAbsentMeansOff`
- ห้ากรณีของ "ทำไม ref ถึงหาย" ที่ต้องไม่ตอบว่าหน้าจอเปลี่ยนเมื่อสาเหตุเป็นอย่างอื่น
- เทสต์ของแสงครอบจอ (กลางจอต้องโปร่ง ขอบต้องสว่างเสมอ หัวแสงต้องเคลื่อน สีต้องคูณ
  อัลฟามาแล้ว) และของหน้าตั้งค่าอีกสิบเอ็ดข้อ
