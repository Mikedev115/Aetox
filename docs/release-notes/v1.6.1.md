## เอเจนที่ระบุ `provider:` คิดที่ provider นั้นจริง

**เรื่องเดิม** v1.6.0 บอกว่า "โปรไฟล์ที่ระบุ provider คิดที่นั่น บนโมเดลที่ระบุหรือโมเดล
เริ่มต้นของ provider นั้น" (62ed2bed) ซึ่งจริงในวันที่เขียน — แต่ตอน merge งานนั้นขึ้น
เครื่องยนต์ที่ผ่าแล้ว (305333eb) บรรทัด `ProviderFor: a.providerFor(cfg)` ใน
`bootstrap.Options` หายไป ในขณะที่ `provider_for.go` ยังอยู่ครบ

ทำไมไม่มีอะไรบอก: `task.go` ถือว่า factory เป็น nil ได้ (สภาพปกติของ CLI และเทสต์เก่า)
→ จดใน log แล้วรันเอเจนบน provider ของแชทแทน ซึ่งคือ fallback ที่ฟีเจอร์นี้มีไว้แทนพอดี
การ์ดเอเจนจึงเขียนว่า "deepseek · v4" ขณะที่ความคิดวิ่งอยู่บน provider ของแชท
คนแรกที่พูดคือ golangci-lint บน CI ของ main หลังพุช 1.6.0: `providerFor is unused`

**รุ่นนี้** คืนบรรทัดนั้น และ `TestApplyConfigHandsTheDelegateItsOwnProviderFactory`
อ่าน `TaskOptions` ของ task tool ที่ลงทะเบียนจริง (ผ่าน reflect — ไม่ export options
เพื่อเทสต์เดียว) แดงถ้าถอดบรรทัดออก พิสูจน์แล้วทั้งสองทาง

## Lint ของ main กลับมาเขียว

CI ของ 1.6.0 ([34742838964](https://github.com/Mikedev115/Aetox/actions/runs/34742838964))
แดงที่ Lint ทั้ง Windows / macOS / Ubuntu — golangci-lint 18 จุดที่มากับ 135 คอมมิตที่ไม่ได้
พุชตั้งแต่ 11 ก.ย. (release.yml ไม่รัน lint รุ่นจึงออกได้) จุดที่ 18 คือ `providerFor`
ข้างบน อีก 17 จุดไม่เปลี่ยนพฤติกรรม:

- **unused 9** — `spriteStore.has`, `swpNoZOrder`, `urlSchemeRe`, `webviewUserDataDir`
  (เบราว์เซอร์ย้ายไปจอแล้ว), `reportMarkdown`, `recorder.names` ลบ; `spriteStore.decoded`/
  `warm` และ `abs` ถูกเรียกจาก `companion_windows.go` เท่านั้น จึงแดงเฉพาะ !windows —
  ย้ายไปอยู่กับผู้เรียก
- **wastedassign 4** — `cmd/aetox-engine` network/address, `consolidate` raw, `gen` name,
  `gen/rpc` call
- **sqlclosecheck 1** — การอ่านของ migration 27 แยกเป็น `desksWithTeamlessMainChats`
  ที่ `defer rows.Close()` และคืนก่อน `tx.Exec`
- **bodyclose 2** — `nolint` พร้อมเหตุผลที่บรรทัด: `provider.open` ยื่น body ให้ `stream`
  ที่ `defer Close` เอง; gorilla บอกเองว่า body ของ handshake ไม่ต้องปิด

`golangci-lint run ./...` ว่างทั้ง `GOOS=windows` และ `GOOS=linux` ก่อนคอมมิต
