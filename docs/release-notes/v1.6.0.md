## จอเป็นจอ เครื่องยนต์เป็น process (§248 เฟส 1–2)

**เรื่องเดิม** `desktop.App` ถือทุกอย่าง — 389 binding ใน 71 ไฟล์ (`app.go` 5,447 บรรทัด)
ทั้งครึ่งที่คิดและอ่านไฟล์ กับครึ่งที่เป็นหน้าต่าง อายุของเทิร์นแขวนกับ context ของ Wails
คีย์ผู้ให้บริการไหลเข้าเครื่องยนต์ผ่าน `config.Config.ModelAPIKey` ซึ่งแปลว่าโค้ดที่ import
config ก็ถือคีย์ได้โดยไม่ต้องขอ และไม่มีทางยกครึ่งไหนไปรันบนเครื่องอื่น

**รุ่นนี้** สอง process บนสายเดียว ในเครื่องเดียวกันก็เดินทางนี้ ไม่มีเส้น in-process เหลือ

- **`internal/engine` เป็นแพ็กเกจของตัวเอง** — ย้ายไฟล์ Go 294 ไฟล์ด้วย `git mv`
  แล้วค่อยย้ายกลุ่มที่ต้องมีหน้าต่างกลับมาจอทีละกลุ่ม (dialog, reveal, ขนาดหน้าต่าง,
  self-update, เบราว์เซอร์, computer use, ตัววาดเด็ค, การเข้าสู่ระบบ, เสียงอ่าน) ทุกคอมมิต
  คอมไพล์และเทสต์ผ่าน สิ่งที่เครื่องยนต์ขอจากหน้าต่างกลายเป็นสัญญา `Screen` ตัวเดียว:
  Emit, ProviderTransport, WindowTools, RenderDeck, AgentTab และสามคำถามโต๊ะ
  (DefaultModel, Probe, ModelResident)
- **สายคือ JSON-RPC สองทางบน WebSocket เส้นเดียว** (`internal/engine/rpc`) — unix socket
  ใต้ DataRoot ก่อน (พิสูจน์แล้วว่า AF_UNIX บน Windows 11 ใช้ได้) ตกไป `--tcp 127.0.0.1:0`
  ถ้าฟังไม่ได้ token เดินทางทาง stdin ไม่เคยเป็น argv (จอเขียนแล้วถือ stdin ไว้ EOF = จอตาย
  เครื่องยนต์ออกตาม) generator ออก client/server จากรายการ method เดิม —
  `*rpc.Client` เป็น `engine.API` ข้าม socket และเทิร์นเต็มวิ่งผ่านมันได้
- **คีย์อยู่ที่จอ ข้อ 3 ของ §248 เป็นจริงบนสาย** — `internal/credentials` เป็นเจ้าของ
  `credentials.json` คนเดียว `internal/engine` ห้าม import credentials/oauth (deps_test บังคับ)
  คำขอถึงผู้ให้บริการเดินทางไปให้จอเซ็นแล้วสตรีมกลับเป็นชิ้น ≤32 KiB เครื่องยนต์เห็นแค่
  status/header/body ยกเลิกถึงผู้ให้บริการภายในไม่ถึงวินาที 401 ได้ต่ออายุโทเค็นหนึ่งครั้ง
  ก่อนบอกให้ล็อกอินใหม่ (ChatGPT ตอบ `token_expired` ทั้งที่ claim เหลืออีกสัปดาห์)
- **เครื่องมือของหน้าต่างข้ามสาย** — จอประกาศรูปทรงของ browser/computer ใน `hello`
  เครื่องยนต์ให้ยืม stub ที่รันกลับบนจอ (`screen.tool`) registry/stance/permission มองไม่ต่าง
  จากตัวจริง ไม่มีจอ = รายงานสภาพเครื่องแทนการค้างเทิร์น ไฟล์ของโปรเจกต์เสิร์ฟจาก
  เครื่องยนต์ที่ `/file/` หลัง token จอ reverse-proxy ทับ (Range ผ่านทั้งสองชั้น วิดีโอเล่น
  ก่อนโหลดครบ)
- **supervisor บนจอ** — สายหลุดแต่ process อยู่ → dial ใหม่ก่อน; process ตาย → เริ่มใหม่
  backoff 1/2/4 วิ; ล้มสามครั้งในหนึ่งนาที → failed แล้วรอปุ่มเริ่มใหม่ ระหว่างนั้น binding
  ทุกตัวรอสาย (≤30 วิ) แทนที่จะพัง — restart คือการหยุดชั่วคราว ไม่ใช่จอเต็ม error หลัง restart
  จอพาแชตบนจอกลับไปหาเครื่องยนต์ใหม่เอง (สร้าง context จาก transcript แบบเดียวกับ launch)
- **ตัวเลขของสาย** (measure_test.go): round trip ผ่าน loopback tcp mean 58 µs (p95 520 µs)
  ถึง process ลูกจริงผ่าน AF_UNIX mean 64 µs เทิร์นบน `aetox-render:test` +15 ms จาก 1.2 วิ
  (อยู่ใน noise) event ต่อเทิร์น 62 เฟรม 9.2 KB — เทียบ git spawn ~190 ms ที่แผนใช้เป็นหลัก
- **แพ็กเกจ** — `aetox-engine.exe` ติดตั้งข้าง `aetox.exe` ทั้ง installer/msix/portable zip
  ตัวอัปเดตในแอปสลับตามชื่อทั้งสองไฟล์ (zip รุ่นเก่าไม่แตะ engine) log แยกสามไฟล์:
  `desktop-<เวลา>.log` ของจอ `aetox-<เวลา>.log`/`engine.log` ของเครื่องยนต์ — สอง process
  ที่เริ่มในวินาทีเดียวกันเคยเปิดไฟล์เดียวกันด้วย `O_TRUNC`
- **`AETOX_ENGINE_ADDR`** ต่อกับเครื่องยนต์ที่คนอื่นเปิดไว้ (ทางเดินด้วยมือถึง host ก่อนเฟส 3
  และยังอยู่สำหรับ host ที่หน้าตั้งค่าอธิบายไม่ได้)

**ตั้งใจไม่ทำ** CLI ยังเป็นจอกับเครื่องยนต์ใน process เดียวและส่งคีย์ตรง (จะเป็นจอที่สอง
ในเฟสหลัง) · ค่าเสียงที่เลือกยังเป็นของเครื่องยนต์ใน `model-preference.json` จนกว่า
`screen-preferences.json` ในเฟส 5 · ไม่มี `kind turn_busy` — client รอสายตอน restart แทน

## เครื่องยนต์บนเครื่องอื่นผ่าน ssh (§248 เฟส 3)

**เรื่องเดิม** ถาม "ssh ไป coding บน host อื่นได้ไหม" คำตอบคือไม่มี — ทุกเครื่องมือผูกกับดิสก์
ของเครื่องที่หน้าต่างรัน และการสอนทุกเครื่องมือให้ข้ามเครือข่ายคือทางที่เจ้าของปฏิเสธ (เลือกระดับ 3
แบบ VS Code Remote-SSH: ยกเครื่องยนต์ไปรันที่นั่น)

**รุ่นนี้** ตั้งค่า › **เครื่องระยะไกล** — เพิ่มเครื่องด้วยชื่อ `ssh` แล้วกดเชื่อมต่อ

- **จอทำให้ทั้งเส้น** (`internal/engine/remote`): Probe (uname, มีเวอร์ชันนี้ไหม, รันอยู่ไหม)
  → Install (ส่งไบนารีทาง stdin ไม่พึ่ง scp) → Start (token ลง `~/.aetox/server/token` 0600,
  nohup, `--tcp 127.0.0.1:0`, `--idle-exit 30m`) → Tunnel (`ssh -N -L`) ทุกขั้นเป็นข้อความไทย
  บน chip ใช้ `ssh` ของระบบ จึงได้ `~/.ssh/config`, agent, jump host ฟรี BatchMode=yes
  (ไม่มี terminal ให้ถาม — เข้าด้วยกุญแจ) accept-new, ConnectTimeout 15, ServerAlive 15×3
  สคริปต์ทุกตัวเป็น `sh -c` (login shell เป็น fish/csh ก็ไม่แตะ) และขึ้นต้น `: aetox-<step>`
  ให้ `ps` บน host อ่านออก
- **ไบนารี Linux ของรุ่นนี้** โหลดจาก release ตาม tag ตรวจ `checksums.txt` + `.sig` ด้วยกุญแจ
  release ก่อน sha256 ทีหลัง แคชใต้ `updates/engine/<ver>/` release.yml สร้าง
  `aetox-engine-linux-{amd64,arm64}` (static) และ CI รัน smoke โดยใช้ runner Linux เป็น host
  ของตัวเอง
- **สลับแล้วดูแลเอง** — retarget ไม่นับเป็น restart ไม่ backoff; อุโมงค์ขาด → reconnecting
  แล้ว dial ใหม่ (probe เจอเครื่องยนต์เดิม เปิดอุโมงค์อย่างเดียว); เปิดครั้งหน้าไปที่ host
  ที่ค้างไว้; ป้ายชื่อ host บนแถบบน กดแล้วไปหน้าตั้งค่า; picker เปิดโฟลเดอร์บน host
  (dialog ของจอเปิดดิสก์เครื่องนี้)
- **หน้าเป็นการ์ดต่อเครื่อง** — แถวแรกคือเครื่องนี้ (ชื่อ, Windows 11 (build), CPU, RAM, arch)
  แต่ละ host มีบรรทัดสเป็คที่เครื่องยนต์ของมันบอก (`internal/machine` — RtlGetVersion +
  GlobalMemoryStatusEx บน Windows, `/etc/os-release` + `/proc/cpuinfo` + `/proc/meminfo` บน
  Linux) ฟอร์มเพิ่ม/แก้ไขเป็นป็อปอัป "เวลาเครื่องเยอะ" ไม่ต้องเลื่อนไปท้ายรายการ
- **host จริงตัวแรก** WSL Ubuntu 26.04 ผ่าน `ssh wsl`: smoke 7.3 วิ แอปเชื่อมต่อ 1.2 วิ
  หน้าต่างโหลดใหม่บน `/home/mikedev` สิ่งที่มันสอน (อยู่ในหมายเหตุหน้าตั้งค่า): `localhost`
  ของ Windows แปลงเป็น `::1` แต่ WSL forward แค่ IPv4 จึงต้องใช้ `127.0.0.1`; `ssh-keygen -N ""`
  จาก PowerShell ได้กุญแจที่มี passphrase สองตัวอักษร BatchMode จึงล้มเงียบ
- **สี่อย่างที่ host จริงพบแล้วแก้** — หน้าต่างดำหลังสลับ (WindowReloadApp ของ Wails บน
  Windows คือเดินไป start URL → เปลี่ยนเป็น `location.reload()`); การ์ดสถานะรับหนึ่งเหตุการณ์
  ต่อ**ประโยค** ไม่ใช่ต่อ 32 KiB (การส่งไบนารี 32 MB หนึ่งครั้งเคยได้ 1,018 เหตุการณ์และบรรทัด
  log); `ssh` ที่เงียบตอนล้มได้ประโยคแทน `exit status 255` (Windows OpenSSH บอก connection
  refused ที่ระดับ INFO จึงเลิกบังคับ LogLevel=ERROR); `sleep` เศษวินาทีมี fallback เป็น 1 วิ
  บน host ที่รับแต่จำนวนเต็ม
- **คีย์ขี่ไปได้เฉพาะที่จอรู้ว่า provider อยู่** — host ที่ถูกยึด (หรือถูกปลอมตอนติดต่อครั้งแรก
  ใต้ accept-new) เคยขอให้จอเซ็นคำขอไป `evil.example` แล้วได้คีย์ติดไปด้วยได้ ตอนนี้เมื่อ
  target เป็น remote จอเซ็นเฉพาะ endpoint ของ catalog, ของ sign-in, ของ custom row ที่จอจดไว้เอง
  และ loopback ที่อื่นส่งออกไปเปล่า ๆ ให้ล้มที่ปลายทาง (เทสต์ 9 กรณี + บนสายจริง)

**สิ่งที่ต้องรู้** การตั้งค่า สิทธิ์ ความจำ MCP และคีย์ GitHub เป็นของ host ส่วนคีย์โมเดล
ไม่ถูกส่ง · base URL ที่ตั้งบน host สำหรับ provider ใน catalog ไม่ถูกเซ็นจากที่นี่ ·
HTTP ของ provider ออกจากเครื่องจอเสมอ · WSL ดับเองเมื่อไม่มี session `wsl.exe` เปิดอยู่

**ตั้งใจไม่ทำ** (บันทึกใน design doc §10) spike streamlocal · Setpgid ลูก Linux · dialog อื่น
นอกจากเปิดโปรเจกต์ยังเปิดดิสก์เครื่องนี้ตอน remote (เฟส 4 — งานถัดไป) · `--idle-exit`
ตายตัว 30 นาที · กฎ 3 ครั้ง/นาที นับอุโมงค์ขาดด้วย

## ผู้ช่วยมีตัวตน — มาสคอต อวตาร และหุ่นบนเดสก์ท็อป (§254)

**เรื่องเดิม** หน้าคนการ์ตูน (agentFace) กับหน้าแชทว่างที่ไม่มีใครอยู่ ผู้ช่วยไม่มีหน้า
ไม่มีเสียง และเอเจนแต่ละคนวาดด้วยอีกระบบที่ส่งบุคลิกข้ามกันไม่ได้

**รุ่นนี้** หุ่นยนต์ตัวเดียวของทั้งบริษัท (`lib/mascot/`, มาตรฐานอยู่ที่ `docs/MASCOT.md`)

- **วาดจากโค้ดล้วน** ไม่มีภาพ ไม่มีอัปโหลด — สี่แกนที่ไม่แตะกัน: ตัวตน (hue · shell · top ·
  badge · face · prop · role), ท่า (ตาราง POSE 21 ท่าในวันแรก ต่อด้วย error, cheer, wink,
  wake, startled), หัน (`--t` ตัวแปร CSS เดียว ทุกชิ้นบนหัวประกาศมุม φ แล้ว CSS คำนวณ sin/cos
  เอง ไม่มี JS ต่อเฟรม), ขนาด (LOD สามระดับ) กฎที่เจ้าของตั้งล็อกไว้ในเทสต์: แขนข้อเดียว
  ยาวคงที่ มือไม่สูงกว่าเส้นหู badge หู = ไอคอนจริง filter เฉพาะตัว ≥ 96px
- **ทุกท่ามีสัญญาณจริง** — ไมค์ → listening, เสียงอ่าน → answering, เครื่องมือทุกตระกูล
  (รวมจาก MCP) → ท่าตามตระกูล, เครื่องมือล้ม → debugging, ถูกลาก → walk, เทิร์นล้ม → error,
  เงียบ 5 นาที → นอนบนหมอน (ถูกจิ้มค่อย ๆ ลุก มีข้อความเข้าสะดุ้งตื่น) เปลี่ยนท่าแบบ crossfade
  แขนแกว่งไปเอง ลูปหายใจต่อจากเฟรมเดิมไม่กระตุกกลับศูนย์
- **ตัวลอยบนจอ** ลากไปวางตรงไหนก็ได้ จำตำแหน่ง พูดเฉพาะตอนรายงาน (บรรทัดแรกของท่อน
  ตัดที่ 96 ตัวอักษร) ระหว่างเครื่องมือรันมีแต่ไอคอน ทักคุณด้วยชื่อตอนแชทว่างขึ้นจอ
  ("mike วันนี้มีอะไรให้ช่วยไหม?" โบกมือ 4 วิ แล้วเงียบ — ข้อยกเว้นเดียวของกฎ "บับเบิลไม่ใช่
  คำโปรยของเรา") สวิตช์ในเมนูบัญชี กรอบ+ปุ่มซ่อนเมื่อเอาเมาส์เข้าใกล้ คลิกแล้วมีท่าตอบ
  เดินไปทางที่ถูกลาก (ซ้าย ขวา หันหลัง หันมา) ถึงขอบจอไม่ติด เลี้ยวทางสั้นเสมอ
- **พูดได้** — เครื่องเล่นเสียงตัวเดียวของหน้าต่าง (`lib/speech.svelte.ts`) อ่านคำตอบที่จบแล้ว
  กับคำถามที่ติดอยู่ด้วย TTS ของเครื่อง ไม่อ่าน narration ระหว่างเครื่องมือ หยุดเมื่อคุณเป็น
  ฝ่ายพูด (ส่งข้อความ ไมค์เปิด สลับแชท คลิกตัวมัน) เปิดเป็นค่าเริ่มต้น พูดไม่ได้ก็เงียบ
  และหน้าอวตารบอกเหตุผลพร้อมทางไป ตั้งค่า › เสียง คำทักมีสวิตช์ของตัวเองอีกชั้น
  เสียงก้องตอนเปิดแอป (สองรอบ key เดียวกันทับกัน) แก้ด้วยเลขรุ่นต่อรอบอ่าน

### หุ่นบนเดสก์ท็อป — หน้าต่าง Win32 ไม่มี WebView2

**เรื่องเดิม** เจ้าของ: "อยากให้อวตารมันออกไปโลดแล่นบนจอส่วนอื่นได้ เหมือน Codex" ทางที่
ชัดที่สุดคือ WebView2 ตัวที่สอง ซึ่งคือเบราว์เซอร์อีกตัวเพื่อวาดตัวเดียว

**รุ่นนี้** ตั้งค่า › อวตาร › **ที่อยู่ของผู้ช่วย**: ในแอป / ทั่วเดสก์ท็อป (เป็นตัวเลือก ไม่แทนที่
พร้อมคำอธิบายว่ากินทรัพยากรไม่เท่ากัน) สมองเดียวขับทั้งสองร่าง

- **layered window บนเธรดของตัวเอง** วาดด้วย `UpdateLayeredWindow` จากผืน RGBA ใน Go —
  โปร่งใสต่อพิกเซล คลิกทะลุตรงที่โปร่งใสโดย Windows เอง ไม่แย่งโฟกัส ไม่มีปุ่ม taskbar
  อยู่บนสุด แรม +0.8 MB ซ่อนตอนแอปเต็มจอ
- **อบเฟรมจาก rig เดียวกัน** — `bake.ts` เมานต์ markup ของ Mascot จริงนอกจอ เลื่อนทุก
  แอนิเมชันไปยังจังหวะที่ต้องการด้วย Web Animations API แล้วถ่ายค่า computed ลง SVG สำเนา
  → PNG ตามสเกลจอ (ทุกท่า × 4 จังหวะ + เดิน 12 ทิศ × 8 จังหวะ + ไอคอนกรอบ) วัดจริง @175%:
  16 ms/เฟรม ~33 KB/ไฟล์ hash ชุด = FNV ของ mascot.css + markup จึงตกไปเองเมื่อ rig เปลี่ยน
  เก็บที่ `<DataRoot>/companion/<hash>/`
- **ข้อความไทยผ่าน GDI** บนบิตแมปทึบแล้วบังคับ alpha 255 (ClearType กับ layered window)
  บับเบิลโตตามขนาดตัว (ตัวอักษร 11–24px กว้างสุด 380) ตัดคำไทยด้วย `Intl.Segmenter`
- **จังหวะเฟรม = จอที่หุ่นอยู่** — โพสต์ข้อความขอเฟรมเองทำให้เมาส์ไม่เคยถูกอ่าน ("เลื่อนไม่ได้
  ติด ๆ") → WM_TIMER 1ms (มาเมื่อคิวว่างจากอินพุตแล้ว) + รอ vblank ของจอใต้ตัวหุ่นผ่าน
  `D3DKMTWaitForVerticalBlankEvent` (DwmFlush รอจอหลัก 60 Hz — ร่างบนจอ 144 ได้แค่ 60)
  วัดจากมือเจ้าของบนจอ 60 Hz: interval mean 16.8 p95 17.4–17.8 ms gap 0–2 ต่อ 100 เฟรม
  (ก่อนหน้า p95 20–28; ก่อนแก้แคช p95 30.7 max 46 ถอดรหัส PNG ~100 ครั้ง/ลาก) ข้ามจอไม่ใช่
  การโหลดใหม่ — เก็บชุดเฟรมทุกสเกลไว้ ยืมสเกลอื่นระหว่างอบ
- **กรอบโผล่เมื่อเมาส์เข้าเขต** ไม่ต้องแตะตัว (Windows hit-test ด้วย alpha → ระบายพื้นกรอบ
  ด้วย alpha 1/255) ปรับขนาดด้วยมุมขวาล่าง เปิดที่ขนาดที่จำไว้ไม่กระโดด เคอร์เซอร์รูปมือ
  (class ที่ไม่มี cursor ทำให้ Windows โชว์วงหมุนตลอด) บั๊กในร่าง recover ไม่พาแอปไปด้วย
  (ร่างเปิดก่อนมีชุดเฟรมเคยล้มทั้งแอป) แท็บเบราว์เซอร์เลิกไปเป็นลูกของหุ่นตอนย้ายจอ

**ถอนออก** crossfade แบบ snapshot+easing (25132d83) — เจ้าของ: "เหมือนเฟรมหลุดเลย เอาเหมือน
เมื่อกี้ก็ได้" กลับไป crossfade เดิม · **ตั้งใจไม่ทำ** WebView2 ตัวที่สอง และ HTTP feed
ที่สร้างไว้รอมัน (ถอดออกแล้ว) — เจ้าของรับข้อจำกัดของภาพอบ (เดิน 8 จังหวะ หัน 30°:
"Codex ก็ประมาณนี้")

## ทีมเอเจน ซับเอเจนปรับได้ และผู้ให้บริการต่อเอเจน (§255, §256)

**เรื่องเดิม** ทีมผู้ช่วยคือ "ทุกคนที่ไม่มีทีม" ซึ่งคำนวณเอา แก้ไม่ได้ ลบไม่ได้ สวิตช์มอบงาน
ตัวเดียวคุมสองฝั่ง ตั้งค่ามีทั้งหน้า เอเจน และหน้าทีมซึ่งเจ้าของสับสน ซับเอเจนปิดตายตั้งแต่
6 ส.ค. และเอเจนเลือกได้แค่โมเดล ไม่ใช่ผู้ให้บริการ

**รุ่นนี้**

- **ทีมคือรายชื่อเอเจนที่ผูกโต๊ะเดียว** — `<DataRoot>/teams/<ชื่อ>/TEAM.md` (desk, description,
  members) เอเจนอยู่ `agents/<ชื่อ>/` ตัวเดียว ความจำเดียว และอยู่ได้หลายทีม
  `sessions.team` (db v25) เป็นพิกัดที่สามของเซสชัน — แชทจ้างจากทีมเดียวตลอดอายุ
  โต๊ะโค้ดจ้างทีมของตัวเองได้ ทีมหายแล้วเปิดเซสชันเดิม = ปฏิเสธพร้อมชื่อ ไม่หายเงียบ
- **ทีมเริ่มต้นเป็นไฟล์ที่แอปตั้งให้** ชื่อ **ผู้ช่วยในคอมพิวเตอร์** (deepresearch · doc ·
  sheet · video) เขียนครั้งแรกที่โฟลเดอร์ teams ยังไม่มี แล้วเป็นทีมธรรมดา — เปลี่ยนชื่อ ตัดคน
  ลบทิ้งได้ ลบแล้วไม่โผล่กลับ automation · editor · github และเอเจนของผู้ใช้ไม่อยู่ทีมไหน
  จนกว่าจะติ๊กเข้า (ชื่อเดิม "ทีมเอเจน" อยู่หนึ่งวัน — migration 26 เปลี่ยนชื่อโฟลเดอร์และ
  แถวให้ครั้งเดียว)
- **"ไม่ใช้ทีมช่วย" เป็นตัวเลือกจริง** — ไม่มีทีมก็คือทีมหนึ่ง แชทที่เลือกแบบนั้นเปิดกลับมาก็
  ยังไม่มีทีม (การอัปเกรดแถวยุคก่อนมีทีมย้ายจาก LoadSession ไปเป็น migration 27 ทำครั้งเดียว
  ตอนเปิดแอป เพราะ team ว่างเคยมีสองความหมาย)
- **สวิตช์มอบงานเป็นของประตู ประตูละตัว** — ผู้ช่วย (เดิม) กับโค้ด (ใหม่ เริ่มเปิด)
  ไม่มีสวิตช์รวมต่อทีมอีก รายชื่อที่ปิดยังเป็นของทีม
- **ตั้งค่า › ทีมเอเจน** — ข้างบนเป็นสวิตช์เลือก **ฝั่งผู้ช่วย / ฝั่งโค้ด** (ไม่ใช่เปิดปิด)
  ทีมอยู่แถบซ้าย ทีมที่เลือกอยู่ขวา แต่ละฝั่งมีประตู "สร้างทีมฝั่งนี้" ฟอร์มไม่ถามโต๊ะซ้ำ
  รายชื่อสมาชิกลงท้ายด้วยชิป "+ เอเจน" ที่พาไปสร้างแล้วกลับมาพร้อมร่างเดิมและติ๊กให้
  หน้าเอเจนเฉพาะทางกลับเป็นห้องที่เดินเข้าไปคุย ไม่มีสวิตช์ **ตั้งค่า › เอเจน ถอดออกจาก nav**
  (เหลือ editor ที่เข้าจากเฟืองบนการ์ด) — "หนึ่งสิ่งหนึ่งบ้าน" ทั้งหน้าพูดว่า "ฝั่ง" ไม่พูดว่า "โต๊ะ"
- **ชิปท้ายช่องพิมพ์แยกเป็นสอง** (`StationPick`) — ใครตอบ (ผู้ช่วยหลัก หรือหน้าหุ่น+ชื่อเอเจน)
  กับ จ้างจากทีมไหน (ชื่อทีม หรือ "ยังไม่มีทีมช่วย") แต่ละเมนูมีของชนิดเดียว ไอคอนผู้ช่วยหลัก
  เป็นของประตูนั้น (ประกายฝั่งผู้ช่วย ไอคอนโค้ดหน้าโค้ด) "จัดการทีม" พาไปฝั่งของหน้าที่กดมา
  เมนูปิดเมื่อกดข้างนอกหรือ Escape
- **ช่องบทบาทตอนเพิ่มเอเจนมีสามทางเข้า** — เปิดไฟล์ .md/.txt · วางลิงก์แล้วดึง (หน้าไฟล์
  GitHub → raw, gist, Google Drive share → download, Google Docs → export txt; UTF-8 ไม่เกิน
  512 KB; หน้า sign-in ถูกปฏิเสธพร้อมบอกว่าให้วางอะไร) · เทมเพลต 4 แบบ ข้อความแนะนำเดิม
  เคยเป็น "ค่า" ของช่องและกดบันทึกได้ เอเจนที่สร้างเร็ว ๆ จึงได้ "มันไม่เห็นประวัติแชท คืนแค่
  ผลลัพธ์" เป็นบทบาทและทำตัวแบบนั้นจริง (ต้นเรื่องของ §256) — ตอนนี้เป็น placeholder
- **ซับเอเจนปรับได้จำกัด** — ไฟล์ชื่อเดียวกับตัวที่มากับแอปเป็นเงาของมัน: model/provider,
  prompt, description, steps, อวตาร มีผล ส่วน tools/deny/needs/desk ยึดของแอปเสมอ ไฟล์ที่พยายาม
  ได้ Notice บนการ์ด ชื่อใหม่ยังเป็นซับเอเจนไม่ได้ (Save ปฏิเสธที่ประตูพร้อมชี้ไปหน้าทีม)
  ลบเงา = คืนค่า ตั้งค่า › ซับเอเจน มีเฟืองแต่ไม่มีปุ่มสร้าง
- **`provider:` ใน AGENT.md** — โปรไฟล์ที่ระบุ provider คิดที่นั่น บนโมเดลที่ระบุหรือโมเดล
  เริ่มต้นของ provider นั้น ผ่าน client แบบเดียวกับที่แชทใช้ (เซ็นด้วย transport ไม่ถือคีย์)
  สร้างไม่ได้ = tool call ล้มพร้อมชื่อ provider ไม่แอบวิ่งบน provider ของ session
  ช่องผู้ให้บริการอิงแถวเดียวกับหน้าตั้งค่าโมเดล (antigravity ที่หลุดแคตตาล็อกเคยโผล่)
- **ชื่อในฟุตเตอร์ถูกอ่านจริง** — ห้องแชทว่างทักด้วยชื่อตามโต๊ะ (ผู้ช่วย: วันนี้มีอะไรให้ช่วยไหม ·
  โค้ด: วันนี้จะพัฒนาส่วนไหนดี) โมเดลรู้ชื่อผู้ใช้ผ่าน `prompt.person` เมนูเปิดเป็นข้อความ
  ไม่ใช่ช่องพิมพ์ และเซฟทุกตัวอักษรที่พิมพ์

## ปุ่ม `+` ประตูเดียว และหน้าต่างที่พับแทนที่จะไม่ยอม (§257)

**เรื่องเดิม** สามปุ่มเป็นของอย่างเดียวครึ่ง: `+` แนบไฟล์, `/` ชุดคำสั่ง, Ctrl+K เปิดชุดคำสั่งซ้ำ
แล้วต่อด้วยแถวที่ซ้ำกับชิปโมเดลข้าง ๆ ("ปุ่มนี้มันทำงานซ้ำซ้อน … Ctrl+K มันพัง") และหน้าต่าง
ลากให้เล็กกว่า 1100×700 ไม่ได้ ("เหมือนโดนล็อค ห่อให้ถึงครึ่งนึงก็ไม่ได้")

**รุ่นนี้** `Palette.svelte` เป็นเมนู `+` สี่กลุ่มค้นข้ามกันได้ — แนบไฟล์ · ชุดคำสั่ง `/` ·
เรียกเอเจน `@` · แท็บที่เปิดอยู่ พิมพ์ `/` หรือ `@` เปิดเมนูแบบกรองกลุ่ม Ctrl+K เปิด `+`
ปุ่ม `/` หายไป ชิปโมเดลไม่แตะตามที่ตกลง แถวไม่ห่อ ฝั่งซ้ายพับ (< 560 ป้าย ลงมือ หลบ, < 420
ไมค์ย้ายเข้าเมนู) เมนูสูงเท่าที่ว่างจริงเหนือปุ่ม (วัด ไม่เดา vh) ปุ่มส่งเต็มสี accent เมื่อมี
ของจะส่ง หน้าต่างพื้น 720×540 แล้วให้ `foldPanels` ตัดสินจากพื้นของแผง — ไซด์บาร์หลบก่อน
inspector หลบตาม การพับไม่แตะสวิตช์ที่ผู้ใช้เก็บไว้ ขยายกลับก็คืนเอง

## ห้องความสามารถถือของชนิดเดียว: MCP (§253, §258)

**เรื่องเดิม** ห้องเดิมถือสามชนิดของ สองแถบแท็บ วาดด้วยแถวของทะเบียน และเซิร์ฟเวอร์ MCP
แก้ได้สามที่ (ห้อง, หน้าตั้งค่า MCP, แท็บใน ตั้งค่า › เอเจน)

**รุ่นนี้** `Capability.svelte` วาดใหม่ตามกรอบของทีมงาน — ถือของชนิดเดียวคือเซิร์ฟเวอร์ MCP
ของคุณเป็นแดชบอร์ดอ่านอย่างเดียว แผ่นแก้ไขเดียวมีสามแท็บ ใครได้ใช้ / การเชื่อมต่อ / เครื่องมือ
(ติ๊ก allowlist จาก `ToolList` ที่เซิร์ฟเวอร์รายงานหลังเชื่อมต่อ พร้อมราคาโทเค็นต่อข้อความ)
หน้า MCP ในตั้งค่าถอดออก (`Settings.svelte` เบาลง 1,000 บรรทัด) ห้องสมุดแยกกลุ่มตามสิ่งที่
เซิร์ฟเวอร์เข้าถึงและซ่อนรายการที่ยังไม่ได้พิสูจน์ preset sign-in ใหม่: Runway ML, DeepL, Mapbox
(Stripe, Sentry, Figma, Atlassian, Vercel ออกจาก candidate หลังมี preset) ค้นพบ OAuth ทนรูปแบบ

## ห้อง Git ห้องไทมไลน์ และรายงานท้ายแผน (§249–§252)

- **ห้อง Git อ่านไม่ทันไม่ใช่ต้นไม้สะอาด** — เจ้าของส่งภาพค้าง "กำลังอ่านไฟล์ที่แก้..." ทั้งที่
  หัวบอก 58 ไฟล์ หนึ่งรอบอ่านเดิม = git 3 โปรเซส + อ่านไฟล์ untracked ทั้งไฟล์ (รวม PNG)
  ทุก 2 วิ และเกินงบ 10 วิ = "ว่าง" ตอนนี้ 2 โปรเซส (`--show-prefix` จำต่อ root; วัดจริง
  rev-parse 175 / status 264 / numstat 342 ms) ไบนารีนับ 0 หลังอ่าน 8 KB แรก git ตอบไม่ทัน =
  แผงเก็บต้นไม้เดิมและบอกบนหน้า โพลรอ 4 เท่าของเวลาที่อ่านครั้งก่อน (2–15 วิ) และ index กับ
  ดิสก์ที่เห็นไฟล์เดียวกันคนละอย่างรวมเป็นหนึ่งแถว (Svelte ไม่ยอมวาดคีย์ซ้ำ)
- **ห้องไทมไลน์** — แท็บ gitlog ในโต๊ะโค้ด แถวละหนึ่งคอมมิต จัดกลุ่มตามวัน หน้าละ 50 จาก git
  โปรเซสเดียว แบ่งหน้าด้วย hash ไฟล์ดึงตอนกางแถว diff ดึงตอนกางไฟล์ (`cat-file --batch`)
  ไม่มี timer ค้นหาและชิป feat/fix/refactor/docs/test กรองในเครื่อง
- **Smart Split สตรีมข้อความลงแต่ละกลุ่ม** — คืนกลุ่มไฟล์ก่อน แล้วเขียนข้อความทีละกลุ่ม
  ยกเลิกรอบเก่าได้ ปุ่มหยุด/แยกใหม่ fallback แก้ได้พร้อมแสดงสาเหตุ
- **ไฟล์แนบของแชทเป็นของแอป** — `.aetox-attachments/` สี่แถวโผล่ในห้อง Git และ "แยกงานด้วย AI"
  ติ๊กให้ จึงมีภาพ 13 ไฟล์คอมมิตติดไปแล้ว ตอนนี้ ignore ที่ root เอาออกจาก git และเป็นหมวด 'app'
  (ไม่ติ๊ก AI ไม่เห็น ไม่ขึ้นแบนเนอร์อันตราย)
- **รันจบด้วยรายงาน** — `plan report` (What was done / How it was checked / What is left) เขียน
  `plan_reports` (db v24) หนึ่งแถวต่อรอบ ตัวเลขบนแถวคัดจากแผนกับรัน ไม่ใช่คำของโมเดล ด่านที่สาม
  ของ มุ่งเป้า: รันไม่จบจนกว่ารอบนี้จะมีรายงาน พาเนลชิ้นงานเหลือห้ากลุ่มจากสองแหล่ง (แผน/รายงาน
  จากฐานข้อมูล เอกสาร/สไลด์/หน้าเว็บ จากธง) ไม่กวาดโฟลเดอร์ — ธง Artifacts หมายถึง "ยื่นให้"
  เท่านั้น สกรีนช็อตเลิกติดธง
- **คำถามของเอเจนต์เอื้อมออกนอกหน้าต่าง** — สถานะที่สาม "รอคุณตอบ" บนแถวเซสชันและแถบบน
  FlashWindowEx ให้ปุ่มบนแถบงานกระพริบเมื่อไม่ได้โฟกัส เสียงสองโน้ตจาก WebAudio (สวิตช์ในตั้งค่า
  ส่งมาเปิด) และ `applyAskUser` ไม่ทิ้ง event ของแชตที่หน้าต่างไม่รู้จัก
- **วางแผน พรอมต์กลับไปสั้นเท่า 29 ส.ค.** — ระหว่าง 9–10 ก.ย. ทิศทางโตจากห้าย่อหน้าเป็น ~500 คำ
  ("ก่อนหน้านี้มันทำได้ดี แต่ตอนนี้ปรับกันไปเยอะ") วิธีสัมภาษณ์ย้ายไป `aetox-grill` ที่มี `before:`
- **หน้าโปรเจกต์ใหม่** — พิมพ์ประโยคแรกได้เลย การ์ดเริ่มต้นใส่ในช่องพิมพ์ไม่ส่งเอง แถวแชท
  สองบรรทัด แผงไฟล์ตามโปรเจกต์ไป ("ดูเฉย ๆ ไม่ย้ายเข้า") ลากไฟล์จาก Explorer มาวางได้
  และแอปเปิดที่โปรเจกต์ที่จดจำไว้ตอนสตาร์ท
- **สลับโต๊ะไปมาเร็ว ๆ แล้วหน้าตากับ session คนละโต๊ะ** — การเดินผ่านประตูเข้าคิวทีละคน
  เอาคำสั่งล่าสุดอันเดียว ประตูบอกว่ากำลังเดินไปไหน (บนเครื่องที่ git ช้า ปุ่มเคยดูเหมือนตาย)
  และชั้น git ในพรอมต์แคช 15 วิ

## ผู้ให้บริการ

- **500 ของเขาไม่ใช่เงินของเรา** (§243) — `opencode request failed with status 500` เคยถูกเติมด้วย
  "ไม่มีเงิน" ตรวจแล้ว GET /models ตอบ 200 พังเฉพาะเส้น inference ตอนนี้ `providerDownStatus`
  (500/502/503/504/529) เป็นลิสต์เดียวที่แปลว่าฝั่งเขาล่ม ตัวที่ตัดสินลองซ้ำกับตัวที่เรียกชื่อ
  ไม่หลุดจากกัน lmstudio/llama-server ได้ประโยคของตัวเอง (ตรงนั้น 5xx คือโปรเซสที่กำลังตาย)
- **ปลายทาง OpenAI-compatible เพิ่มได้เป็นรายการ** (§245) — แต่ละอันเป็นแถว provider ใต้ชื่อ
  ที่ตั้งเอง จำคีย์/URL/โมเดลของตัวเอง โผล่ในตัวเลือกโมเดลเหมือน provider อื่น
- **TokenRefresh** เมื่อ 401 ทั้งฝั่งแอปและ CLI
- **ร่างดีไซน์ combo fallback provider** (`docs/architecture/combo-fallback-provider-2026-09-13.md`)
  สำหรับรุ่นถัดไป — สลับ provider ข้ามบัญชีอัตโนมัติเมื่อโควต้าหมดกลางเซสชัน ยังไม่สร้าง

  เปิดใหม่ทีหลังก็ได้" ซึ่งจริงเฉพาะ portable ตอนนี้ Stage เขียน `staged.json` + checksums + sig

  ถูกยกเลิกอยู่ตรงนี้) ลง `update-restart.log` แล้วแปลงเป็นประโยคบนการ์ด download มี stall
  guard 60 วิ (ไม่ใช่ total timeout) checksums/sig เพดาน 30 วิ

  เฟรม 16–32 ใส่แค่ขอบไม่ใส่เงา (ที่ขนาดนั้นเงาเป็นคราบมัว)
- **PNG ของ Store ที่ขนาดตรงกับเฟรมใน .ico เป็นไบต์เดียวกันจริง** — `make-logos.ps1` เคย blit

  ออกมาตรง ๆ
