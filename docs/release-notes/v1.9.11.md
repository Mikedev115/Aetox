# 🧩 Aetox v1.9.11

รุ่นนี้ทำให้เอเจนต์เปิดงานและตามผลลัพธ์ได้ต่อเนื่องขึ้น: เปิดไฟล์ที่เกี่ยวข้องจากคำตอบและผลค้นหาได้
ส่งภาพหรือ PDF ให้โมเดลใหม่ที่ยังไม่มีข้อมูลยืนยันอย่างระวัง และบอกตรง ๆ เมื่อผู้ให้บริการไม่รับ

## เปิดไฟล์จากคำตอบและผลค้นหาได้ทันที

- พาธไฟล์ที่เครื่องมือเขียน **หรือค้นพบ** กลายเป็นลิงก์ในคำตอบ รวมถึงระหว่างที่คำตอบกำลังสตรีม
  เปิดในแท็บไฟล์ได้โดยไม่ต้องคัดลอกไปหาเอง
- ลิงก์ผลค้นหาถูกเก็บกับประวัติเทิร์น จึงยังเปิดได้เมื่อกลับมาอ่านแชตเดิม
- การพิมพ์พาธที่เป็นข้อความตัวอย่างหรืออยู่ในบล็อกโค้ดยังไม่ถูกเปลี่ยนเป็นลิงก์ และชื่อไฟล์ที่มีข้อมูลไม่ปลอดภัยไม่ถูกนำไปรันเป็นโค้ด

## ภาพและ PDF ไม่ถูกกันไว้เพราะชื่อโมเดลเดาไม่ออก

**เดิม** โมเดลที่รายการความสามารถยังไม่ระบุอาจถูกกันภาพหรือ PDF ไว้ก่อน แม้ช่องทางจะส่งไฟล์ชนิดนั้นได้

**รุ่นนี้** เมื่อช่องทางรองรับ แต่ยังไม่มีข้อมูลยืนยันรายโมเดล Aetox จะลองส่งภาพหรือ PDF พร้อมคำกำกับให้โมเดลบอกตรง ๆ หากมองไม่เห็นหรืออ่านไฟล์ไม่ได้ แทนการตอบจากชื่อไฟล์หรือการเดา

- ถ้าผู้ให้บริการปฏิเสธภาพหรือ PDF ที่ส่งแบบลอง ระบบเอาสิ่งที่ถูกปฏิเสธออกแล้วลองคำขออีกครั้งหนึ่ง
  โดยเหลือข้อความบอกว่าโมเดลไม่ได้รับไฟล์ และใช้ทางอ่านไฟล์/OCR ที่มีแทน
- ข้อมูลความสามารถจากปลายทางและ catalog ยังชนะชื่อโมเดลเสมอ: สิ่งที่ระบุชัดว่าไม่รองรับจะไม่ถูกส่ง
- ภาพจากการอ่านไฟล์ จับหน้าจอ ตรวจหน้าเว็บ และไฟล์แนบ ใช้กติกาเดียวกัน; ตัวแทนย่อยตัดสินจากโมเดลของตัวเอง ไม่ใช่โมเดลของแชตหลัก

## ทำงานกับตัวแทนย่อยเห็นบริบทที่ส่งเพิ่ม

เมื่อส่งข้อมูลเพิ่มให้ตัวแทนย่อยระหว่างทำงาน หน้างานแสดงเป็นข้อความจากผู้มอบงานในจุดที่ส่ง
ไม่ปะปนเป็นคำพูดของตัวแทนหรือของผู้ใช้ และมีป้ายสถานะว่า “ส่งข้อมูลเพิ่ม”

## งานในเบราว์เซอร์และไฟล์เสถียรขึ้น

- แท็บเบราว์เซอร์ที่ WebView2 สร้างไม่สำเร็จมีเส้นตายและรายงานว่าอยู่หลังแท็บใด แท็บที่ค้างจึงไม่ขวางแท็บอื่นทั้งแอป
- `page_check` และการบันทึกวิดีโอรายงานชื่อเบราว์เซอร์, exit code และข้อความท้ายจาก stderr เมื่อเบราว์เซอร์ปิดก่อนพร้อมใช้งาน แทนการรอจนหมดเวลาโดยไม่ทราบสาเหตุ
- เมื่อ ref ของหน้าเว็บหายเพราะหน้ารีโหลด Aetox อ่านหน้าปัจจุบันใหม่และแนบ ref ใหม่ให้ใช้ต่อ แยกจากกรณี element ถูกลบจริง
- เครื่องมือ Git ที่ได้รับโฟลเดอร์ซึ่งมีรีโปอยู่ชั้นล่างบอกพาธรีโปที่พบให้ส่งต่อได้ แทนการจบที่ข้อความว่าไม่ใช่รีโป

## สร้างภาพจากโต๊ะโค้ดและ editor

โต๊ะ coding และ editor ใช้ `image_make` ได้ พร้อมสกิล `aetox-design` สำหรับแปลงบรีฟเป็น prompt
โดยคงข้อความที่ผู้ใช้ระบุให้ใช้ตรงตัวและไม่รับประกันขนาดภาพที่ได้

## แก้ปัญหาที่พบระหว่างตรวจรุ่น

- ความคืบหน้าการสแกนคลังสื่อส่งเรียงกัน แม้ตรวจไฟล์ขนานอยู่ ป้องกันการเขียนสถานะชนกันและเปอร์เซ็นต์ย้อนกลับ
- ปิดแท็บ terminal แล้วจบ process ของ shell และลูกที่แท็บนั้นเปิด ก่อนรายงานว่าปิดแล้ว ไม่ทิ้งโฟลเดอร์ทำงานถูกล็อก
- ห้องตัดถามรายชื่อ encoder จาก ffmpeg ที่ใช้งานจริง รองรับตัวที่ติดตั้งเองซึ่งมี libx264 แทนการเดาว่าต้องเป็น libopenh264
- ตรวจและแก้การปิด HTTP response และ SQL rows พร้อมล้างโค้ดภายในที่ไม่มีผู้เรียก โดยไม่ปิดกฎ lint
- `powerpoint` ที่ v1.9.10 เพิ่มในหน้า MCP ตอนนี้เครื่องมือติดตั้งของโมเดลค้นเจอด้วย เดิมจอเห็นแต่ชั้นที่โมเดลค้นไม่มีแถวนี้
- หน้าผู้ให้บริการและแผงเฝ้าสตูดิโอใช้สีตัวอักษร เส้นขอบ และพื้นตอนชี้ตามธีม เดิมอ้างชื่อสีที่ไม่มีอยู่จริง
- ห้องออฟฟิศไม่ขึ้นข้อผิดพลาดทุกเฟรมเมื่อ WebView ให้พื้นวาด 2D ไม่ได้ ข้ามการวาดเฟรมนั้นไปแทน
