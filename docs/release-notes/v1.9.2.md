## หน้าเว็บ: เขียนแล้วตรวจเลย ไม่ต้องเสียรอบไปเปิดดู

**เดิม** สกิลดีไซน์บอกให้โมเดลเปิดหน้าตรวจเอง ในการวัด โมเดลเรียกตรวจตั้งแต่ 1 ถึง 13 ครั้งต่องาน
ทุกครั้งส่งบทสนทนาทั้งก้อนซ้ำ (งานหนึ่งใช้ 23 รอบ 867k input token) ส่วนโมเดลที่ไม่ตรวจเลย
ตัวอักษรจางกว่าเกณฑ์ทุกรอบ
**รุ่นนี้** การเขียนหรือแก้ไฟล์ `.html` โหลดหน้านั้นเองที่ 1280 และ 390 px ทั้งสว่างและมืด
และสิ่งที่ต้องแก้กลับมาในผลของคำสั่งเดียวกัน

- สิ่งที่ตรวจ: สคริปต์พัง ไฟล์โหลดไม่ขึ้น หน้ากว้างเกินจอมือถือ ตัวอักษรต่ำกว่า AA
  โหมดมืดที่พื้นยังสว่าง กล่องที่ตัดเนื้อหาทิ้ง ไม่มี viewport บนมือถือ
- **ใหม่: ตัวไทยที่เลย์เอาต์ทำพัง** ข้อความไทย ลาว เขมร พม่า อินดิก หรืออาหรับที่มี letter-spacing
  (สระกับวรรณยุกต์หลุดจากตัวพยัญชนะ) หรือ line-height ต่ำกว่า 1.1 (สระทับบรรทัดข้างเคียง)
  มาจากงานจริงที่หัวเรื่องไทยตั้ง line-height .82 จนสระทับคำโปรย แต่ผ่านทุกด่าน
- **ใหม่: ปุ่มหรือลิงก์ที่เล็กกว่า 24x24 px** (WCAG 2.5.8) ลิงก์ในเนื้อความไม่นับ
- ทุกข้อบอกชื่อ element และคลาส เช่น `p.muted 4.37` จะได้หากฎที่ต้องแก้เจอทันที
  หน้าที่ไม่มีอะไรต้องแก้ได้บรรทัดเดียว ไม่มีคำชม
- จงใจไม่ตรวจสไลด์ เพราะที่ความกว้างมือถือ สไลด์ล้นจอโดยตั้งใจ หน้าที่ใช้เวลาเกิน 30 วินาทีปล่อยให้
  `codebase page` และถ้าเครื่องไม่มีเบราว์เซอร์หรือการตรวจล้ม การเขียนก็สำเร็จตามเดิม
- `codebase page` ยังมีไว้สำหรับสิ่งที่การตรวจอัตโนมัติทำไม่ได้ คือคลิกทดสอบกับถ่ายรูป

**สองบั๊กที่เจอระหว่างทาง**

- **ข้อผิดพลาดหลังแก้ไฟล์ไม่เคยไปถึงโมเดล** บรรทัด "[n error(s) … after the change]"
  ขึ้นบนหน้าจอ แต่ไม่ได้อยู่ในข้อความที่ส่งให้โมเดล ตั้งแต่เพิ่มเข้ามาเมื่อ 29 ส.ค. 2026
  รุ่นนี้ส่งถึงโมเดลแล้ว
- **`codebase page` ค้างที่ STILL RUNNING หลายนาที ทั้งที่ตรวจเสร็จใน 6 วินาที** ครั้งหนึ่งรอ Edge
  ปิดตัวนาน 3 นาที 37 วินาทีบนเครื่องที่ทำงานหนัก จนโมเดลยอมแพ้และส่งหน้าที่ไม่ได้เห็นกลับมา
  ตอนนี้ขอให้เบราว์เซอร์ปิดตัวเองก่อน ถ้ายังไม่ปิดใน 5 วินาทีจึงบังคับปิด และการรอเกิดเบื้องหลัง

**สกิลดีไซน์หน้าเว็บสั้นลงจาก 109 เหลือ 61 บรรทัด** ตัดสิ่งที่โมเดลรู้อยู่แล้ว เหลือสิ่งที่มันไม่รู้เอง
หน้าตามาจากโลกของหัวเรื่อง ไม่ใช่พื้นครีมกับเขียวเข้มที่ทุกโมเดลเลือก ฟอนต์ต้องรองรับทุกอักษร
ที่หน้าแสดง (มีรายชื่อฟอนต์ไทย) ความผิดที่โมเดลทำโดยไม่รู้ตัว และท้ายงานให้ดูภาพหนึ่งครั้ง
แล้วปรับจุดเด่นของหน้าอีกครั้งเดียว การรีวิว UI ที่มีอยู่แล้วย้ายไปไฟล์ของตัวเอง
เอเจน web เปิดสกิลนี้ทุกหน้า และสกิล landing-page เหลือแค่สิ่งที่หน้าร้านไทยต้องเพิ่ม

## ธีม: 11 ชุด ทั้งสว่างและมืด อ่านออกทุกชุด

**เดิม** เจ้าของบอกว่า "บางธีมมันดูยากเสียเหลือเกิน" พอวัดจริง 11 จาก 14 ธีมมีคู่สีที่ต่ำกว่าเกณฑ์
แย่สุดคือตัวขาวบนปุ่มสีอ่อน: Dracula 1.38 · Rosé Pine 1.70 · Mocha 2.11 · One Dark 2.36
และเทสต์ไม่เคยตรวจคู่สีนี้
**รุ่นนี้**

- จูนเฉพาะสีที่ต่ำกว่าเกณฑ์ สีประจำธีมยังเหมือนเดิม และทุกชุดมีครบทั้งสองโหมด
  ชุดที่เพิ่มคือ Aetox Light · Nord Light · Alucard · Tokyo Night Day · One Light · Everforest Light ·
  Kanagawa Lotus · Solarized Dark พร้อมสีโค้ดของแต่ละชุด
- เลือกเป็นชุด แล้วเลือกโหมดตามระบบ สว่าง หรือมืด ถ้าตามระบบ ธีมจะเปลี่ยนทันทีที่ Windows เปลี่ยน
  เลือกคนละชุดให้แต่ละโหมดได้
- ตั้งสีเองได้สามสี คือสีหลัก พื้นหลัง และพื้นหน้า ปรับคอนทราสต์ 0–100
  และคัดลอกหรือนำเข้าธีมเป็นบรรทัด `aetox-theme:…` สีที่คำนวณได้ถูกดันกลับขึ้นเกณฑ์เดียวกับเทสต์
  จะเลือกสีไหนหรือลดคอนทราสต์เท่าไร ตัวอักษรก็ยังอ่านออก
- ตัวเลือกธีมเป็นตัวเดียวกันทั้งในหน้าตั้งค่าและเมนูบัญชี และมีชิป "Aa" ที่ใช้สีของแต่ละชุด
- ค่าเดิมที่เคยเป็นชื่อธีมเดี่ยวถูกย้ายเป็นชุดกับโหมดที่คุณใช้อยู่ เครื่องใหม่เริ่มแบบตามระบบ
- สวิตช์ Agent/Editor ใช้เม็ดสีกลางแทนเม็ดไล่ฟ้าตัวขาว ซึ่งบางธีมวัดได้แค่ 1.4:1
- ตอนเต็มจอและพับแถบข้าง การ์ดจะชิดขอบจอ ส่วนตอนแถบข้างเปิด มุมยังมนเหมือนเดิม
- ที่ยังไม่ครอบคลุม: พื้นหลังที่ตั้งเองยังไม่เปลี่ยนพื้นกล่องโค้ดกับ Monaco และข้อความใหม่ในภาษาจีนยังแสดงเป็นอังกฤษ

## เซสชันยาวจ่ายน้อยลง

**เดิม** เวลาเครื่องแบบละเอียดถึงวินาทีต่อท้าย system prompt ทุกคำขอ และ system prompt อยู่หัวสุด
ของส่วนที่ผู้ให้บริการแคช หัวเปลี่ยนทุกครั้งที่พิมพ์ข้อความใหม่ ประวัติทั้งหมดจึงถูกอ่านใหม่เต็มราคา
ใน 14 วันบนเครื่องเจ้าของ ส่วนนี้คือ 18.6M token หรือราว 40% ของ token ที่ไม่ได้แคชทั้งหมด
**รุ่นนี้**

- **เวลาเครื่องถูกใส่ครั้งเดียวในข้อความที่เปิดเทิร์น** ประวัติที่ส่งไปแล้วจึงไม่เปลี่ยนอีก
  ข้อความเก่าแต่ละอันบอกว่าส่งเมื่อไร ไม่ได้บอกเวลาที่เก่าแล้ว
- **ผลเครื่องมือเป็นข้อความล้วน** ไม่ห่อ JSON 7–8 ช่องที่โมเดลรู้อยู่แล้ว ไม่แปลง `<` เป็น `<`
  และลบรหัสสีทิ้ง shell ที่รันจบขึ้นต้นด้วย `exit 0` ส่วนงานที่ล้มขึ้นต้นด้วย `error: …`
  และติดธง `is_error` ไปถึงผู้ให้บริการ ลองกับผลจริง 2,951 ชิ้น ไบต์ลดลง 15.8%
- **อ่านบรรทัดที่ยังอยู่ในบทสนทนาซ้ำ** ได้คำตอบว่าอยู่ด้านบนแล้ว ไม่ส่งซ้ำ ถ้าช่วงที่ขอคลุมบรรทัดใหม่ด้วย
  ส่งเฉพาะบรรทัดใหม่ ใช้เนื้อไฟล์เป็นตัวตัดสิน ไม่ใช่ขนาดหรือเวลาแก้ไข
- **grep ตัดระหว่างผลลัพธ์ ไม่ตัดกลาง** จำกัดที่ 12 KB ก้อนแรกออกเต็มเสมอ ส่วนที่เกินจะบอก
  `path:line` ของทุกจุดที่เหลือพร้อม offset ให้ค้นต่อ ไม่หายเงียบเหมือนเดิม
  บนเครื่องเจ้าของ 30 วัน grep แบบมี context คือ 22% ของไบต์ผลเครื่องมือบนโต๊ะโค้ด
- **prompt เล็กลง** กติกาวาด SVG กับแผงในคำตอบย้ายไปเป็นสกิล `aetox-answer-visuals` ซึ่งเปิดเฉพาะตอนวาด
  คำอธิบาย web_search web_fetch calc และการส่งไฟล์ของเอเจน ย้ายไปมากับการใช้ครั้งแรก
  prompt โต๊ะโค้ดบนเดสก์ท็อปลดจาก 25,360 เหลือ 22,307 B และโต๊ะผู้ช่วยลดจาก 19,922 เหลือ 16,429 B
- ประโยคบอกความคืบหน้าพูดเมื่อเริ่มงานส่วนใหม่หรือเปลี่ยนทาง ไม่ใช่ทุกรอบที่เรียกเครื่องมือ
- โต๊ะตั้ง `verbosity:` (low/medium/high) ได้เอง โต๊ะโค้ดตั้ง medium ซึ่งเท่ากับค่าเดิมของเซิร์ฟเวอร์
  พฤติกรรมจึงยังเหมือนเดิม และปรับทีหลังได้ง่าย
- โต๊ะโค้ดไม่ถือเครื่องมือของบริการที่เชื่อมบัญชี (Meta YouTube n8n Windmill) และ GitHub แล้ว
  เดิมเครื่องมือพวกนี้มาด้วยทุกรอบ ประมาณ 1.4k token แต่ใน 30 วันไม่เคยถูกเรียกเลย
  งาน GitHub ไปทางเอเจน github

## โต๊ะโค้ด

- **ของใหม่ต้องมีเทสต์อยู่ในชุดเทสต์ของโปรเจกต์** แค่ "ลองรันแล้ว" ไม่พอ
  งานหนึ่งตรวจ Part 2 ด้วยสคริปต์ชั่วคราวใน shell เทิร์นถัดมาเขียนไฟล์ใหม่ทั้งไฟล์
  แล้วคะแนนตกจาก 63/63 เหลือ 20/63 เพราะไม่มีเทสต์ไหนคลุม Part 2
- **หลังเทสต์แคบ ให้รันการตรวจเต็มของโปรเจกต์** ไม่ใช่ทั้งรีโป ถ้ามีเทสต์ล้มในโค้ดที่การแก้ไปไม่ถึง
  ให้รายงาน ไม่ต้องตามแก้ เดิม `go test ./...` ทั้งรีโปเคย panic ในแพ็กเกจที่ไม่เกี่ยว และเคยค้าง 600 วินาที
- **ตอบให้กระชับ** บอกว่าแก้อะไร ตรวจเจออะไร และอะไรยังค้าง จะเสนอหรือแนะนำก็ได้
  แต่ต้องอ้างหลักฐานจากเซสชันนั้น และถ้าเดาต้องบอกว่าเดา
- `diagnostics` ใช้เมื่อไม่มีเทสต์หรือ build ให้รัน ไม่ตรวจซ้ำสิ่งที่เทสต์พิสูจน์ไปแล้ว
  `git status` ใช้ตอนจะ commit จริง ไม่ใช่ทุกครั้งที่จบงาน
- **โมเดลเข้าโหมดวางแผนเองไม่ได้แล้ว** จากงานจริง 376 เซสชันมี 2 ครั้ง และจากเบนช์ 1,263 รันมี 8 ครั้ง
  ที่โมเดลเข้าโหมดวางแผนเองแล้วล็อกตัวเองจนงานเสียทุกครั้ง ตอนนี้โหมดวางแผนเป็นปุ่มของคุณอย่างเดียว
  ส่วนเครื่องมือ plan, todo_write และ task_plan ยังใช้ได้เหมือนเดิม
- **ที่ลองแล้วถอยกลับ:** ย่อหน้า "Done means proven" เคยเปลี่ยนเป็น "รันตัวตรวจตัวเดียวที่พิสูจน์การแก้"
  ประหยัดได้ราว 11% แต่โจทย์ความปลอดภัย SEC1 บน Luna ตกจาก 0.93 เหลือ 0.77
  เพราะโมเดลเลิกยิงอินพุตโจมตีใส่โค้ดตัวเอง รุ่นนี้จึงกลับไปใช้คำเดิมของ 1.9.1 ทุกไบต์

## เบราว์เซอร์: ปุ่ม ให้เอเจนใช้ บนทุกแท็บ

- ถ้าปุ่มติดสี แปลว่าเอเจนใช้แท็บนั้นได้ แท็บที่เอเจนเปิดเองจะติดสีตั้งแต่แรก กดดับแล้วแท็บจะเป็นของคุณ
  แท็บยังเปิดอยู่ แต่เอเจนแตะไม่ได้ และจะรู้ตอนเรียกครั้งถัดไป
- แท็บที่คุณเปิดเองจะดับตั้งแต่แรก กดเปิดเมื่ออยากให้แชทบนจอใช้ ถ้าเอเจนสั่งปิดแท็บที่คุณให้ยืม
  แท็บจะกลับเป็นของคุณ ไม่ถูกปิด และแท็บนี้ไม่ถูกนับในงบหน่วยความจำ
- ก่อนโพสต์หรือส่งอะไรจากแท็บที่ให้ยืม ระบบยังถามคุณก่อน เหมือนแท็บของเอเจน

## เทอร์มินัล

- คลิกขวา: ถ้ามีข้อความที่เลือกไว้จะคัดลอก ถ้าไม่มีจะวาง Ctrl+C: ถ้ามีที่เลือกจะคัดลอก ถ้าไม่มีจะส่ง ^C
  ใช้ Ctrl+Shift+C/V ได้ และ Ctrl+V บนแป้นไทยวางได้แล้ว (เดิมส่ง ^V เข้าเชลล์)
- สีตัวอักษร เคอร์เซอร์ และแถบเลือกมาจากธีม และเปลี่ยนตามทันทีเมื่อสลับธีม
- Ctrl+คลิก URL เปิดในเบราว์เซอร์ในแอป ส่วน `path:line` หรือ `path(line,col)` เปิดไฟล์ตรงบรรทัดนั้น
- ย้อนดูได้ 10,000 บรรทัด
- เชลล์ที่ปิดเองไม่ค้างเป็นจอตายอีก ถ้าจบด้วย error แท็บยังอยู่ พร้อมปุ่มเริ่มใหม่และปิดแท็บ

- **ภาพ SVG ในกรอบโค้ด** ` ```svg ` ` ```html ` หรือ ` ```xml ` ที่ปิดครบและมีแค่ `<svg>` ชิ้นเดียว
  จะแสดงเป็นภาพ ไม่ใช่โค้ด 30 บรรทัด ถ้าต้องการโค้ด ใช้ปุ่มคัดลอก/บันทึกที่กรอบภาพ
  กรอบที่ยังพิมพ์ไม่เสร็จ มีเนื้อหาอื่นปน หรือมีสองภาพ จะแสดงเป็นโค้ดตามเดิม
- ตัวหนังสือในภาพที่โมเดลไม่ได้กำหนดสี ใช้สีตัวอักษรของธีม ไม่ใช่ดำที่มองไม่เห็นบนธีมมืด
  ภาพที่ปูพื้นเองจะไม่ถูกเปลี่ยน
- **การติ๊กขั้นในแผนเป็นจุดพับการ์ด** มุ่งเป้าแทบไม่เขียนประโยคระหว่างทำงาน งานห้าขั้นจึงเคยเป็นก้อนเดียวบนจอ
  ตอนนี้ตัดที่รอบถัดไปหลังติ๊ก ชุดคำสั่งที่รันพร้อมกันจึงไม่ถูกแยกเป็นสองการ์ด และตอนเปิดอ่านย้อนหลัง
  การ์ดพับที่เดียวกับตอนทำงานจริง
- **โหมดเขียนเอง: กดลิงก์ dev server ในคำตอบแล้วเปิดเบราว์เซอร์กลางจอ** เดิมแท็บไปเปิดใน workbench
  ซึ่งโหมดนี้ไม่แสดง จึงดูเหมือนกดแล้วไม่มีอะไรเกิดขึ้น ถ้ากดที่อยู่เดิมซ้ำ จะพาแท็บที่เปิดอยู่ขึ้นมา
  ไม่เปิดแท็บใหม่ รายงานปิดงานเปิดที่หน้า ชิ้นงาน ของ Explorer และปุ่ม ดูรายงาน ใต้แผนก็ใช้ได้ในโหมดนี้แล้ว
