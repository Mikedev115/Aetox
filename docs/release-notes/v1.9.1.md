# 🧩 Aetox v1.9.1

รุ่นนี้เป็นรุ่นของ **Aetox CLI ที่มีตัวติดตั้งของตัวเอง** กับ **งานโค้ดยาว ๆ ที่ไม่ค้างและไม่ล้มกลางทาง**
และ **ความจำที่ผู้ช่วยจดเองได้ทันทีแล้วคุณยกเลิกได้** — 43 คอมมิตใน 2 วันหลัง v1.9.0
(27–28 ก.ย. 2026) ส่วนใหญ่มาจากการวัดโจทย์โค้ดชุดโหด (SlopCodeBench และ Terminal-Bench)
ที่ไล่ทุกข้อที่ Aetox ตามหลัง แล้วแก้ที่ต้นเหตุ

## Aetox CLI: ตัวติดตั้งของตัวเอง ลงแล้วพิมพ์ `aetox` ได้ทุกที่

**เดิม** คอนโซลมาเป็น zip หรือ scoop แตกไฟล์แล้วต้องเพิ่ม PATH เอง
**รุ่นนี้** มี `aetox-cli-setup.exe` ในหน้า Release

- ลงในโฟลเดอร์ผู้ใช้ (`%LOCALAPPDATA%\Programs\Aetox CLI`) ไม่ต้องใช้สิทธิ์แอดมิน ตัวติดตั้งใส่ PATH ให้
  เปิดเทอร์มินัลใหม่แล้วพิมพ์ `aetox` ได้เลย
- ถอนได้จาก ตั้งค่า → แอป → Aetox CLI ก่อนเขียนทับหรือลบ ตัวติดตั้งเช็กว่า `aetox.exe` ไม่ได้รันอยู่
  ข้อความมีทั้งไทยและอังกฤษ
- แยกจากแอปทุกทาง ตัวติดตั้งแอปกับแพ็กเกจ Microsoft Store ไม่เปลี่ยน และ CLI ไม่ขึ้น Store
  ถ้าเครื่องมีแอปอยู่แล้ว CLI ใช้เอนจินของแอป คีย์ แชท และความจำชุดเดียวกัน
- ถ้าใช้ zip ให้รัน `.\aetox.exe path add` ในโฟลเดอร์นั้นครั้งเดียว (`aetox path remove` เอาออก)
  ตัวนี้แก้ PATH ผ่าน registry ตรง ๆ จึงไม่ติดเพดาน 1,024 ตัวอักษร
- **หน้าตอนเปิด** เป็นตัวอักษร AETOX สองแถว ข้าง ๆ บอก โต๊ะโค้ด · เวอร์ชัน · โฟลเดอร์ · branch
  ถ้าจอแคบจะวางซ้อนลงมา ส่วนบรรทัด "เริ่มจาก" ขึ้นแค่ 5 ครั้งแรก
- **ช่องพิมพ์** เป็นแผ่นพื้นเต็มความกว้าง มีแถบซ้ายสีตามโหมด โหมดกับโมเดลอยู่ในกล่อง
  ระหว่างที่ทำงานอยู่ ช่องพิมพ์บอกว่าพิมพ์แทรกได้
- **`--whole-machine`** ให้เครื่องมือเข้าถึงได้ทั้งเครื่อง โดยโปรเจกต์ยังเป็นที่ทำงาน ไฟล์ใหม่ยังลงในโปรเจกต์
  และที่เก็บกุญแจยังปิด ต้องเลือกทุกครั้ง ระบบไม่จำไว้ ใช้กับคอนเทนเนอร์หรือ VM ที่ทิ้งได้
  เดิมงานที่ต้องแตะ `/tmp` `/usr/bin` `/etc` จะชนกำแพง แล้วการ์ดขอสิทธิ์ก็ไม่มีใครตอบ
- ถ้าสายหลุด โหมดบรรทัดจะบอก "สายหลุด ต่อใหม่ ครั้งที่ 2/4 ในอีก 2 วิ" ไม่เงียบไปเฉย ๆ
- **บอกเมื่อมีรุ่นใหม่** จอเต็มจะขึ้นบรรทัดใต้หัวจอ พร้อมวิธีอัปตามที่ลงไว้ (ตัวติดตั้ง · `scoop update aetox-cli` · zip)
  ถาม GitHub ไม่เกินครั้งละ 12 ชั่วโมง ถ้าต่อเน็ตไม่ได้จะเงียบ และปิดได้ด้วย `AETOX_DISABLE_UPDATE_CHECK=1`
  เริ่มมีตั้งแต่รุ่นนี้ คนที่ใช้ CLI 1.9.1 จะเห็นเมื่อ 1.9.2 ออก

## ความจำ: ผู้ช่วยจดเองทันที และมีปุ่มยกเลิก

**เดิม** ทุกบรรทัดที่ผู้ช่วยอยากจำต้องรอคุณกดอนุมัติ และคำอธิบายเครื่องมือส่วนใหญ่เป็นข้อห้าม
ผู้ช่วยจึงจำน้อย และคุณต้องมาตัดสินการ์ดของเรื่องที่ตัวเองเพิ่งพูดไป
**รุ่นนี้** ผู้ช่วยจดเอง และคุณเป็นคนเอาออก

- บรรทัดที่ผู้ช่วยจดถูกเก็บทันที การ์ดใต้คำตอบแสดง "จำไว้แล้ว" พร้อมข้อความที่จด และมีปุ่ม **ยกเลิก**
  ยกเลิกแล้วทุกอย่างกลับเหมือนเดิม ทั้งการเพิ่ม การแก้ และการลืม
- เรื่องที่คุณปฏิเสธหรือยกเลิกไปแล้ว ผู้ช่วยจะไม่จดซ้ำ ไม่ว่าจะใช้คำไหน
- ผู้ช่วยรู้ว่าควรจดอะไร:
  - **จด** เมื่อคุณติ เมื่อคุณยืนยันวิธีที่ไม่ใช่วิธีปกติ เมื่อคุณบอกเรื่องของตัวเอง
    หรือมีการตัดสินใจ เป้า หรือกำหนดส่งที่โค้ดไม่ได้บอก
  - **ไม่จด** สิ่งที่ไฟล์หรือ git บอกได้อยู่แล้ว วิธีแก้บั๊ก และงานของสัปดาห์นี้
  - ถ้ามีบรรทัดเดิมในเรื่องเดียวกัน จะแก้บรรทัดนั้นแทนการเพิ่มซ้ำ
- วิธีทำงานเก็บเหตุผลไว้ในบรรทัดเดียวกัน (ทำไม · ใช้อย่างไร) และเปิดการ์ดแล้วแยกบรรทัดให้อ่าน
- ข้อเสนอจากการทบทวนเซสชันและจากนิสัยการทำงาน ยังรอคุณตัดสินเหมือนเดิม

## งานยาวไม่ค้าง: shell ที่นิ่งคืนตาให้โมเดล

**เดิม** ถ้า `go test ./...` ค้างหลังพิมพ์บรรทัดสุดท้าย เทิร์นจะนั่งรอจนครบ timeout 10 นาที
ในรันหนึ่งการรอนี้กินไป 65% ของเวลา และตอนที่โมเดลกลับมาถามผลด้วยคำอธิบายคนละคำ
ระบบก็รันเทสต์ทั้งชุดซ้อนขึ้นมาอีกชุด

- shell ที่ไม่พิมพ์อะไรเกิน 2 นาที โมเดลได้ผล STILL RUNNING พร้อมบรรทัดท้ายทันที ไม่ต้องรอถึง timeout
  ถ้าถามผลซ้ำ ระบบรอคำสั่งเดิมต่อ ไม่รันชุดใหม่ซ้อน
- "นิ่ง" แปลว่า ไม่พิมพ์ + ไม่ใช้ CPU + ชุดโปรเซสไม่เปลี่ยน คอมไพล์ที่เงียบแต่ยังทำงานอยู่จึงไม่ถูกนับว่าค้าง
- ถ้านิ่งครบ 3 นาที ระบบหยุดทั้ง process tree เอง เฉพาะที่วัด CPU ได้ ถ้าวัดไม่ได้ (เช่นใน WSL) จะรายงานอย่างเดียวไม่หยุด
  ความนิ่งนับต่อคำสั่ง การเรียกดูซ้ำไม่ทำให้เริ่มนับใหม่
- คำสั่ง background ที่รอด้วย `wait_for exit` ตอบกลับเมื่อนิ่งครบ 2 นาที แต่ไม่หยุดให้ เพราะ dev server
  ที่นิ่งอยู่เป็นเรื่องปกติ
- ผลลัพธ์ของ shell มีเพดาน 30 KB เก็บส่วนหัวกับส่วนท้าย เดิม log บรรทัดยาว 208 KB เคยทำให้คำขอถัดไป
  กระโดดจาก 56k เป็น 111k token และทุกรอบที่เหลือต้องจ่ายซ้ำ

## เน็ตหลุดและ 5xx ลองใหม่จริง

**เดิม** บันไดลองใหม่มีครบตั้งแต่ 1.9.0 แต่ไม่ทำงานเมื่อคำขอวิ่งผ่านเอนจินที่อยู่อีกโปรเซส (`aetox-engine.exe`)
เพราะชนิดของ error หายไประหว่างทาง ผลคือ DNS หาไม่เจอ สายถูกตัด หรือ 500 จบเทิร์นในไม่ถึงหนึ่งวินาที
**รุ่นนี้** ชนิดของ error ข้ามไปถึงเอนจินได้ ระบบจึงลองใหม่ตามที่ตั้งไว้

- สายหลุดหรือ DNS ล้ม: ลองใหม่ที่ชั้นการเชื่อมต่อ 2 ครั้ง แล้วที่ชั้นเทิร์นอีก 4 ครั้ง
- 5xx: ระบบถอยแล้วลองใหม่ที่ 2, 5 และ 10 วินาที พร้อมแถวสถานะ
- header โควตาของ Codex (เวลารีเซ็ตหลายชั่วโมงที่มากับทุกคำตอบ) ใช้เฉพาะกับ 429 แล้ว
  เดิมถูกอ่านเป็นเวลารอของ 500 ด้วย
- 401, 403, 400 และโควตาหมด ยังทำงานเหมือนเดิม

## เครื่องมือแก้ไฟล์และตัวตรวจคำสั่ง

- **ตัวตรวจ path ของ shell อ่านคำสั่งตามไวยากรณ์ของ shell นั้น**
  ในการวัด มีโจทย์ช่วงหนึ่งได้ 0/28 เพราะคำสั่งถูกปฏิเสธผิดสองครั้ง แล้วโมเดลยอมแพ้ทั้งที่เหลือเวลาอีกราว 28 นาที
  - ที่ตอนนี้ผ่านแล้ว:
    - backtick ของ PowerShell เป็น escape ไม่ใช่ command substitution
    - here-string หรือ heredoc ที่ส่งเข้าโปรแกรม (เช่น `@'…'@ | python -`) เป็นข้อมูล ไม่ใช่อาร์กิวเมนต์
    - ข้อความใน single quote ไม่ใช่ substitution
    - ไดรฟ์ที่ไม่มีอยู่จริง เช่น `e:\n` ในโค้ด Python ไม่นับเป็นทางออกจากโปรเจกต์
  - ที่ยังถูกปฏิเสธเหมือนเดิม:
    - ข้อความที่ส่งเข้า shell หรือ eval
    - `$(` ที่อยู่นอก quote
    - ไดรฟ์ที่ต่ออยู่จริงแต่อยู่นอกโปรเจกต์
- **batch แก้ข้อความที่ซ้ำกันได้** ถ้าข้อความเจอหลายที่ และในชุดเดียวกันมีการแก้ไฟล์นั้นก่อนหน้าแล้ว
  ระบบจะหาต่อจากจุดที่แก้ก่อนหน้า แบบเดียวกับที่ patch วาง hunk เดิม batch ล้ม 12.8%
  ส่วนหนึ่งเพราะเจอข้อความ "matches 2 times" แล้วทั้งชุดไม่ถูกเขียน
- **edit ที่ใส่ backslash เกินหรือขาดไปหนึ่งชั้น** จะบอกว่าผิดไปทางไหน และบรรทัดไหนที่ตรง
- **คำตอบปิดเทิร์นที่บอกเองว่างานยังไม่เสร็จ** ถูกส่งกลับให้ทำต่อหนึ่งครั้ง
  - เงื่อนไข: ครั้งเดียวต่อเทิร์น และเฉพาะเทิร์นที่ใช้เครื่องมือไปแล้ว คำตอบที่ปิดด้วยคำถามถึงคุณจะไม่ถูกส่งกลับ
  - ทดสอบกับคำตอบจริง 686 อัน: จับได้ 20 อัน ทุกอันยังไม่เสร็จจริง และไม่มีอันไหนจับผิด

## อื่น ๆ ในรุ่นนี้

- **undo ไม่กองไฟล์ในเครื่องอีก** เดิมเครื่องหนึ่งสะสมไว้ 29 คลัง 27,060 ไฟล์ รวม 600 MB
  - ไม่เก็บ `node_modules`, `.venv` และ `__pycache__`
  - snapshot ต่อกันเป็นสาย commit ทำให้ git แพ็กได้
  - คลังของโปรเจกต์ที่โฟลเดอร์หายไปแล้ว หรือไม่ได้ใช้ 30 วัน ถูกลบ
- **language server ที่ไม่เคยตอบถูกจำไว้ในดิสก์ 7 วัน** เดิม `aetox chat` รอบใหม่ต้องรอ 20 วินาทีซ้ำทุกครั้ง
  การตรวจไฟล์ .js สิบครั้งจึงเสียเวลารวมราว 170 วินาที
- **สกิล aetox-security:** ค่าที่สเปกรับต้องได้ผลเหมือนเดิม แถว SSRF จึงไม่บล็อก URL ภายในเองถ้าสเปกไม่ได้ห้าม
  ความเสี่ยงยังบอกผู้ใช้ และตัวกันที่จะเปลี่ยนพฤติกรรมกลายเป็นตัวเลือกที่ผู้ใช้เปิดเอง
- **สกิลออกแบบ UI:**
  - แยกงาน marketing / product / ระบบเดิม
  - ดูหน้าหลักด้วยข้อมูลสมจริงตั้งแต่เนิ่น ๆ
  - ตรวจภาษาไทยบนหน้าที่ render จริง
  - `page_check` ถ่ายภาพตอน render ครั้งแรก และอีกครั้งตอนเสร็จ
- โต๊ะโค้ดยกคำพูดของเทสต์มาในรายงานเฉพาะตอนที่ล้ม
- รายงานเทียบงานโค้ดจริงบนโมเดลเดียวกัน (Aetox 1.9.0 · OpenCode · Codex CLI) อยู่ที่ `docs/reports/`
  ตัวเลขเป็นค่าเฉลี่ย 3 รอบ พร้อมช่วงต่ำสุด–สูงสุด
