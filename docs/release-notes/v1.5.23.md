# 🧩 Aetox v1.5.23

รุ่นนี้เปิดประตูบ้านให้กว้างขึ้น **สามประตู** — Google Antigravity, GitHub Copilot และ Kilo Code —
พร้อมระบบที่ทำให้ Aetox จำตัวตนและนิสัยการทำงานของคุณได้เองอย่างมีมนุษย์ตรวจทุกขั้น:
**Session Review** และ **Habits**

---

## ผู้ให้บริการใหม่ 3 เจ้า

### Google Antigravity — โควตา Gemini ผ่าน Google OAuth

- ลงชื่อผ่าน Google OAuth (PKCE + loopback callback) ใช้โควตา Antigravity ที่ให้บริการ
  Gemini 3.x และโมเดล Claude ที่ Antigravity เสิร์ฟ
- runtime ใหม่ `RuntimeAntigravity` ทั้งสาย: ซองคำขอแบบ nested `request`, content parts
  แบบ Gemini, functionCall/functionResponse, และ routing ด้วย companion project ID
  (resolve อัตโนมัติผ่าน `:loadCodeAssist`)
- ดึงรายชื่อโมเดลแบบไดนามิกจากบัญชีจริง (`:fetchAvailableModels`) เรียงตามลำดับที่เซิร์ฟเวอร์แนะนำ
- สตรีม SSE รองรับ thought parts, thought signature (เก็บกลับเข้า history ให้โมเดลคิดต่อได้),
  usage รวม thought tokens, และ PDF/รูปผ่าน inlineData
- นำเข้าเซสชันจาก Antigravity CLI ที่ติดตั้งอยู่แล้วได้ (`~/.gemini/antigravity-cli/auth.json`)
- มีเครื่องมือ `cmd/probe-antigravity` ไว้ทดสอบการลงชื่อและ tool-calling รอบเดียวจบ

### GitHub Copilot — Device Flow แบบสองโทเคน

- ลงชื่อผ่าน GitHub Device Flow (`github.com/login/device`) ด้วย client ID สาธารณะของ editor plugin
- เข้าใจสถาปัตยกรรมสองโทเคน: GitHub token อายุยาวเก็บไว้ขอ mint Copilot token อายุสั้น (~25 นาที)
  จาก `copilot_internal/v2/token` และต่ออายุอัตโนมัติก่อนหมดอายุเสมอ
- ส่ง header ระบุตัว editor ครบทุกคำขอ (`Copilot-Integration-Id` ฯลฯ) — ค่าคงที่ pinned
  ไม่อ่านจากเครื่องผู้ใช้
- บัญชีที่ไม่มีสิทธิ์ Copilot ตอบ 403 แล้ว Aetox บอกตรง ๆ ว่าเป็นเรื่องสิทธิ์ ไม่ใช่ล็อกอินพัง
- นำเข้าโทเคนเดิมจาก VS Code / Copilot CLI (`hosts.json`, `apps.json`) ได้

### Kilo Code — ประตูเดียวสู่ 500+ โมเดล

- เกตเวย์ OpenAI-compatible ของ Kilo (`api.kilo.ai/api/gateway`) รวมโมเดล Anthropic,
  OpenAI, DeepSeek, Meta และอื่น ๆ ไว้ใต้คีย์เดียว (`KILO_API_KEY`)
- นำเข้าคีย์จาก Kilo CLI / config ในเครื่องได้ทันที ไม่ต้องคัดลอกด้วยมือ
- context window และ thinking capabilities resolve ตาม vendor ต้นทางของ `vendor/model`

ทั้งสามเจ้ามี **โลโก้ในแอปและในหน้าเอกสาร** และถูกจัดระดับความเสี่ยงตรงไปตรงมา
(Antigravity/Copilot เป็น `RiskRestricted` — ยืม client ID ของ editor ต้นทาง ผู้ใช้ควรรู้ก่อนใช้)
รายละเอียดการตัดสินใจอยู่ใน `docs/DECISIONS.md` §241

## Session Review — Aetox ทบทวนเซสชันเพื่อเรียนรู้ตัวคุณ (Hermes ethos)

เปิดใน Settings → Learning (ปิดตามค่าตั้งต้น):

- เมื่อเซสชันเงียบ 5 นาที หรือคุณสลับออกจากเซสชัน Aetox จะทบทวน **ข้อความของคุณเท่านั้น**
  (ไม่ใช่คำตอบของโมเดล — ต้นทุนต่ำ แม่นกว่า) แล้วเสนอข้อเท็จจริงถาวรเกี่ยวกับตัวคุณ
  เข้าไปเป็นข้อเสนอใน USER.md
- **มนุษย์ต้องอนุมัติทุกข้อ** — ไม่มีอะไรเขียนลงดิสก์เอง ทุกข้อผ่านคิว "รอคุณตัดสิน" เหมือนเดิม
- เขียนเป็น **ข้อเท็จจริงประกาศเชิงบอกเล่า** ไม่ใช่คำสั่ง ("ผู้ใช้ชอบสรุปสั้นก่อนแก้ไฟล์"
  ไม่ใช่ "ตอบสั้น ๆ ทุกครั้ง") เพราะคำสั่งที่ฝังไว้จะกลายเป็นเงาทับคำสั่งใหม่ในเซสชันถัดไป
- ยกเลิกได้ทันที: พอคุณพิมพ์ข้อความใหม่ การทบทวนที่กำลังรันถูกตัดทันที
  ไม่แย่งโควตาโมเดลที่รันอยู่ (สำคัญกับ Ollama ในเครื่อง)
- มีปุ่ม "ทบทวนเซสชันปัจจุบันเดี๋ยวนี้" สำหรับรันเองเมื่อไรก็ได้

## Habits — เห็นคำสั่งที่คุณสั่งซ้ำ

- คำนวณจากฐานข้อมูลล้วน ๆ **ไม่ใช้ LLM** — โมเดลอ่านตัวเลข ไม่ได้เดาตัวเลข
- ทำ normalization ภาษาไทยจริง: ตัดคำหวาน ("นะครับ", "หน่อย", "ช่วย" ฯลฯ) แล้วคลัสเตอร์
  ข้อความแรกของแต่ละเซสชันด้วยความคล้าย (common substring + คำทับซ้อน)
- แสดงรายการ "คำสั่งที่สั่งบ่อย" ใน Settings พร้อมจำนวนเซสชันที่สั่งซ้ำ
- และที่สำคัญกว่า: เมื่อคุณถามสิ่งที่เคยถามใน ≥2 เซสชันก่อนหน้า Aetox จะแนบบริบทให้โมเดลรู้ว่า
  นี่เป็นขั้นตอนที่ซ้ำ ๆ — จึงเสนอทำเป็น Skill หรือ starter card ได้พอดี แทนที่จะตอบซ้ำเหมือนครั้งแรก

## Skill dispatcher — โมเดลพลาดชื่อแล้วระบบเข้าใจแทน

เมื่อโมเดลเรียก `write` หรือ `grep` ตรง ๆ แทนที่จะเรียก `change`/`search` พร้อม `action`
dispatcher จะ resolve กลับไปยัง packed tool ที่ถูกต้อง ใส่ `action` ให้เอง และยังเคารพ
action filter ทุกข้อ (โหมดวางแผนปฏิเสธ write ได้เหมือนเดิม) — การเรียกที่เคยตอบ
"ไม่มีเครื่องมือนี้" กลายเป็นการทำงานที่สำเร็จ
