## 1. มันคืออะไร

หุ่นยนต์หัวกลมจอ OLED ที่**วาดขึ้นจากโค้ด** ไม่ใช่ไฟล์ภาพ ไม่มีอัปโหลด — เหตุผลเดียวกับหน้าการ์ตูนของเอเจนที่มันมาแทน
(12 ก.ย. 2026, DECISIONS §254): เอเจนที่ผู้ใช้สร้างเองพรุ่งนี้ต้องได้หน้าในวินาทีเดียวกับที่ได้ชื่อ และไม่มีไฟล์ที่สองให้หาย

ใช้ที่ไหน (วันนี้): **ตัวลอยบนจอ** (`Companion.svelte` mount ที่ราก `App.svelte`) — ตัวเดียว ลากไปวางตรงไหนก็ได้
จำตำแหน่งไว้ ไม่หลุดขอบจอ ไม่หันตามเมาส์ (โยกตัวเบา ๆ แทน) · ท่ามาจาก `presence.ts` อ่านสถานะเทิร์นของแชทบนจอ:
เครื่องมือที่รันเป็น**ไอคอน**ข้างหัวเท่านั้น · บับเบิลข้อความมีเฉพาะตอนเอเจน**พูด** — คำบรรยายระหว่างเครื่องมือ (แถว `note`/`said`
ของผู้ช่วยเอง ไม่เอาของซับเอเจน), ท้ายคำตอบตอนสตรีม, หรือคำถามที่ค้าง (`reportOf`) — ไม่ใช่ชื่อคำสั่ง ไม่ใช่คำโปรยของเรา ยกเว้นประโยคเดียว: **คำทักของห้อง** ตอนแชทว่างขึ้นจอ (สลับโต๊ะ/แชทใหม่/เปิดแอป) — ประโยคเดียวกับที่ห้องพิมพ์เหนือการ์ด (`starters.headlineFor` ใส่ชื่อผู้ใช้จากฟุตเตอร์) พูดพร้อมโบกมือ 4 วิแล้วเงียบ ถ้าโมเดลพูดจะแทนที่ทันที (12 ก.ย. 2026, §255)

**เอเจนและซับเอเจนทุกตัว** ก็คือตัวนี้ (`AgentMascot.svelte`) — บริษัทมีหน้าเดียว (COMPANY.md §6): เอเจนคือ role `assistant`
สวม `icon:` ของตัวเองบนหู ในสีที่ชื่อให้ (`coverHue`) หรือที่ `AGENT.md` ระบุ · เจ็ดที่ที่วาดเอเจน — ออฟฟิศ, การ์ด delegate ในแชท,
แผงงานพื้นหลัง, ห้องความสามารถ, งานวิดีโอ, รายชื่อและตัวแก้ไขในตั้งค่า — เรียกตัวเดียวกันด้วย props ชุดเดิมของหน้าการ์ตูน
(`name, icon, size, off, hue, state`) · `agentLook.ts` (`lookOf`) แปลงแถวโปรไฟล์จาก Go เป็น props ในที่เดียว · ไฟล์ `AGENT.md`
บอกรูปได้ด้วย `icon:` `shell:` `top:` `face:` `accent:` (id จากแคตตาล็อก) และ `hue:` ตัวเลข (สีเต็ม ชนะ accent) — ว่างทุกช่อง = แม่แบบผู้ช่วย
ในสีจากชื่อ · state ห้าคำของการ์ด (`'' / think / work / done / err`) เป็น pose ผ่าน `poseOfFaceState()` — ไทล์ในรายชื่อ `still`
ตัวที่กำลังทำงาน (think/work) ขยับ · picker ในตั้งค่า › เอเจน ให้สี่แกนตัวตนเดียวกับหน้าอวตาร และสวม "บุคลิก 1–6" ที่บันทึกไว้ได้
(badge ยังเป็นของเอเจน — บุคลิกคือรูปลักษณ์ ไม่ใช่ตัวตน)

เปิด/ปิดจากเมนูบัญชี (`CompanionSwitch.svelte`, ค่าใน `companionSetting.svelte.ts`) · เอาเมาส์เข้าใกล้ → กรอบ + ปุ่ม × ซ่อน + ปุ่มลำโพง (เสียงเปิด/ปิด — ปิดอยู่ปุ่มค้างให้เห็น) · คลิก → สุ่มท่าตอบ (greeting / cheer / helping / wink) 1.6 วิ ไม่มีข้อความ (ถ้ากำลังพูดอยู่ = หยุดพูดด้วย) · หลบหน้าต่างเนทีฟเสมอ (15 ก.ย. 2026, §292): แท็บเบราว์เซอร์เป็นหน้าต่างจริงที่วาดทับทุกชั้นของ DOM ตัวมันขึ้นทับไม่ได้จึงก้าวหลบ — ทะเบียนสี่เหลี่ยมอยู่ `workbench/nativeRects.svelte.ts` ลากเข้าไปใต้แท็บไม่ได้ จุดที่ถูกดันไม่ทับจุดที่ผู้ใช้ลากไว้ · ยังอยู่ในหน้าต่างแอปเท่านั้น — การออกไปนอกหน้าต่าง (หน้าต่าง WebView2 ที่สอง โปร่งใส บนสุด คลิกทะลุ) เป็นงานถัดไปที่ยังไม่ตัดสิน

**มันพูดได้** (12 ก.ย. 2026, ค่าเริ่มต้น *เปิด*): อ่าน **คำตอบที่จบแล้วของแชทบนจอ** **คำถามที่มันติดอยู่** และ**คำทักของห้อง**ตอนห้องว่างมาบนจอ (สวิตช์ย่อย `greet` / `companionGreet` เปิดเป็นค่าเริ่มต้น · รอ 0.4 วิ ให้ชื่อผู้ใช้โหลดก่อน จะได้ทักครั้งเดียว) ผ่านเครื่องเล่นตัวเดียวของหน้าต่าง (`lib/speech.svelte.ts` — ย้ายออกจาก Chat.svelte วันเดียวกัน ปุ่มฟังใต้คำตอบก็ใช้ตัวนี้) ด้วยเอนจิน/เสียงของ ตั้งค่า › เสียง · **ไม่อ่าน** narration ระหว่างเครื่องมือ — งานยาวเงียบจนกว่าจะรายงาน ฟองข้อความรับหน้าที่ระหว่างนั้น · เสียงเดียวเสมอ: อันใหม่แทนอันเก่าทั้งสองฝั่ง (หยุดเล่น + `StopSpeech` ยกเลิกสังเคราะห์) ชิ้นเสียงเล่นต่อกันทีละชิ้น ชิ้นที่ยังไม่มาคือ *เว้นวรรค* ไม่ใช่เสียงซ้อน · หยุดเมื่อผู้ใช้เป็นฝ่ายพูด: ส่งข้อความใหม่ / ไมค์เปิด / สลับแชท / ปิดสวิตช์ / คลิกตัวมัน · พูดไม่ได้ (ไม่มีเสียง เอนจินรันไม่ได้) = เงียบ ไม่มี error โผล่ — หน้าอวตารเป็นที่บอกเหตุผล (`AvatarSettings.svelte` ถาม `TTSStatus` แล้ว `ListTTSVoices` หาเสียงภาษา UI มีปุ่มไป ตั้งค่า › เสียง และ "ลองพูด") · ระหว่างอ่าน ฟองข้อความค้างบรรทัดแรกของคำตอบไว้ (`headlineOf`) · สวิตช์อยู่ `companionSetting.svelte.ts` (`voice`, localStorage `companionVoice` เหตุผลเดียวกับ `companionOn`) มีสามประตู: แถวในหน้าอวตาร ปุ่มลำโพงบนกรอบ และคลิกตัวมันตอนพูด (อันนี้หยุดรอบนั้น ไม่แตะสวิตช์)

**ทุกท่ามีสัญญาณจริง** (เทสต์ `gives every tool family a pose and the sheet's poses a tool` ล็อกไว้ว่าไม่มีท่าไหนไร้ทางถูกสวม):

| สัญญาณ | ท่า | ที่ |
|---|---|---|
| ไมค์เปิด / กำลังอ่านออกเสียง | listening / answering | `voice.svelte.ts` (Chat กระจกไมค์ออกมา · `speech.svelte.ts` ตั้ง `speaking` เอง) |
| โมเดลถาม / ตอบสตรีม / คิด | asking / answering / thinking | `presence.ts` |
| เครื่องมือรัน — ตามชื่อ ไม่รู้จักชื่อก็ตามตระกูล (`toolFace.ts`) | reading · searchFiles · searchData · searchDocs · research · typing · coding · planning · presenting · helping · debugging (`diagnostics`) | `TOOL_POSE` + `FAMILY_POSE` |
| เครื่องมือล้มแล้วยังไม่มีตัวถัดไป | debugging | `failed` |
| เทิร์นจบ — ตอบได้ / ล้ม (ไม่ใช่กดหยุด) | success / error 2.2 วิ | `Companion.svelte` |
| เปิดแอป-เปิดสวิตช์ / ถูกลาก / ถูกคลิก / เงียบ 5 นาที | greeting / walk (หันไปทางที่ถูกลาก — ขวา ซ้าย ขึ้นคือหันหลัง ลงคือหันมา; `walkTurn()` จากความเร็วที่เฉลี่ยแล้ว หัวหมุนไม่เกิน 240°/วิ ตัวตามมือแบบหน่วง) / cheer-wink-helping-greeting / recharge | `Companion.svelte` |
| ตื่นจากหลับ — ถูกจิ้ม/ถูกลาก vs มีข้อความเข้า | wake (ค่อย ๆ ลุก 1.1 วิ ยืดแขน ตาง่วง) / startled (สะดุ้ง .45 วิ มือชูสองข้าง แล้วเข้าท่าทำงาน) — เอนตัวลง/ลุกขึ้นเป็น animation บน `.ms-all` ไม่ใช่ transition เพราะภาพใหม่ไม่มีค่าเก่าให้ transition | `Companion.svelte` `wakeUp()` |

**เปลี่ยนท่าแบบสมูท** (เจ้าของ: "ไม่ใช่เด้งไปเด้งมาทันที"): ตำแหน่งมือหกค่าอยู่บนรูท (`handVars()`), แขนอ่านจากรูท → `.settle` transition พาแขนแกว่งไปเอง (.42 วิ) เหมือนที่ `--t` พาหัวหัน · ส่วนที่ markup เปลี่ยน (หน้า การ์ด ของในมือ) crossfade ใน `Mascot.svelte` (`{#key}` + fade .24 วิ) — สองภาพซ้อนกันชั่วครู่ โดยแขนของทั้งคู่อ่านค่าเดียวกันจึงเห็นเป็นแขนเดียว · ลูปทุกอัน (หายใจ กระพริบ ลอย) เริ่มที่ `--ms-phase` = เวลาที่วาด จึงไม่กระตุกกลับเฟรมแรกเมื่อวาดใหม่

## 3. กฎที่ล็อกไว้ (มีเทสต์ทุกข้อใน `src/test/mascot.test.ts`)

1. **สีคือตัวตน** — ท่าเปลี่ยนได้แค่แสงบนจอ แขน ไฟบนหัว และการ์ดลอย ห้ามแตะ accent หรือ shell · **ค่าเริ่มต้นของผู้ช่วยคือ `brand`** — เปลือกขาว หมวก/หูน้ำเงิน Aetox (เจ้าของ 13 ก.ย.: "ฝากเอาสีนี้เป็นค่าเริ่มต้นทีนะครับ" ชี้ตัวที่เขาตั้งไว้เอง; ก่อนหน้านั้นคือ `ink` ขาวกับเทาเงินตามโลโก้ 12 ก.ย. — แถวนั้นยังอยู่ให้เลือก) · **hue เป็นองศา = สีเต็มเสมอ** (เอเจนที่ได้สีจากชื่อ) · accent ที่ระบุชื่อชนะสีจากชื่อ
2. **ชิ้นส่วนระบุด้วย id ไม่ใช่ตำแหน่ง** — แคตตาล็อกทุกอันต่อท้ายเท่านั้น ห้ามแทรก ห้ามเปลี่ยนชื่อ · id ที่ไม่รู้จัก → ค่าเริ่มต้น ไม่ใช่ error
3. **badge บนหู = ไอคอนในชุดของแอป (`ICONS`) หรือ `'logo'` เท่านั้น** — ตัวเดียวกับปุ่มบนจอ คนเห็นหูก็รู้ว่าทำอะไร · โลโก้ใช้ path จริงจาก `assets/logo.svg` ไม่วาดใหม่
4. **แขนข้อเดียว ยาวคงที่** — ลูกบอลไหล่ + แคปซูลเดียว + มือกลม เป้าหมายในท่าบอกแค่ทิศทาง ไม่มีศอก ไม่ยืด
5. **มือยกไม่สูงกว่าเส้นหู (y ≥ 36)** และท่าที่ยกมือจำกัดการหันตามเมาส์ (`look` ≤ 30°) — ไม่งั้นหูจะถูกหันมาชนมือ
6. **ของในมือมีปริมาตรและหันถูกด้าน** — โน้ตบุ๊ก: ฝาอยู่ขอบไกลตัว (ใกล้คนดู) หันหลังฝาที่มีโลโก้มาหาเรา จอหันเข้าหาหุ่น ฐานกว้างกว่าฝาเล็กน้อยมีขอบโผล่ใต้ฝา คีย์บอร์ดเห็นเมื่อหันข้าง
7. **ไม่มี `<filter>` ต่ำกว่า 160px** — ตัวใหญ่ตัวเดียวมีได้อันเดียวคือ glow ใต้แสงตา (blur ใต้กลุ่มที่ขยับต้องคำนวณใหม่ทุกเฟรม ตัวลอยจึงใช้ halo แบบ gradient) · < 48px ตัดไฮไลต์ สำเนาหลังหู ช่องลำโพง และเหลือแค่กระพริบตา (`lite`) · ช่องใน picker และไทล์ในรายชื่อ**นิ่งสนิท** (`still`) — 25 ตัวหายใจพร้อมกันคือหน้าที่กระตุก
8. **markup ของผู้ใช้ไม่เข้า SVG** — ทุก id ถูก lookup ไม่ถูก interpolate

## 4. การหันทำงานยังไง (ไม่มี JS ต่อเฟรม)

ทุกชิ้นบนหัวประกาศมุม φ บนทรงกลม (หน้า 0° · หู ∓90° · ช่องลำโพง 180°):

```
x = 32 + R·sin(φ + t)     กว้างที่เห็น = |cos(φ + t)|     อยู่หน้าเมื่อ cos(φ + t) > 0
```

ของที่อยู่หน้าตัวมีความลึก d: `x' = 32 + (x − 32)·cos t + d·sin t` ระนาบนอนเห็นจากบนเล็กน้อย `y' = 49 + 0.4·d`

`rig.ts` วาด SVG ครั้งเดียวต่อ (ตัวตน, ท่า) แล้ว `mascot.css` คำนวณทั้งหมดจาก `--t` ตัวเดียวด้วย `sin/cos/atan2` ใน CSS
ชิ้นที่ข้ามจากหลังตัวไปหน้าตัวตอนหัน (หู แขน) วาดสองสำเนา สลับด้วย opacity เพราะ CSS สลับ DOM ไม่ได้
ชิ้นใหม่ในอนาคต (หมวก เสาอากาศ) แค่บอก φ — การหันทำงานทันที

## 7. บนเดสก์ท็อป — ร่างที่สองของผู้ช่วยตัวเดียวกัน (13 ก.ย. 2026)

ตั้งค่า › อวตาร › **ที่อยู่ของผู้ช่วย**: *ในแอป* (ค่าเริ่มต้น — ตัวลอยในหน้าต่างนี้ วาดสดด้วย CSS ทั้งหมดตาม §4) หรือ *ทั่วเดสก์ท็อป* — หน้าต่างเล็กของ Windows ที่ลากไปจอไหนก็ได้ อยู่ต่อแม้ย่อแอป เจ้าของขอให้เป็น**ตัวเลือก** ไม่ใช่การแทนที่ และให้บอกต้นทุนตรง ๆ

**ทำไมไม่ใช่ WebView2 ตัวที่สอง** — Wails v2 มีหน้าต่างเดียว หน้าต่างที่สองต้องสร้างเองอยู่แล้ว และ WebView2 อีกตัวกินแรม 40–70 MB "แค่ตัวเล็ก ๆ ตัวเดียว" ร่างบนเดสก์ท็อปจึงเป็น **Win32 layered window** (`UpdateLayeredWindow` จากผืน RGBA ที่ Go วาด) — โปร่งใสต่อพิกเซล คลิกทะลุตรงที่โปร่งใสโดย Windows เอง ไม่แย่งโฟกัส ไม่มีปุ่ม taskbar อยู่บนสุด แรมเพิ่มไม่กี่ MB ไม่มีโปรเซสเพิ่ม (`desktop/companion_windows.go`)

**สมองเดียว ร่างสอง** — `Companion.svelte` ยังตัดสินทุกอย่างเหมือนเดิม (ท่าจาก presence, บับเบิลจาก `reportOf`, ทักทาย, หลับ/ตื่น, เสียงพูด) แค่ไม่ render DOM เมื่อร่างออกไปแล้ว ทุกการเปลี่ยนแปลงไป Go ผ่าน `SetCompanionState` (`companion.go`) ร่างส่งคลิก/ลาก/ปุ่มกลับมาเป็น event `companion:input` (`desktopBody.svelte.ts`) เสียงยังออกจากหน้าต่างหลักที่เดียว

**ภาพมาจากไหน** — ไม่มีเบราว์เซอร์นอกหน้าต่าง จึง**อบ**เฟรมจาก rig เดียวกัน (`lib/mascot/bake.ts`): เมานต์ markup ของ `Mascot.svelte` นอกจอ เลื่อนทุกแอนิเมชันไปยังจังหวะที่ต้องการด้วย Web Animations API แล้วถ่ายค่า computed `transform`/`opacity` ลง inline style ของ SVG สำเนา → `<img>` → canvas → PNG ตามสเกลจอ **mascot.css ยังเป็นที่เดียวที่กำหนดการเคลื่อนไหว** — ไม่มีสูตร keyframe ซ้ำใน Go ชุดเฟรม = ทุกท่า × 4 จังหวะ + ตาหลับ + เดิน 12 ทิศ × 4 + ไอคอนกรอบ (~170 ภาพ, ~33 KB/ภาพ @175%) แคชที่ `<DataRoot>/companion/<hash>/` — hash จาก mascot.css + markup ทุกท่า + สเกล เปลี่ยน rig แล้วแคชเก่าตกไปเอง (`companion_sprites.go`) อบท่าปัจจุบัน+idle ก่อนแล้วที่เหลือทีละ 20 ภาพ

**ร่างทำอะไรเอง** (`companion_draw.go`, `companion_walk.go`) — เบลนด์สองจังหวะข้างเคียงให้สี่ภาพอ่านเป็นลูป, crossfade 240 ms ตอนเปลี่ยนท่า, กระพริบ, hop, เดินตามมือด้วยคณิตชุดเดียวกับ `Companion.svelte` (หันไม่เกิน 240°/s ทางสั้น ไม่เลี้ยวตามมือสั่น), บับเบิลการ์ดทึบ + ข้อความไทยจาก GDI (สมองตัดคำด้วย `Intl.Segmenter` ให้ Go จัดบรรทัด; ClearType กับ layered window → วาดบนบิตแมปทึบแล้วบังคับ alpha 255), กรอบเส้นประ + ปุ่ม ×/เสียง ตอน hover, ซ่อนตอนมีแอปเต็มจอ (`SHQueryUserNotificationState`)

**ต้นทุน** — หน้าต่าง = ส่วนที่ใช้จริงเท่านั้น (228 px ตอนไม่มีบับเบิล) 10 fps ตอนนิ่ง, 60 fps + `timeBeginPeriod(1)` ตอนขยับ เฟรมขับจาก `WM_MOUSEMOVE` ระหว่างลาก (WM_TIMER โดนท่วม) วัดจริง: แรม +0.8 MB, CPU ~1% ของหนึ่งคอร์ตอนมีบับเบิล

**หลายจอ** — ตัวหุ่น (ไม่ใช่ทั้งผืน) ถูกกันให้อยู่ในพื้นที่ทำงานของจอที่ใกล้สุด แต่**ขอบที่มีจอถัดไปเปิดไว้** ไม่งั้นข้ามจอไม่ได้เลย; DPI เปลี่ยนแล้วจุดที่จับยังอยู่ใต้เมาส์ นาฬิกาท่าไม่ reset และใช้เฟรมชุดเก่าย่อ/ขยายไปก่อนจนอบชุดสเกลใหม่เสร็จ

**ขนาด** — ลากมุมขวาล่างของกรอบ hover (ทั้งสองร่าง) ค่าเดียว `companionSetting.size` 64–240 px ค่าเริ่มต้น 104; บนเดสก์ท็อป size คูณเข้าสเกลชุดภาพ (`spriteScale = dpi/96 × size/104`) จึงอบชุดใหม่ต่อขนาด ระหว่างลากใช้ภาพย่อ/ขยายชั่วคราว หน้าอวตารมีแถวขนาด + คืนค่าเริ่มต้น · **ฟองข้อความโตตามตัว** (13 ก.ย. 2026, `bubbleMetrics` ใน `companionSetting.svelte.ts` และ `companion_draw.go` — กติกาเดียวกันสองภาษา ต้องแก้คู่กัน): ที่ 104 คือ 12px/กว้างสุด 300 เท่าเดิม ใหญ่ขึ้นตัวอักษรโต ¾ ของอัตราตัว (11–24px) ส่วนกว้างสุดโตช้ากว่า (+0.6/px เพดาน 380) ข้อความยาวจึงพับลงเป็นบรรทัดแทนที่จะยืดข้าง ขอบใน/มุม/ระยะจากตัวคิดเป็น em

**ความลื่น (วัดจากมือเจ้าของ 13 ก.ย. 2026, log `companion: drag`)** — ตอนขยับ ร่างรอ vblank ของจอที่มันอยู่ (`D3DKMTWaitForVerticalBlankEvent`, ถอยไป `DwmFlush` ถ้าเปิดไม่ได้) เฟรมขับด้วย timer 1 ms ที่มาหลังอินพุตเสมอ: ก่อนแก้ p95 30.7 ms ถอดรหัส PNG ~100/ลาก → หลัง mean 16.8 p95 17.5 ms gap 0–2/100 เฟรม = refresh ของจอ ที่เหลือคือลักษณะการเคลื่อนไหวจากภาพอบ (8 จังหวะ, หัน 30°) ซึ่งตัดสินว่าพอ
