# บันทึกการถอดระบบค้นไฟล์ด้วยดัชนีในเครื่อง

สถานะ: ถอดออกจากผลิตภัณฑ์แล้วเมื่อ 17 กันยายน 2026

## สิ่งที่เคยทดลองทำ

- สร้างฐานข้อมูล SQLite FTS5 ในเครื่องเพื่อค้นชื่อไฟล์ พาธ และข้อความด้วย BM25 โดยไม่ใช้โมเดลหรือ embedding
- อ่านไฟล์ข้อความ/โค้ด รวมถึงดึงข้อความจาก DOCX, PPTX, XLSX และ PDF ที่เครื่องมี `pdftotext`
- เพิ่มคำสั่ง `search` แบบ `action=index` ให้ผู้ช่วยสร้างดัชนีของโฟลเดอร์ที่เลือกก่อนค้นหา
- เพิ่ม API/RPC และ Wails bindings สำหรับสร้าง หยุด ลบ ดูสถานะ และค้นดัชนี
- เพิ่มแท็บด้านขวาสำหรับเลือกโฟลเดอร์ ดูสถิติ ค้นหา และสร้างดัชนีใหม่
- เพิ่ม prompt เฉพาะโหมดผู้ช่วย ข้อความแปล คู่มือ และชุดทดสอบของระบบนี้

## เหตุผลที่ถอดออก

- สถานะโฟลเดอร์ที่เลือกในหน้าต่างเป็นสถานะชั่วคราว ทำให้ผู้ช่วยไม่เห็นเป้าหมายอย่างสม่ำเสมอเมื่อเปลี่ยน session หรือเปิดแอปใหม่
- การสั่งผ่าน prompt และ tool routing ยังทำให้พฤติกรรมขึ้นกับบริบทของบทสนทนา ทั้งที่การสร้างดัชนีควรเป็นวงจรชีวิตของระบบโดยตรง
- หน้าดัชนีและการสร้างจากผู้ช่วยต้องซิงก์สถานะข้าม UI, engine และ cache เพิ่มความซับซ้อนมากกว่าประโยชน์ในรุ่นนี้
- การวางกติกาไว้ใน prompt กลางเสี่ยงทำให้โหมดโค้ดได้รับพฤติกรรมที่ไม่เกี่ยวข้อง จึงเคยย้ายไป prompt ผู้ช่วย แต่สุดท้ายเลือกถอดทั้งระบบ

## ขอบเขตที่ถอด

- ตัว indexer และตัวดึงข้อความเอกสาร
- engine runtime, assistant callback และ `search action=index`
- API/RPC, desktop forwarders และ Wails bindings ที่เกี่ยวข้อง
- แท็บดัชนีไฟล์ เมนู สถานะ workbench ข้อความแปล และ guide targets
- prompt ผู้ช่วยและ tests เฉพาะฟีเจอร์

การค้นไฟล์เดิมของโปรเจกต์ผ่าน `list`, `glob` และ `grep` ไม่ถูกเปลี่ยน และงานส่วนอื่นใน worktree ไม่ถูกย้อนกลับ

## ข้อมูลบนเครื่องผู้ใช้

ดัชนีที่เคยสร้างเป็นแคชอนุพันธ์ที่ตำแหน่ง `<DataRoot>/indexes/files.db`; ไฟล์ต้นฉบับไม่เคยถูกย้ายหรือแก้ไข การถอดโค้ดครั้งนี้ไม่ลบแคชเดิมอัตโนมัติ เพื่อหลีกเลี่ยงการแตะสถานะนอกโปรเจกต์หรือชนกับแอปที่ยังเปิดอยู่ สามารถลบไฟล์แคชนี้ภายหลังเมื่อปิด Aetox แล้วได้โดยไม่กระทบไฟล์ต้นฉบับ

หากนำแนวคิดนี้กลับมา ควรกำหนดแหล่งโฟลเดอร์และวงจรชีวิตการสแกนเป็นระบบถาวรแบบ event-driven ให้ UI กับผู้ช่วยอ่านสถานะเดียวกัน และไม่พึ่ง prompt เพื่อเริ่มงานพื้นฐาน
