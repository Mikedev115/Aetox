# พาเนลชิ้นงานในเซสชัน — ทำไมเปิดแล้วรอ และแก้ยังไง

**สถานะ: แก้แล้ว 11 ก.ย. 2026** (เจ้าของ: *"มันเรนเดอร์ยังไง ทำไมเปิดอยู่ถึงรอนานและกระตุก ทั้งที่ควรจะแบ่งโหลด"*)

## อาการ และเหตุ

พาเนล **ชิ้นงานในเซสชัน** เรียก `ListArtifactsIn('all')` แล้วกรองเองฝั่งหน้าจอ:

```
ListArtifactsIn('all')   ← กวาดทุก root: โฟลเดอร์ non-project + โปรเจกต์ที่เปิด
   │                       + ทุกโปรเจกต์ที่เคยเปิด (RecentProjects)
   │                       readdir + stat ต่อไฟล์ · สูงสุด 5,000 แถว
   │                       เรียงใหม่ทั้งชุด · JSON ข้าม binding
   ↓
if (art.sessionId === curSessionId)   ← เก็บไว้แค่ไม่กี่แถว
```

สองอย่างที่ทำให้มันแพงเกินคำถาม:

1. **ถามกว้างกว่าที่ใช้** — แถวที่เก็บคือแถวใน `output/<sessionID>` เท่านั้น เพราะ `sessionId` ของ Artifact ถูกอ่านมาจากชื่อโฟลเดอร์ตั้งแต่ต้น (`sweepSession` รับชื่อนั้นมา) การกรองที่หน้าจอจึงเป็นโฟลเดอร์ที่ควรชี้ไปตั้งแต่แรก
2. **ทำงานตอนไม่มีใครดู** — `$effect` ผูกกับ `cockpit.chat.length` และ `cockpit.plan` ⇒ ยิงทุกข้อความที่ถูกเขียน และทุกครั้งที่แผนขยับ และเพราะแท็บที่อยู่ข้างหลังยัง mount ค้างอยู่ (`display:none`) มันจึงทำทั้งเทิร์นให้กับรายการที่ไม่มีคนอ่าน

| `desktop/frontend/wailsjs/*` | binding ใหม่ (ตัวแอป generate ให้เอง — มี `wails dev` เฝ้าอยู่) |

| `Workbench.svelte` | ส่ง `active={workbench.activeId === tab.id}` ให้พาเนล (แบบเดียวกับ GitPane) |

## ต่อด้วย: โค้ดไม่ใช่ชิ้นงาน (เจ้าของ, 11 ก.ย.)

*"ตรงนี้ไม่ควรแสดงโค้ดสิ มันควรแสดงแค่ ไฟล์ ตัวอย่าง หรือ แผน หรืออะไรพวกนี้"* — พาเนลนี้ประกาศจุดประสงค์ของตัวเองไว้ที่
`workbench.svelte.ts` ว่า **Plan, Walkthrough, UI Mockups, Media** แต่รายการกลับเต็มไปด้วย `.go` / `.svelte` ของโปรเจกต์
ที่เซสชันเข้าไปแก้ เพราะมันดึงจากสามทาง: ไฟล์ที่เทิร์นผลิต (`producedFiles`), ไฟล์ที่เซสชันแก้ (`SessionEdits`) และโฟลเดอร์ output ของแชท

แก้: `detectKind()` คืน `null` สำหรับไฟล์ซอร์สโค้ด (`ArtifactKind` จึงไม่มี `'code'` อีก) และทั้งสามทางที่เพิ่มรายการข้ามมันทิ้ง
— กฎเดียว ถามที่เดียว ไม่ว่าไฟล์จะเข้ามาทางไหน `other` ยังอยู่: `.pptx`/`.zip` ที่เอเจนสร้าง คือของที่ทำมาจริง แต่พรีวิวไม่ได้
ต่างจากซอร์สของโปรเจกต์ ส่วนสิ่งที่เซสชันแก้ ยังดูได้สองที่ตามเดิม คือ diff ใต้เทิร์น (`FileChangeReview`) และ
"ไฟล์ที่สร้างหรือแก้" ในแถบเซสชัน (`SessionStrip`)

## ยังไม่ได้ทำ (และเหตุผล)

- **ยังไม่ได้วัดเวลาจริงของการเปิดพาเนลแบบ end-to-end** — โฟลเดอร์หลัก `C:\Users\phrms\aetox\output` อยู่นอกช่วงที่เซสชันเข้าถึง จึงวัดได้แค่โฟลเดอร์ของโปรเจกต์ (14 ไฟล์, 7 ms) ถ้าต้องการตัวเลขก่อน/หลังจริง ต้องเพิ่มโฟลเดอร์นั้นเข้าเซสชันก่อน แล้ววัดทั้ง `ListArtifactsIn('all')` กับ `ListArtifactsForSession` เทียบกัน
- **debounce ไม่ได้ใส่** — พอการเรียกถูกและถูกเรียกเฉพาะตอนมองอยู่ การรวมการเรียกซ้ำจึงเป็นของประดับ ไม่ใช่การแก้ (ถ้าอนาคตมีอาการยิงรี่ยังเหลือ ค่อยเพิ่มทีหลังได้)
