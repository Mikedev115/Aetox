# สถาปัตยกรรมของไกด์ — ฐานที่ต้องอยู่รอดเมื่อ UI เปลี่ยน

> เอกสารยืน (living) · เขียน 15 ก.ย. 2026 · ตัดสินใจอยู่ที่ [DECISIONS §293](../DECISIONS.md) · แผนงานเดิมอยู่ที่ [ui-guide-2026-09-15.md](ui-guide-2026-09-15.md)
>
> **ทำไมมีเอกสารนี้:** ไกด์ผูกกับ UI มากกว่าฟีเจอร์ไหนในแอป — มันรู้จักปุ่ม 157 จุดด้วยชื่อ และ UI จะถูกปรับแน่นอน
> เอกสารนี้ไม่ได้บรรยายว่ามีอะไร (โค้ดบอกเองได้) แต่บอกว่า **อะไรจะพังเมื่อ UI เปลี่ยน อะไรจับได้ อะไรจับไม่ได้ และจะแก้ยังไงให้ไม่พัง**

## 1. หลักการเดียวที่ทุกอย่างตามมา

> **ไกด์ไม่ได้มองจอ มันอ่านแผนที่ แล้วถาม DOM ว่าของชิ้นนั้นอยู่ตรงไหน *ตอนนี้***

เพราะเราเป็นเจ้าของ DOM ไกด์จึงไม่ต้อง screenshot ไม่ต้อง vision ไม่ต้องเดาพิกัด — ต่างจาก computer-use ที่ต้องดูภาพ
ผลที่ตามมาคือ **พิกัดไม่เคยเน่า** (คำนวณสดทุกครั้งจาก `getBoundingClientRect()`) แต่ **ชื่อเน่าได้** — และชื่อคือทั้งหมดที่ไกด์มี

ทุกข้อในเอกสารนี้คือการป้องกันชื่อไม่ให้เน่า

## 2. ชั้นของระบบ — อะไรนิ่ง อะไรขยับ

| ชั้น | ไฟล์ | เปลี่ยนบ่อยแค่ไหน | ใครเปลี่ยน |
|---|---|---|---|
| **สัญญา** id ของปุ่ม | `data-guide="…"` ใน `.svelte` | นิ่งที่สุด — เปลี่ยนเมื่อฟีเจอร์หาย/ย้ายจริง | คนที่แก้ฟีเจอร์นั้น |
| **แผนที่** id → หน้า/safe/§ | `lib/guide/map.ts` | ตามข้อบน | คนเดียวกัน |
| **คำพูด** ชื่อ/คืออะไร/ทำไม | `docs/GUIDE-MAP.md` → `locales/{th,en,zh}.ts` | เปลี่ยนได้อิสระ ไม่กระทบโค้ด | ใครก็ได้ที่เขียนคำ |
| **ไทม์ไลน์** ลำดับการพาเดิน | `lib/guide/routes.ts` | เปลี่ยนบ่อย เป็นเรื่องรสนิยม | เจ้าของ/คนออกแบบ UX |
| **การเดิน** ยืนตรงไหน หันทางไหน นานแค่ไหน | `lib/guide/walk.ts` | เปลี่ยนเมื่อจูนท่า | คนทำ motion |
| **ทางไปถึง** ต้องกดปุ่มไหนก่อนถึงจะไปถึงจุดนั้น | `lib/guide/path.ts` | เปลี่ยนเมื่อประตูเข้าห้องย้าย | คนที่แก้ห้องนั้น |
| **ตอนนี้อยู่หน้าไหน** | ป้าย `data-guide-place` บนหน้า + `lib/guide/where.ts` | เปลี่ยนเมื่อมีหน้าใหม่ | คนที่ทำหน้านั้น |
| **ชื่อของหน้า** (คำศัพท์ชุดเดียว) | `lib/rooms.ts` → `PageId` | เปลี่ยนเมื่อมีหน้าใหม่ | คนที่ทำหน้านั้น |
| **คำทัก** เปิดมาแล้วพูดอะไร | `lib/guide/greeting.ts` | เปลี่ยนบ่อย เป็นเรื่องน้ำเสียง | คนเขียนคำ |
| **ค่าที่ผู้ใช้ตั้ง** สมอง ภาษา เสียง | `lib/guide/guidePrefs.svelte.ts` | เพิ่มลูกบิดใหม่ = เพิ่มหนึ่งฟิลด์ | — |
| **คำสั่งสำเร็จ** ปุ่ม "พาไปหน้าโค้ด" | `lib/guide/presets.ts` | เพิ่มได้เรื่อย ๆ = หนึ่งแถว | เจ้าของ/UX |
| **หน้าตั้งค่าไกด์** | `lib/guide/GuidePanel.svelte` | ตามสองแถวบน | — |
| **การไปหน้า** | `lib/guide/pages.ts` + `lib/rooms.ts` | เปลี่ยนเมื่อห้องเพิ่ม/ย้ายหน้า | คนที่แก้ห้องนั้น |
| **สมอง** | `lib/guide/mapPick.ts` · โต๊ะ `guide` ในเอนจิน | นาน ๆ ครั้ง | — |
| **การวาด** | `lib/guide/Guide.svelte` | นาน ๆ ครั้ง | — |

**กฎการแยก:** แต่ละไฟล์ตอบคำถามเดียว และเปลี่ยนไฟล์หนึ่งต้องไม่บังคับให้อ่านอีกสองไฟล์

- `routes.ts` ตอบ **"พาไปดูอะไรบ้าง ตามลำดับไหน"** — ไม่รู้ว่าจะเดินยังไง ไม่รู้ว่าจะพูดอะไร
- `walk.ts` ตอบ **"ยืนตรงไหนเมื่อมีเป้าอยู่ตรงนี้"** — ไม่รู้ว่าเป้าคืออะไร ไม่แตะ DOM ไม่แตะ state (เลขคณิตล้วน ทดสอบได้หมด)
- `path.ts` ตอบ **"จากตรงนี้ ต้องกดอะไรต่อ"** — คืน**ก้าวเดียว** เสมอ ไม่เคยคืนแผนทั้งชุด
- `pages.ts` ตอบ **"จะเปิดหน้านั้นตรง ๆ ได้ยังไง"** — ทางลัดสำรอง ใช้เมื่อ `path.ts` หาทางกดไม่เจอ
- `greeting.ts` ตอบ **"เปิดมาเจอผู้ใช้อยู่ห้องไหน แล้วควรทักว่าอะไร"** — ไม่รู้เรื่องการเดิน ไม่รู้เรื่องเส้นทาง
- `Guide.svelte` **ไม่ตัดสินใจอะไรเลย** — มันแค่ตอบสนอง `moveSeq`/`saySeq` จาก `guideState`

> ก่อน 15 ก.ย. 2026 สามอย่างแรกอยู่ก้อนเดียวกันใน `Guide.svelte` การจะจูนท่าเดินจึงต้องเปิดคอมโพเนนต์ที่มีทั้งการวาด เสียง และบับเบิลปนอยู่ — นั่นคือเหตุผลที่แยก

## 3.3 หน้าบอกชื่อตัวเอง — ไกด์ไม่ผูกกับหน้าไหนเลย

เดิมไกด์ถามแอปว่าอยู่หน้าไหน ผ่าน `cockpit.activeView` ซึ่งมีปัญหาสองชั้น: มันตอบได้แค่ `"settings"` **บอกไม่ได้ว่า section ไหน**
(ไกด์จึงแยกหน้าโมเดลกับหน้าความจำไม่ออก ทักเหมือนกันหมด) และมันผูกฟีเจอร์ที่ควรลอยอยู่เหนือ UI เข้ากับไส้ในของสโตร์ตัวหนึ่ง

**ตอนนี้หน้าประทับชื่อตัวเองไว้** — `data-guide-place="<PageId>"` บนรากของหน้า แล้ว `where.ts` อ่านจาก DOM
ไกด์จึงไม่รู้จักเลยว่าห้องไหนสร้างยังไง สโตร์ไหนถือสถานะ หรือว่ามี `cockpit` อยู่ · **ห้องใหม่พรุ่งนี้ ติดป้ายแล้วไกด์เห็นทันที ไม่ต้องแก้ไฟล์ไหน**
(เจ้าของ 15 ก.ย. 2026: *"อาจจะต้องทำเหมือนป้ายไว้ … ไกด์ไม่ผูกกับหน้าไหนเลย"*)

**คำศัพท์ชุดเดียว** (เจ้าของ: *"ระบบแมพของเราเอามาใช้กับตรงนี้ได้ไหม"* — ได้ และนี่คือจุดที่สองอย่างมาบรรจบ):
`PageId` ใน `lib/rooms.ts` คือชื่อของ "ที่" ในแอปนี้ และมีสี่คนพูดภาษาเดียวกันโดยไม่มีใครเก็บลิสต์ของตัวเอง —
ป้ายบนหน้า · ช่อง `page` ของทุกแถวในแผนที่ · เส้นทางการกดใน `path.ts` · ตัวเปิดหน้าตรง ๆ ใน `pages.ts`

ป้ายชั้นในสุดชนะ เพราะที่ซ้อนกันได้ (Settings วาดเปลือกแล้ววาด section ข้างใน) อันในสุดคือคำตอบที่เจาะจง · ป้ายที่สะกดผิด = ไม่มีคำตอบ ไม่ใช่คำตอบผิด

**`pages.ts` คือที่เดียวที่รู้ไส้ในของแอป** — แปลง `PageId` เป็น setter ของ `cockpit` แอปจัดห้องใหม่เมื่อไหร่ ตามแก้ที่เดียว

## 3.4 พาเดิน ไม่ใช่เทเลพอร์ต

ไกด์เคยไปถึงจุดหมายด้วยการเรียก setter ของแอปเอง — หน้าจอเปลี่ยนเฉย ๆ **ซึ่งไม่สอนอะไรเลย**
คนที่ดูอยู่อยากรู้ว่า*ปุ่มไหน*พาไปที่นั่น และหน้าจอที่จัดเรียงตัวเองใหม่โดยไม่มีใครกด ทิ้งเขาไว้ที่เดิม คือไม่รู้
(เจ้าของ 15 ก.ย. 2026: *"ควรจะค่อยๆพาคลิกทีละจุดไม่ใช่เด้งไปเลย ไม่งั้นผู้ใช้ไม่รู้ว่าควรจะกดไปตรงไหน"*)

**รูปแบบที่ทำให้มันทน: คำนวณแค่ "ก้าวถัดไป" เท่านั้น** ไม่เคยทำแผนห้าก้าวไว้ให้เดินตามตาบอด —
หน้าจอขยับใต้ทุกคลิก (เมนูเปิด ห้องโหลด rail โผล่) แผนที่ทำไว้ก่อนคลิกแรกจึงเก่าตั้งแต่คลิกที่สอง
ถามใหม่ทุกครั้งแล้วคำตอบจะเป็นของที่**อยู่บนจอจริงตอนนี้**และนำไปข้างหน้าได้จริงเสมอ
ผลพลอยได้: `path.ts` ไม่ต้องมีสถานะว่า "เดินถึงไหนแล้ว" เลย — **DOM คือสถานะ**

กฎที่ต้องรู้ข้อเดียว: เอา **ประตูชั้นในสุดที่มองเห็น** ไม่ใช่ชั้นแรก เพราะกดประตูแล้วมันไม่ได้หายไป
(ปุ่มเมนูบัญชียังอยู่หลังเมนูเปิด) ถ้าเอาชั้นแรกจะชี้ซ้ำที่เดิมตลอด และกดครั้งที่สองจะปิดสิ่งที่ครั้งแรกเปิด

ประตูอยู่ใน `ROOM_DOORS` แค่ 5 แถว ส่วนปุ่ม rail ของหน้านั้น ๆ **อ่านจากแผนที่เอง** (`railDoorFor`) — section
ที่ย้ายหรือเปลี่ยน id จึงไม่ต้องแก้ไฟล์นี้ · หาทางกดไม่เจอ → ถอยไปเปิดหน้าตรง ๆ เพราะไปถึงแบบไม่มีคำอธิบาย ยังดีกว่าไปไม่ถึง

## 3.5 ไกด์ฟัง ไม่ดัก

ตอนไกด์เปิด **แอปใช้งานได้ตามปกติทุกอย่าง** สองท่า แยกกันชัด:

| ท่า | เกิดอะไร |
|---|---|
| **คลิกธรรมดา** | ใช้แอปตามปกติ ไกด์**ไม่แตะอีเวนต์เลย** และไม่พูดถึง — ยกเว้นกรณีเดียว: ถ้ามันคือปุ่มที่ไกด์เพิ่งขอให้กด นั่นคือการเดินไปต่อ |
| **Shift+คลิก** | "ปุ่มนี้คืออะไร" — อันนี้ไกด์ยึดอีเวนต์ไว้ (`preventDefault`) เพราะคนที่กด Shift อยากรู้ว่าปุ่มทำอะไร ไม่ได้อยากให้มันทำ · การส่งข้อความออกไปเพื่อจะรู้ว่าปุ่มส่งทำอะไร เป็นการแลกที่ไม่คุ้ม |

listener อยู่ capture phase เพราะการยับยั้งต้องเกิดก่อน handler ของปุ่มเอง — แต่ทางของคลิกธรรมดา `return` ออกโดยไม่แตะอีเวนต์ การกดปกติจึงเหมือนเดิมทุกประการ

เดิมไกด์กลืนคลิก*ทุกอัน* แอปจึงกลายเป็นอ่านอย่างเดียวตอนไกด์เปิด — คนที่เปิดไกด์มาเพื่อ*เข้าใจ*ปุ่มหนึ่ง กลับ*กด*ปุ่มนั้นไม่ได้
(เจ้าของ: *"เวลาผู้ใช้กดเองควรจะกดได้เลย … หรือเราทำให้ แบบ กดชิฟแล้วคลิก จะเป็นการถามไกด์ก็ได้ว่าปุ่มนี้คืออะไร"*)

เคอร์เซอร์ `help` ถูกเอาออกด้วย — เคอร์เซอร์ที่บอกว่า "นี่คือคำถาม" บนปุ่มที่กดแล้วทำงานจริง คือการโกหก

**ข้อยกเว้นเดียว:** `guide.pressing` — ตอนไกด์กดปุ่มให้เอง มันไม่นับเป็นคลิกของผู้ใช้

## 3.6 บับเบิลมีสองหน้า และไกด์มีสมองของตัวเองได้

หน้าแรกอธิบายสิ่งที่กำลังดูอยู่ · หน้าที่สอง (ปุ่มฟันเฟืองบนกรอบ) คือตัวไกด์เอง — สมอง ภาษา เสียง และปุ่มพาไปเลย
กรอบเป็นแบบเดียวกับตัวลอย (× ปิด · ลำโพงปิดเสียง · ฟันเฟือง) ด้วยเหตุผลเดียวกัน: ตัวที่ปิดได้ ปิดเสียงได้ โดยไม่ต้องไปหาว่าสวิตช์อยู่ไหน

**ไกด์มีสมองของตัวเองได้** (`OpenGuideSession(provider, model, think)`) — ว่างไว้ = ใช้อันเดียวกับแชท ซึ่งเป็นกรณีปกติ
และเป็นกรณีที่ยังทำงานเมื่อผู้ใช้ไปเปลี่ยนผู้ให้บริการที่อื่น · **ประเด็นของการตั้งเอง**: งานของไกด์คือคำศัพท์ปิดบนแผนที่
โมเดลเล็กในเครื่องทำได้ ตั้งให้ไกด์ใช้ Ollama ขณะที่แชทคุยกับโมเดลที่เสียเงินอยู่ได้เลย · เปลี่ยนผู้ให้บริการแล้วชื่อโมเดลถูกล้าง
เพราะโมเดลเป็นของผู้ให้บริการ การหิ้วชื่อข้ามเจ้าคือการขอโมเดลที่ไม่มีอยู่

**ค่าที่ตั้งคือ "ตั้งค่า" ไม่ใช่ "ความจำ"** — ไกด์ไม่เก็บบทสนทนาและไม่เก็บตำแหน่งการเดิน (§3.3) แต่สิ่งที่ผู้ใช้*เลือก*
เก็บได้เหมือนธีม · อ่านกลับแบบทีละฟิลด์ ค่าที่ไม่รู้จักถูกแทนด้วยค่าเริ่มต้น ไม่ให้ระดับคิดเพี้ยน ๆ หลุดขึ้นไปบนคำขอ

**เพิ่มของใหม่:** ลูกบิด = หนึ่งฟิลด์ใน `guidePrefs` + หนึ่งแถวใน `GuidePanel` · ปุ่มพาไปเลย = **หนึ่งแถวใน `presets.ts`** กับคำสามภาษา ไม่ต้องแตะโค้ดเลย
(เทสต์ `guidePresets.test.ts` แดงถ้าปุ่มชี้ไป id ที่แผนที่ไม่มี หรือคำแปลขาดภาษาใดภาษาหนึ่ง)

## 4. เส้นที่ห้ามข้าม (ความปลอดภัย)

สามข้อนี้ถูกบังคับที่โค้ด ไม่ใช่ที่พรอมต์ — เพราะพรอมต์คือคำขอ ไม่ใช่กลอน

1. **ไกด์ส่งข้อความหาหัวไม่ได้** — ไม่มีทางในโค้ดเลย ไม่ใช่แค่ห้ามไว้ในพรอมต์ (เจ้าของตัดขานี้ทิ้ง 15 ก.ย.)
2. **`press` กดได้เฉพาะที่แผนที่ติดป้าย `safe`** — ตรวจที่ `guideState.press()` ซึ่งเป็น**ที่เดียวที่คลิกจริง** ทั้งปุ่มในบับเบิลและ action ของโมเดลผ่านทางนี้เหมือนกัน · ฝั่ง Go แค่สะท้อน error กลับ
3. **โต๊ะ `guide` ถือเครื่องมือชิ้นเดียว** — `workbenchSkills` คืนเฉพาะแพ็ก `guide` และ**ตัด**แพ็กนั้นจากโต๊ะอื่นทุกโต๊ะ (เหตุผลเดียวกับ computer §22: เอาออก ไม่ใช่ปฏิเสธ — เครื่องมือที่ลงทะเบียนแล้วปฏิเสธทำให้โมเดลวางแผนบนเรื่องที่ไม่จริง)

**ไกด์ไม่เก็บอะไรเลยระหว่างการเปิดแต่ละครั้ง** — ไม่เก็บบทสนทนา และไม่เก็บว่าเดินค้างไว้ที่จุดไหน
เคยเก็บอย่างหลัง แล้วมันกัดทันที: กด "พาเดินดู" แล้วเด้งไปต่อที่จุดสุดท้ายของรอบก่อน เจ้าของจึงไปโผล่หน้า MCP โดยไม่รู้สาเหตุ (15 ก.ย. 2026)
คนที่ขอให้พาเดินดู แปลว่าขอตั้งแต่ต้น — การเดินต่อที่ควรมีคือแบบที่ไกด์**เสนอ** ไม่ใช่แบบที่มัน**ยัดให้**

เพิ่มเติม: โต๊ะ `guide` ประกาศ `memory: none` → `prompt.Desk.Nobody` → พรอมต์เปล่า (ทิศ + จอ + ชื่อผู้ใช้ เท่านั้น) ไม่มีไฟล์ตัวตน ไม่มีความจำชั้นไหน ไม่มีกฎโปรเจกต์ — การพับเต็มจะบอก "ผู้ช่วยคือใคร" ให้คนผิดฟัง

## 5. กฎของคำ — `why` คือของที่แพงที่สุด

`what` = อธิบายว่าปุ่มทำอะไร เขียนได้อิสระ
`why` = **ต้องมาจาก `docs/DECISIONS.md` จริง และอ้าง `§`** — ไม่มีก็**เว้นว่าง**

`guideText()` คืน `''` สำหรับ `why` ที่ไม่มี บับเบิลและ `describe` จึงไม่เคยโชว์คีย์ locale หรือเหตุผลที่แต่งขึ้น

> รอบแรกที่สร้างแผนที่ มี `why` ครบทั้ง 157 จุด ส่วนใหญ่แต่งเอง — ถูกล้างทิ้งเหลือ ~1/3 ที่อ้าง § ได้จริง
> **เหตุผลที่ผิดแย่กว่าไม่มีเหตุผล** เพราะผู้ใช้เชื่อ และมันจะกลายเป็นตำนานที่ไม่มีใครตรวจ

ฝั่งโมเดล: พรอมต์ของโต๊ะสั่งว่า `why` มาจาก `describe` เท่านั้น ห้ามคิดเอง ไม่มีก็บอกว่าไม่รู้

## 6. ขั้นตอนเมื่อคุณจะแก้ UI

### เปลี่ยนชื่อ/ย้ายปุ่ม
1. ย้าย `data-guide="<id>"` ไปกับปุ่ม — **id ไม่ต้องเปลี่ยนตามตำแหน่ง** (id คือฟีเจอร์ ไม่ใช่ที่อยู่)
2. ถ้าย้ายข้ามหน้า → แก้ `page` ในแถวของ `map.ts`
3. `npm test` — เขียวแปลว่าจบ

### ลบปุ่ม
1. ลบแถวใน `map.ts` + แถวใน `docs/GUIDE-MAP.md` + คีย์ทั้ง 3 ภาษา
2. ถ้ามันอยู่ใน `routes.ts` → เอาออกจากเส้นทางด้วย
3. `npm test`

### เพิ่มปุ่มใหม่ที่ควรอยู่ในแผนที่
1. `data-guide="area.thing"` — **ต้องเป็น string literal** (เทสต์ grep หา ไม่ได้รันโค้ด)
2. แถวใน `docs/GUIDE-MAP.md` ก่อน (ต้นทางของคำ) → `map.ts` → locale ทั้ง 3
3. `why` อ้าง § ได้ก็ใส่ ไม่ได้ก็เว้น
4. `safe` — ให้เฉพาะสิ่งที่ย้อนได้ในคลิกเดียวและไม่เปลี่ยนข้อมูล ถ้าลังเล = `false`

### เพิ่ม/ย้ายหน้าในห้อง (Settings rail, ห้องความสามารถ)
1. เพิ่ม id ใน `lib/rooms.ts` **ก่อน** — ไม่งั้นคอมไพเลอร์ไม่ให้ผ่าน
2. เพิ่มแถวใน rail ของห้อง
3. แผนที่แถวไหนที่ควรชี้หน้าใหม่ ก็แก้ `page`

### จูนไทม์ไลน์การพาเดิน
แก้ `GUIDE_ROUTES` ใน `routes.ts` อย่างเดียว — กฎ 4 ข้ออยู่หัวไฟล์นั้น คำพูดไม่ได้อยู่ที่นั่น

### จูนคำทัก
แก้ `greeting.ts` + คีย์ `guide.greet*` / `guide.room.*` ทั้ง 3 ภาษา · ห้องใหม่ที่ยังไม่มีใน `ROOM_KEY` ไม่ใช่ error — ไกด์ถอยไปใช้คำทักแบบไม่ระบุห้อง ซึ่งยังเป็นคำถามอยู่ดี

### จูนท่าเดิน
แก้ `walk.ts` อย่างเดียว — ค่าคงที่ (`SIZE`, `BUBBLE`, ระยะห่าง, ความเร็ว) อยู่ต้นไฟล์ · `BUBBLE` ต้องตรงกับ `width` ของ `.say` ใน CSS (เขียนเตือนไว้ในไฟล์แล้ว)

## 7. หนี้ที่รู้ตัว (ยังไม่ทำ — ตัดสินใจแล้วว่ารอ)

1. **`path.ts` รู้จักแค่ประตู "เข้าห้อง"** — ปุ่มที่โผล่หลังกดอย่างอื่น*ภายในหน้าเดียวกัน* (ฟอร์มสร้างโปรเจกต์ที่ต้องกด + ก่อน) ยังไม่มีทางไปถึง ไกด์จะบอกว่า "ไม่ได้อยู่บนจอตอนนี้"
   *ถ้าจะทำ:* เพิ่ม `via?: string[]` ในแถวแผนที่สำหรับกรณีเฉพาะ แล้วให้ `nextStepTo` ต่อท้าย `ROOM_DOORS` — ยังคงกฎ "คืนก้าวเดียว" ไว้
2. **แผนที่ไม่รู้จักสถานะ** — ปุ่มที่มีเฉพาะตอนต่อสมองแล้ว/มีโปรเจกต์แล้ว ดูเหมือน "ไม่อยู่บนจอ" เฉย ๆ
3. **เส้นทาง `first` จบลงที่ห้องความสามารถ** — เดินครบแล้วผู้ใช้ถูกทิ้งไว้ในห้องที่ไม่ได้ขอเปิด ควรจบที่หน้าแชท (ไทม์ไลน์เป็นของเจ้าของปรับ — `routes.ts`)
4. **หน้าที่รับ intent ระหว่างเปิดอยู่** — `Settings` ตอบ `cockpit.settingsIntent` แม้เปิดค้างอยู่แล้ว (ไกด์เดินข้าม section ได้) ตัวที่ mount ล่าสุดเท่านั้นที่รับ (`settingsMounts`) เพราะในเทสต์มีหลายตัว mount ค้าง · ห้องความสามารถยังใช้ `arriveAt()` ตอน mount อย่างเดียว — ไกด์เดินข้ามหน้าในห้องนั้นระหว่างเปิดค้างยังไม่ได้ ถ้าจะทำ ใช้แพตเทิร์นเดียวกัน
5. **ยังไม่มีบันทึกคำถามที่ตอบไม่ได้** — เคยเสนอไว้ (ไฟล์ในเครื่อง ไม่ส่งไปไหน) เจ้าของยังไม่ตัดสิน · นี่คือทางเดียวที่จะรู้ว่าแผนที่ขาดอะไร
6. **ตัวบนเดสก์ท็อป (Win32 sprite) เดินชี้ปุ่มไม่ได้** — ไกด์อยู่ในหน้าต่างเท่านั้น
7. **คำถามที่ยังเป็นของเจ้าของ:** รายการ `safe` เพิ่มเติม · ไกด์ควรมีไฟล์ตัวตนของตัวเองไหม · ให้มันโผล่เองตอนผู้ใช้นิ่งบนหน้าต่อสมองไหม

## 9. ถ้าจำอะไรได้ข้อเดียว

**แผนที่คือสัญญาระหว่าง UI กับไกด์ และสัญญาที่ไม่มีใครตรวจคือสัญญาที่จะเน่า**
ทุกอย่างในเอกสารนี้คือการทำให้การเน่าส่งเสียง — คอมไพเลอร์ก่อน เทสต์รองลงมา และที่เหลือคือวินัยกับ `§`
