## 0. สิ่งที่ตัดสินแล้ว (ห้ามเปิดใหม่)

| เรื่อง | ตัดสิน |
|---|---|
| ไกด์คืออะไร | ตัวละครที่ **เดินบน UI ของแอปเอง** ไปยืนข้างปุ่มจริง บอกว่าปุ่มนั้นคืออะไร ออกแบบด้วยเหตุผลอะไร พาไปได้ทุกหน้า |
| ทำอะไรได้ | `where` · `describe` · `point` · `goto` · `press` (เฉพาะจุดที่แผนที่ติดป้าย `safe`) — **เท่านั้น** |
| ทำอะไรไม่ได้ | ส่งข้อความหาหัว (ผู้ช่วย/โค้ด) แทนผู้ใช้ — **ตัดออกทั้งขา** รวมถึงร่างข้อความลงช่องพิมพ์ · แก้ตั้งค่า · ลบ · รันเครื่องมือใด ๆ · อ่านภาพหน้าจอ |
| ร่าง | ร่างเดียวกับ Companion (`lib/mascot/Companion.svelte` + ริก `lib/mascot/`) **คนละคน**: ยศที่สี่ `guide` ตราเข็มทิศที่มุมหน้า สีอำพัน · ตอนไกด์เปิด Companion ของหัวหายไปชั่วคราว (ช่องเดียว ไม่มีสองตัวพร้อมกัน) |
| สองสมอง ไกด์เดียว | **mapPick** (ไม่มีโมเดล: เส้นทาง + ค้นชื่อ + คลิกอะไรก็ได้แล้วอธิบาย) ต้องมีตลอด ไม่ใช่แค่ครั้งแรก · **modelPick** (LLM ถือเครื่องมือ 5 ตัว) เมื่อสมองที่ตั้งไว้ตอบได้ · สลับเองอัตโนมัติ ไม่มีสวิตช์ให้ผู้ใช้ตั้ง · ผู้ใช้เห็นคนเดียวกันตลอด |
| แหล่งความจริง | **แผนที่** (`data-guide` id + ข้อความ) เป็นแหล่งเดียวของทั้งสองสมอง · LLM เรียบเรียงได้ **แต่งเองไม่ได้** โดยเฉพาะ "ทำไมออกแบบแบบนี้" — ไม่มีในแผนที่ = ตอบว่าไม่รู้ |
| คลิกอะไรก็ได้แล้วอธิบาย | เอา — ตอนไกด์เปิด คลิกบนจุดที่มี `data-guide` = ถาม ไม่ใช่กด · ต้องมีท่าปิดที่ชัด (Esc, ปุ่ม ×, แถบบอกโหมด) |
| บทสนทนากับไกด์ | ไม่ลง sidebar ไม่ค้นเจอ ไม่เข้าความจำ หายเมื่อปิดไกด์ |
| ทัวร์เก้าฉาก (§279) | **คงไว้** ไม่แตะ ไกด์เป็นของถัดจากทัวร์ ไม่ใช่ของแทน |

## 3. เฟส 1 — แผนที่ (frontend เท่านั้น ยังไม่มีตัว ยังไม่มีโมเดล)

### 3.1 `data-guide` บนปุ่มจริง
- ติด `data-guide="<id>"` บนทุกสิ่งที่ผู้ใช้กดได้ซึ่งมีความหมายในระดับ "ฟีเจอร์": ปุ่ม แท็บ รายการเมนู สวิตช์ แถวตั้งค่า ประตู ชิป — **ไม่ติด** บนแถวข้อมูลที่เกิดจาก data (แชทแต่ละอัน โปรเจกต์แต่ละอัน) ให้ติดที่หัวกลุ่ม/ปุ่มสร้างแทน
- **ค่าต้องเป็น string literal** ในไฟล์ .svelte (ไม่ interpolate) เพื่อให้เทสต์ grep ได้ · ถ้าจำเป็นต้องมี id ตาม data ให้ใช้รูป `data-guide="area.thing"` บนตัวห่อ ไม่ใช่บนแต่ละแถว
- ขั้นต่ำเฟสนี้ (นับตอนรับงาน): sidebar ทุกปุ่ม · topbar (ประตูสลับหัว แท็บ) · composer ทุกปุ่ม (แนบไฟล์ ไมค์ ส่ง/หยุด ปุ่มปรับกลางเทิร์น) · การ์ดขอจำ · เมนูบัญชีมุมซ้ายล่างทุกแถว · ตั้งค่า: rail ทุกรายการ + หน้าตัวหลัก/พนักงาน/ลูกมือ (hero, ตรายศ, แท็บทุกอัน, ปุ่ม บันทึก/ลบ) + ต่อสมอง (ทุกแถวผู้ให้บริการ, ทดสอบการเชื่อมต่อ) + เสียง + อวตาร + เกี่ยวกับ · ห้องความสามารถทั้งห้าหน้า (MCP · สกิล · เครื่องมือในตัว · การใช้คอมพิวเตอร์ · การเชื่อมต่อ) · ออฟฟิศ/ทีม · แผงงานพื้นหลัง · คลังสตูดิโอ — **คาดว่า 120–180 id** ให้นับจริงแล้วรายงาน

### 3.2 `lib/guide/map.ts`
```ts
export type GuidePage =
  | { view: 'chat' }
  | { view: 'settings'; rail: string; tab?: string; head?: 'assistant' | 'coding' }
  | { view: 'capability'; page: string }
  | { view: 'office' } // เพิ่มตามหน้าจริงที่มี
export type GuideEntry = {
  id: string            // = data-guide
  page: GuidePage       // ไปหน้าไหนถึงจะเห็นมัน
  safe: boolean         // ไกด์กดให้ได้ไหม — true เฉพาะ เปิด/ปิด/สลับหน้า/สลับแท็บ/เปิดเมนู
  ref?: string          // อ้าง DECISIONS เช่น '§279' — ไม่ก็อปข้อความ
  synonyms?: string[]   // คำที่คนใช้เรียก (ทุกภาษา) สำหรับค้น
  // ข้อความ: ไม่อยู่ที่นี่ อยู่ใน locales ใต้คีย์ guide.<id>.name / .what / .why
}
export const GUIDE_MAP: GuideEntry[] = [ /* append only */ ]
```
- `safe: true` ให้เฉพาะสิ่งที่ย้อนได้ในคลิกเดียวและไม่เปลี่ยนข้อมูล: เปิด/ปิดกลุ่ม เปิดเมนู เปลี่ยนหน้า เปลี่ยนแท็บ · **ไม่** safe: ส่ง หยุด บันทึก ลบ สวิตช์ทุกตัว ทดสอบการเชื่อมต่อ ปุ่มที่เรียกเอนจิน ทุกอย่างที่ไม่แน่ใจ

## 4. เฟส 2 — ตัวไกด์ + สมองแผนที่ (ยังไม่มีโมเดล — ใช้ได้เต็มรูปแบบแล้ว)

### 4.3 `lib/guide/Guide.svelte` — ตัว
- mount ใน `App.svelte` ถัดจาก `<Companion />` · เมื่อ `guide.on` Companion ไม่ render (ช่องเดียว) และกลับมาเมื่อปิด — **ห้ามแก้พฤติกรรม Companion ตอนไกด์ปิด**
- รูป: `<Mascot role="assistant" accent="amber" top="bar" face="happy" prop="none" shell="pastel" pose={…} turn={…} size={72} sway />` ห่อด้วย `RankedFace tier="guide"` — ใช้ริกเดิมทั้งหมด **ห้ามเพิ่มชิ้นส่วนใหม่ใน parts.ts/poses.ts**
- ท่า (มีอยู่แล้วทั้งหมดใน `poses.ts`): เดิน `walk` (turn ±70 ตามทิศ) · ชี้จุดที่กดให้ได้ `presenting` · ชี้จุดที่กดไม่ได้ `helping` · รอคำถาม `asking` · พูด `answering` · ไม่รู้ `thinking`
- การเดิน (`point(id)`): `openPage` → `querySelector('[data-guide=id]')` → `getBoundingClientRect()` → ยืน**ขวา**ของเป้าถ้ามีที่ ไม่งั้นซ้าย → translate ด้วย transition ที่ยาวตามระยะ (ใช้โทเคนใน `motionTokens` — เพิ่ม `--dur-walk` ถ้าต้อง เทสต์ `motionTokens.test.ts` ห้ามมีตัวเลขดิบ) → วงแหวนอำพันรอบเป้า (breathe) · เป้าที่ scroll ไม่เห็น `scrollIntoView({block:'center'})` ก่อนวัด · `prefers-reduced-motion` = โผล่ทันทีไม่เดิน
- บับเบิล (สไตล์ `.say` ของ Companion): หัว = ชื่อ + ป้าย **กดให้ได้ / ชี้ได้อย่างเดียว** · เนื้อ = คืออะไร (พิมพ์ทีละตัวเหมือน Companion) · ท้าย = "ทำไมออกแบบแบบนี้" + § · แถวปุ่ม `กดให้หน่อย` (เฉพาะ safe) · `ต่อไป` (ถ้าอยู่ในเส้นทาง) · บรรทัดเล็กใต้สุด "ตอบจากแผนที่" เมื่อ `brain === 'map'` (ไม่ใช่ error ไม่มีสีเตือน)
- **บับเบิลอยู่ฝั่งตรงข้ามกับเป้าเสมอ** (ไม่บังสิ่งที่ชี้) และย้ายลงล่างเมื่อตัวยืนใกล้ขอบบน (ต้นแบบมี logic นี้ใน `GuideLab.svelte` ฟังก์ชัน `go()` — เอามาใช้ได้)
- ช่องพิมพ์เล็กติดตัว (ไม่ใช่ composer ของแชท) + ปุ่ม × ปิด · ลากได้เหมือน Companion
- แถบบางบนสุดของหน้าต่างขณะไกด์เปิด: "โหมดไกด์ — คลิกอะไรก็ได้เพื่อถาม · Esc ปิด" — นี่คือท่าปิดที่ชัด

### 4.4 คลิกอะไรก็ได้แล้วอธิบาย
- ขณะ `guide.on`: listener `click` แบบ **capture** ที่ `document` — ถ้า `event.target.closest('[data-guide]')` เจอและไม่ใช่ UI ของไกด์เอง → `preventDefault(); stopPropagation();` แล้ว `explain(id)` · ไม่เจอ → ปล่อยผ่าน
- cursor ทั้งหน้าเป็น `help` ขณะเปิด · Esc ปิดไกด์ · ปุ่ม × ปิด
- ยกเว้น: ช่องพิมพ์ของไกด์ ปุ่มในบับเบิล และ `[data-guide-passthrough]` (ใส่บนปุ่ม × ของแถบบน)

### 4.5 สมองแผนที่ `lib/guide/mapPick.ts`
```ts
export function mapPick(q: string, state): { stopId: string | null; sentence: string; route?: … }
```
ลำดับ:
1. คำสั่งเส้นทาง: "รอบแรก/พาดู/ทัวร์" → route `first` · "ต่อสมอง/ใส่คีย์" → route `brain` · "ตั้งทีม/พนักงาน" → route `team` (นิยามใน `lib/guide/routes.ts` เป็นลิสต์ id ธรรมดา)
2. "ต่อไป/ถัดไป/next" → จุดถัดไปในเส้นทางที่อยู่
3. "…อยู่ไหน / where is … / หา…" → ค้น `name` + `synonyms` (normalize: ตัดวรรณยุกต์ไม่ต้อง แค่ lowercase + trim + ตัดคำว่า ปุ่ม/หน้า/เมนู) → คะแนน substring ยาวสุดชนะ · เจอหลายอัน = เอาอันแรกแล้วบอกว่ามีอีก n
4. "นี่คืออะไร/ปุ่มนี้" โดยไม่มีชื่อ → อธิบาย `stopId` ปัจจุบัน
5. ไม่เข้าเลย → ประโยคเดียว: "ตอบจากแผนที่ได้อย่างเดียวตอนนี้ — ลองพิมพ์ชื่อสิ่งที่หา หรือคลิกมันบนจอ" (ถ้า `brain === 'map'` เพราะยังไม่ต่อสมอง ให้ต่อท้ายว่าต่อสมองแล้วถามได้อิสระ และ **ชี้ไปที่ `settings.rail.brain`** — นี่คือจุดที่ไกด์ไม่มีสมองมีค่าที่สุด)

### 4.6 ทางเข้า
1. จบทัวร์เก้าฉาก (`Tour.svelte` `onDone`) → ไกด์โผล่ครั้งเดียวพร้อมประโยค "พาเดินดูของจริงไหม" + ปุ่ม เอา/ไว้ก่อน (จำว่าเคยเสนอแล้วใน localStorage คีย์เดียว `guideOffered`)
2. เมนูมุมซ้ายล่าง แถวใหม่ "ถามไกด์" ถัดจาก "รู้จักกับ Aetox"
3. หน้าแชทว่าง: ลิงก์เล็กใต้การ์ดทัก "ให้ไกด์พาเดินดู"
4. ตั้งค่า › เกี่ยวกับ ข้าง "ดูการแนะนำอีกครั้ง"

## 5. เฟส 3 — สมอง LLM

### 5.1 โต๊ะ `internal/mode/modes/guide.md`
```
---
description: ไกด์ — เดินบน UI พาผู้ใช้ไปดูปุ่ม บอกว่าคืออะไรและออกแบบด้วยเหตุผลอะไร กดได้เฉพาะจุดที่แผนที่ให้กด
categories:
tools: guide
dispatch: none
memory: none
---
```
เนื้อ prompt ภาษาอังกฤษ (กฎ §267) สั้น ราว 150 คำ ใจความ: you are the guide of this app; you know it through the map only; every turn ends with at most ONE `point` or `goto`; explain in the user's language, two sentences, plain words; the "why" comes from `describe` verbatim in meaning — never invent a reason; if the map has no why, say so; `press` only what `describe` marks safe, and say what you pressed; you cannot send messages, change settings, or run anything — when asked, say so and point at the thing so the user can press it; never narrate your tools.
- โต๊ะนี้ **ต้องไม่ได้** skills index / MCP / shell / file tools / ask_user / todo — ตรวจใน `workbenchSkills` + เทสต์ Go ว่าชุดเครื่องมือของ session โต๊ะ guide มีชื่อเดียวคือ `guide`
- ยังไม่มีโฟลเดอร์ identity ของไกด์ในเฟสนี้ (`IdentityHeads` คงเดิม — ดูหัวข้อ 11 ข้อ 2)

### 5.2 เครื่องมือ `guide` — หนึ่ง tool ห้า action (แบบเดียวกับ `browserSkill` ใน `desktop/browser_tool.go`)
ไฟล์ `desktop/guide_tool.go` · เสนอผ่าน `appScreen.WindowTools` (desktop/screen.go) · เอนจินให้เฉพาะ session โต๊ะ guide และตัดจากโต๊ะอื่นที่จุดเดียวกับ `computerToolName` ใน `internal/engine/app.go` (~บรรทัด 4510)

| action | args | คืน |
|---|---|---|
| `where` | — | `{ page, guideAt, visible: [{id, name, safe}] }` — **ส่งเฉพาะที่เปลี่ยนจากครั้งก่อน** ของ session นั้น (เก็บ snapshot ล่าสุดไว้ฝั่ง Go ต่อ session) เพื่อไม่ให้ต้นไม้ทั้งหน้าถูกส่งซ้ำทุกรอบ |
| `describe` | `id` | `{ id, name, what, why?, ref?, safe, page }` ในภาษา UI |
| `point` | `id` | `{ ok, page }` — ตัวเดินไปยืน + วงแหวน |
| `goto` | `page` (id หน้า) | `{ ok }` |
| `press` | `id` | `{ ok }` หรือ error `not safe` |

- ทุก action → `a.emitEvent("screen:guide", {id, action, args})` → frontend ทำ → `AnswerGuide(id, resultJSON)` (binding ใหม่บน App แบบเดียวกับ `AnswerHostDir` ใน `desktop/host_files.go`) · รอ 30 วิ แล้ว error "window did not answer"
- **ผู้บังคับใช้ `safe` คือ frontend** (`press()` ใน `guide.svelte.ts` ตรวจ `GUIDE_MAP` ก่อน `el.click()`) — Go ส่งต่อและสะท้อน error · เขียนไว้ใน description ของ tool ด้วยว่า press จะถูกปฏิเสธถ้าไม่ safe (กัน round trip เปล่า)
- description ของ tool ลิสต์ **ดัชนี** แผนที่ (id + ชื่อ + safe) ไม่ใช่ข้อความเต็ม — ราว 150 บรรทัด · รายละเอียดผ่าน `describe` · ดัชนีสร้างจาก frontend ตอนเปิด session (ส่งขึ้นมาใน `NewGuideSession` ด้านล่าง) เพื่อให้ตรงกับภาษา UI ขณะนั้น

### 5.3 session ของไกด์
- binding ใหม่ `NewGuideSession(indexJSON) (id, error)`: `NewSessionAt("guide")` + ทำเครื่องหมาย `hidden` (คอลัมน์/flag ใน sessions เพิ่มเท่าที่จำเป็น) · session hidden **ไม่โผล่** ใน sidebar, ค้นหา, รายการล่าสุด, การ์ดขอจำ, สถิติ · `memory: none` ในโต๊ะทำให้ไม่แตะความจำอยู่แล้ว
- ปิดไกด์ / ปิดแอป → `DeleteSession(id)` · ตอนเปิดแอปครั้งถัดไป ล้าง session hidden ที่ค้าง
- ใช้ loop ส่งข้อความและ stream event เดิมทั้งหมด — `Guide.svelte` subscribe ด้วย `sessionId` ของมันเอง แล้วเอาข้อความสตรีมมาใส่บับเบิล (ไม่ผ่าน `Chat.svelte`) · ระวังกฎ `onScreenSession()` — session ไกด์ไม่ใช่ session บนจอ ห้ามไปเปลี่ยน `cockpit.openSession`
- ใช้โมเดล/ผู้ให้บริการเดียวกับหัวผู้ช่วยที่ตั้งไว้ (ไม่มีตัวเลือกโมเดลแยกในเฟสนี้)

### 5.4 การสลับสมอง
- `brain = 'model'` เมื่อ: มีผู้ให้บริการตั้งไว้ **และ** สร้าง session ได้ **และ** เทิร์นล่าสุดของไกด์ไม่ล้ม
- ล้มกลางเทิร์น (error/timeout 20 วิ/ไม่มีคีย์/โมเดลไม่ resident): คำถามนั้นตกไป `mapPick` ทันที บับเบิลขึ้น "ตอบจากแผนที่" และ `brain='map'` จนกว่าจะเปิดไกด์ใหม่ · ไม่มี error popup
- ผู้ใช้ไม่เห็นความต่างนอกจากบรรทัด "ตอบจากแผนที่" และคำตอบที่สั้น/ตรงกว่า

### 5.5 เทสต์
- Go `internal/engine`: session โต๊ะ guide ได้เครื่องมือชื่อ `guide` เท่านั้น (ไม่มี browser/computer/shell/ask_user/skills) · โต๊ะอื่นไม่ได้ `guide`

## 12. หนี้ที่รู้ตั้งแต่วางแผน
- แผนที่ 120–180 แถว × 3 ภาษา คือของหนักที่สุด — เขียนไทยให้ดีก่อน แปลทีหลัง
- `where` เป็น diff ต่อ session — ถ้าหน้าต่างรีโหลด snapshot ฝั่ง Go จะเก่า: ให้ `where` รับ arg `full: true` ที่ frontend ส่งครั้งแรกหลังโหลด
- ตัวบนเดสก์ท็อป (Win32 sprite) ไม่เดินชี้ปุ่มได้ — ไกด์อยู่ในหน้าต่างเท่านั้น จดใน MASCOT.md
- ทัวร์เก้าฉากกับเส้นทาง `first` ของไกด์ซ้อนกันบางส่วน — วันหนึ่งอาจยุบทัวร์เป็นเส้นทาง แต่ไม่ใช่งานนี้
