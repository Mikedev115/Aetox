# พรอมป์สำหรับด่าน `codebase trace` (รัน 22 ก.ย.)

> คู่กับ [evidence-semantic-code-map-2026-09-15.md](evidence-semantic-code-map-2026-09-15.md) §12
> และ `docs/DECISIONS.md` §298.3 · กติกาของด่านอยู่ที่ §12.5

## ก่อนรัน — สองอย่างที่ทำให้ตัวเลขอ่านได้

1. **บิลด์ที่รันต้องมี `trace`** — สาขา `feat/semantic-code-map` (ต้อง rebase บน `main` ให้เสร็จก่อนรัน — ตอนนี้ตามหลังอยู่ 2 คอมมิต) ไม่ใช่ build ที่ติดตั้งอยู่ ถ้าเครื่องที่รันไม่มี act นี้ `tool_runs` จะได้ศูนย์ด้วยเหตุที่ไม่เกี่ยวกับคุณภาพของมัน
2. **หนึ่งพรอมป์ต่อหนึ่งแชทใหม่** — ห้ามถามต่อในแชทเดิม เพราะคำตอบก่อนหน้าจะกลายเป็นบริบท และการที่โมเดลไม่ต้องเรียกอะไรเลยจะอ่านไม่ออกว่า "ไม่เรียกเพราะรู้แล้ว" หรือ "ไม่เรียกเพราะไม่รู้ว่ามี"

**พรอมป์ห้ามเอ่ยชื่อเครื่องมือ** ทั้ง `trace` และ `codebase` การที่มันถูกเรียกหรือไม่ถูกเรียกคือสิ่งที่ด่านนี้วัด — พรอมป์ที่บอกให้ใช้ ก็ได้คำตอบที่พิสูจน์อะไรไม่ได้

**วิธีเก็บหลักฐาน** ในหน้าต่าง (โต๊ะโค้ด) ดูแถวเครื่องมือใต้คำตอบ · ทางคอนโซลใช้ `aetox chat "..." --report runs.jsonl` แล้วอ่าน `tools[]` ของเทิร์นนั้น — ต้องเห็นว่ามีหรือไม่มี `"name":"codebase","act":"trace"`

## ห้าพรอมป์ และคำตอบที่ต้องได้

แต่ละข้อ "ถูก" เมื่อคำตอบมีบรรทัดที่ระบุไว้ (ตรวจจากคำตอบจริง ไม่ใช่จากความรู้สึก) บรรทัดทั้งหมดนี้อ่านจากรีโปนี้และยืนยันแล้ว

### 1. ข้ามกำแพง

```
ในโปรเจกต์นี้ RepoMapPane.svelte ตอนที่มันโหลดกราฟขอข้อมูลจากฟังก์ชัน Go ตัวไหน
และกว่าจะถึงฟังก์ชันนั้นต้องผ่านอะไรบ้าง บอกเป็นเส้นทางพร้อมไฟล์และบรรทัด
```

ต้องมี: `desktop/frontend/src/lib/workbench/RepoMapPane.svelte:219` → `desktop/frontend/wailsjs/go/main/App.js:581` → `desktop/engine_forwarders_gen.go:366` → `internal/engine/repomap_view.go:52`

บันทึกเพิ่ม: เรียก `trace` ไหม และถ้าเรียก มันเป็นคำเรียกที่เท่าไรของเทิร์น (ในรอบวัด 16 ก.ย. รอบที่เรียกใช้เป็นเครื่องมือที่สอง แล้วก็ยังไล่อ่านไฟล์เองครบสี่ไฟล์)

### 2. ทิศกลับ

```
GetRepoMapGraph ที่ฝั่ง Go ถูกเรียกจากที่ไหนบ้าง
```

ต้องมี: `desktop/engine_forwarders_gen.go:366` และ `internal/engine/rpc/client_gen.go:585`

### 3. ปลายทางที่สองของกำแพงเดียวกัน

```
ปุ่มเปิดไฟล์ข้างนอกใน MediaPane.svelte สุดท้ายไปลงที่ฟังก์ชัน Go ตัวไหน
```

ต้องมี: `desktop/frontend/wailsjs/go/main/App.js:993` → `desktop/screen_doors.go:345`

### 4. ผลกระทบ — ข้อที่แย่ที่สุดในรอบวัด

```
ถ้าผมเปลี่ยน signature ของ repomap.Graph โปรเจกต์นี้มีที่ไหนบ้างที่ต้องแก้
ไล่จากจุดเรียกทั้งหมด
```

ต้องมี: `internal/repomap/graph.go:72` และผู้เรียกในรีโปนี้

บันทึกเพิ่ม: รอบวัด 16 ก.ย. รอบนี้ **ไม่เรียก `trace` เลย** ทั้งที่เป็นคำถามที่ act นี้ควรชนะที่สุด — ถ้ารอบนี้ก็ไม่เรียกอีก แปลว่าปัญหาอยู่ที่บรรทัดในบล็อก ไม่ใช่ที่ตัว act (ดู §298.3 ท้ายสุด)

### 5. การปฏิเสธที่ถูกต้อง

```
ProgramIcon ในฝั่งเดสก์ท็อปถูกเรียกผ่าน binding เดียวกันไหม แล้วไปจบที่ไหน
```

ต้องได้: คำตอบที่บอกว่า **ยืนยันไม่ได้** เพราะ `main.App.ProgramIcon` ประกาศสองที่แบบ build-tagged (`desktop/computer_icon_windows.go:218` และ `desktop/computer_icon_other.go:10`) — การที่มันเลือกบรรทัดเดียวแล้วตอบแบบมั่นใจคือคำตอบผิด

ระวัง: ข้อนี้ตอบถูกได้ง่ายเกินไปในทางที่ไม่ได้แปลว่าเครื่องมือทำงาน — โมเดลจะเห็นการประกาศซ้ำจากการอ่านไฟล์เองก็ได้ ต้องดูว่า `tools[]` มี `trace` และคำตอบอ้างถึงบรรทัดของทั้งสองไฟล์จริง

## สิ่งที่ต้องจดต่อเทิร์น

| ที่จด | จากไหน | ใช้ตัดสินอะไร |
|---|---|---|
| `codebase trace` ถูกเรียกไหม + เป็นคำเรียกที่เท่าไร | `tools[]` | เกณฑ์ข้อ 1 (ถึง) |
| ข้อ 1–5 ถูกกี่ข้อ | คำตอบ เทียบกับบรรทัดข้างบน | เกณฑ์ข้อ 2 (ถูก) — ต้องได้ 4 ใน 5 |
| input / cached / out / rounds | `--report` | ราคาต่อเทิร์น เทียบกับ 146 tokens ที่ act นี้เพิ่มให้ทุกคำขอ |
| prefix break ของหน้าต่างนั้น | `tokenaudit -days 7` | เกณฑ์ข้อ 3 (ไม่เกินงบ) |

**ข้อควรรู้จากรอบวัด:** สามเทิร์นแรกตอบถูกทั้งสามข้อ แต่ `trace` ถูกเรียก 1 ใน 3 และย้าย input ราว 75,500 fresh tokens ต่อหนึ่งคำถาม — สามเทิร์นไม่ใช่คำตอบของด่าน และไม่มีอะไรในนั้นบอกว่าคำตอบดีขึ้น *เพราะ* เครื่องมือนี้
