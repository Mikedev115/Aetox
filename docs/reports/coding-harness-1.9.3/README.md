# Aetox 1.9.3 งานโค้ดจริง โมเดลเดียวกัน: เทียบ OpenCode · Codex CLI · omp · pi

> **มีฉบับใหม่กว่า:** [coding-harness-1.9.7](../coding-harness-1.9.7/README.md) (4 ต.ค. 2026) · รายงานทุกฉบับและฉบับล่าสุดของแต่ละเรื่องอยู่ที่[หน้ารวมรายงาน](../README.md)

> เอกสารบันทึกผล · 11 โจทย์ × 2 โมเดล × 3 รอบ = 66 รันต่อตัวครอบ · 6 ตัว (Aetox 1.9.3 · Aetox 1.9.0 · OpenCode · Codex CLI · omp · pi) = 396 ตัดออก 1 = **395 รัน**
>
> คำถามเดียว: **สั่งงานคำเดียวกันกับโมเดลตัวเดียวกัน ตัวครอบ (harness) ไหนพาโมเดลส่งงานที่ผ่านเทสต์ได้มากกว่า**
> วัดคุณภาพงานเป็นหลัก ไม่ได้แข่งกันประหยัด — เวลาและ token แสดงไว้เป็นราคาที่จ่าย
> ทุกโจทย์ตัดสินด้วยเทสต์ที่ซ่อนไว้ ผู้แข่งไม่เห็นเทสต์ระหว่างทำ ไม่มีคนให้คะแนนด้วยความรู้สึก
>
> ทุกช่องรัน 3 รอบ ตัวเลขใหญ่คือค่าเฉลี่ย ตัวเล็กใต้ตัวเลขคือรอบที่ทำได้ดีที่สุด และเป็นรอบไหน
> ข้อสอบชุดเดียวกับ[รายงานฉบับ 1.9.0](../coding-harness-2026-09-27) ผลของตัวครอบอื่นมาจากรอบวัดเดียวกันนั้น

## เด่นอะไร อ่อนอะไร

สามรอบต่อช่องยังแกว่ง ตัวเลขที่ห่างกันไม่กี่เปอร์เซ็นต์อ่านเป็น "พอ ๆ กัน" ข้อสรุปด้านล่างคือเรื่องที่เห็นซ้ำทุกรอบ

**Aetox เด่น**

- **โค้ดที่ปลอดภัย (CWEval func-sec@1)** — นำทุกตัวทั้งสองโมเดล: Luna 97.8% ต่อ 68.9% ของตัวอื่นที่ดีที่สุด · Terra 95.6% ต่อ 77.8% ของตัวอื่นที่ดีที่สุด · ฟังก์ชันที่ทำงานถูก (func@1) ก็สูงสุดทั้งสองโมเดล
- **งานโค้ดยาวหลายเทิร์นบน Luna (SlopCodeBench)** — % เทสต์ผ่านสูงสุด (91.8%) และ checkpoint ผ่านครบมากสุด (4.0 / 14) จากเดิม 3.0 ใน 1.9.0
- **Aetox + Luna ทัดเทียมตัวอื่น + Terra** — SlopCodeBench 91.8% ต่อ 91.3–92.8% ของตัวอื่นบนโมเดลที่ใหญ่กว่า และความปลอดภัยสูงกว่า (97.8% ต่อ 73.3–77.8%)
- **โจทย์ไทย** — 100% ทั้งสองโมเดล (โจทย์ที่ทีม Aetox เขียนเอง และ Aetox มีสกิลภาษาไทยติดมา อ่านแยกจากชุดมาตรฐาน)

**เทียบ 1.9.0**

- **เร็วขึ้น** — Luna 64 → 47 นาที · Terra 88 → 81 นาที โดยคุณภาพส่วนใหญ่เท่าเดิมหรือดีขึ้น
- **ดีขึ้น** — CWEval ปลอดภัย (Luna 91.1 → 97.8% · Terra 93.3 → 95.6%) · checkpoint ผ่านครบบน Luna (3.0 → 4.0) · SWE-bench ตามรายงานบั๊กบน Luna (67 → 100%)
- **ลดลง** — Web-Bench (Luna 5.7 → 5.0 · Terra 5.7 → 5.3) · SlopCodeBench บน Terra (94.3 → 92.2%) ส่วนใหญ่มาจากโจทย์ B1

**ราคาที่จ่าย**

- **ใช้เวลาและ token มากกว่า** — token รวมสูงกว่าตัวอื่น 1.2–7 เท่า ราว 90% เป็นขาเข้าที่แคชไว้ ส่วนที่ไม่ได้แคชมากกว่าราว 1.2–2.3 เท่า
  บน Terra ยังช้าที่สุด (81 นาที ต่อ 46–71 นาที) บน Luna ช้ากว่า Codex CLI และ pi (ราว 30 นาที) แต่ใกล้ OpenCode และ omp
  เหตุผลมีสองส่วน: Aetox ตรวจงานตัวเองมากกว่า และ prompt ตั้งต้นมีกติกาการทำงานกับเครื่องมือมากกว่า (หัวข้อ 2)

**Aetox อ่อน**

- **Web-Bench** — pi ทำได้มากกว่าเล็กน้อยทั้งสองโมเดล และ omp บน Terra (Luna 5.0 ต่อ 5.3 · Terra 5.3 ต่อ 5.7)
- **SlopCodeBench บน Terra** — OpenCode นำทั้ง % เทสต์ผ่านและ checkpoint ผ่านครบ (92.8% · 6.7 ต่อ 92.2% · 6.0)

**ยังสรุปไม่ได้**

- SWE-bench มีบั๊กเดียว ตามเทสต์ของชุดข้อมูลทุกตัวแกว่ง 0–100% ถ้าตรวจตามที่รายงานบั๊กขอ ทุกตัวแก้ได้แทบทุกรอบ (หัวข้อ 4)
- Web-Bench ต่างกันทีละ 1–2 งาน
- ส่วนต่างของ SlopCodeBench % เทสต์ผ่านระหว่างตัวที่อยู่กลุ่มบน เล็กกว่าการแกว่งระหว่างรอบ ต้องรันมากกว่า 3 รอบจึงจะแยกได้

## 5. กติกาการวัด

**รันที่ตัดและรันใหม่ — กฎเดียวกันทุกตัวครอบ** ของเดิมทุกรันเก็บไว้ในผลดิบ ไม่ได้ลบ

- ล้มเพราะสภาพแวดล้อม (เน็ตหลุด ล็อกอินชนกัน เครื่องปิดโปรแกรมกลางทาง) → ตัดแล้วรันใหม่
- รันที่ได้ต่ำกว่า 60% ของค่ากลางของอีกสองรอบในช่องเดียวกัน → รันใหม่หนึ่งครั้ง ใช้ผลรันใหม่ไม่ว่าจะดีขึ้นหรือไม่
- เทิร์นที่ชนเพดาน 30 นาทีไม่นับ
- ช่องที่ได้ 0 หรือตกทุกรอบ เปิดเทสต์ที่ตกเทียบกับโจทย์ก่อนยอมรับตัวเลข
- SWE-bench แสดงสองแบบ เพราะเทสต์ของชุดข้อมูลตรวจเกินกว่าที่รายงานบั๊กขอ · SlopCodeBench ติดตั้งตาม `requirements.txt` ของรันก่อนตรวจ ตามที่โจทย์สั่ง

รันที่ตัดออก 1 รัน: omp · C1 · Luna รอบ 1 — omp ทำงานเว็บครบ 5 จาก 6 งานในเทิร์น 1–5 แล้วค้างเองในเทิร์นที่ 6 จนชนเพดาน 30 นาที
(stderr ของ omp: `omp launch ended before completing`) ตามกฎข้างบน รันนี้ไม่นับ ช่องนั้นจึงเฉลี่ยจาก 2 รอบ
