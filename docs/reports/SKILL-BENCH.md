# SKILL-BENCH — สกิลของ Aetox ช่วยงานจริงแค่ไหน

> เอกสารบันทึกผล · วัดระหว่าง 25–26 ก.ย. 2026 · เจ้าของชุดทดสอบ: เซสชันวัดผล
>
> คำถามเดียวของเอกสารนี้: **ใช้โมเดลเดียวกัน งานเดียวกัน ถ้าเปิดสกิลของ Aetox เทียบกับปิดสกิล งานออกมาดีขึ้นแค่ไหน**
> และเมื่อเทียบกับ Codex CLI และ OpenCode ที่ใช้โมเดลเดียวกัน Aetox อยู่ตรงไหน
>
> ตัวเลขในนี้ส่วนใหญ่มาจากการรันงานละ 1–3 ครั้ง ผลของงานเดียวแกว่งได้ ±5–10 คะแนน
> ส่วนต่างที่เชื่อได้คือส่วนต่างที่ใหญ่ และเกิดซ้ำทุกครั้งที่รัน (ดูหัวข้อ 5)

---

## 1. วัดอย่างไร

| เรื่อง | ค่าที่ใช้ |
|---|---|
| โมเดล | `gpt-6-luna` และ `gpt-5.6-terra` ผ่านบัญชี Codex เดียวกัน ความคิดระดับ medium (Sol ไม่ได้วัดรอบนี้) |
| Aetox เปิดสกิล | ตัวแชท (`aetox chat`) บิ้วจาก commit ที่ระบุ ชั้นวางสกิลตามที่ส่งจริง |
| Aetox ปิดสกิล | exe ตัวเดียวกัน แต่ถอดสกิลออกจากทุกโต๊ะด้วยไฟล์ `skill-placements.json` ส่วนอื่นเหมือนเดิมทุกอย่าง |
| Codex CLI | ล็อกอินอย่างเดียว ไม่มีสกิลหรือคำสั่งประจำตัวของผู้ใช้ |
| OpenCode 1.18 | โฟลเดอร์ตั้งค่าแยก มีแค่ไฟล์ล็อกอิน ปิดการอ่านไฟล์ของ Claude Code |
| ที่ทำงาน | ทุกครั้งเริ่มจากโฟลเดอร์ใหม่ โฟลเดอร์ข้อมูลใหม่ อนุมัติเต็ม ไม่มีคนตอบคำถามกลางทาง |
| การให้คะแนน | ตัวตรวจอัตโนมัติทุกงาน ไม่มีคนให้คะแนนด้วยความรู้สึก (หัวข้อ 3) |
| คะแนนที่รายงาน | สัดส่วนข้อที่ผ่าน (0–100) ถ้ารันหลายครั้งจะเฉลี่ย และบอกจำนวนครั้งไว้ในวงเล็บ |

เทสต์ที่ใช้ตรวจ ไม่เคยถูกคัดลอกเข้าไปในโฟลเดอร์ที่โมเดลทำงาน และทุกงานมีเฉลยที่พิสูจน์แล้วว่าผ่านตัวตรวจครบ

### 7.1 ด่านสกิล: ทุกสกิลที่สร้างใหม่หรือปรับ ต้องผ่านตัวนี้

`scripts/skill-gate.py` วัดสกิลทีละตัวด้วยสามแบบ บนตัวแอปเดียวกัน โมเดลเดียวกัน และข้อความเดียวกัน

| แบบ | คืออะไร | ตอบคำถามอะไร |
|---|---|---|
| off | ทุกสกิลเปิดยกเว้นตัวที่วัด | ถ้าไม่มีสกิลนี้ ได้คะแนนเท่าไร |
| full | ชั้นสกิลตามที่ส่งจริง | โมเดลหาสกิลนี้เจอเองไหม |
| forced | full แล้วเติมบรรทัดสั่งเปิดสกิลไว้หน้าข้อความแรก | เนื้อหาของสกิลช่วยได้จริงไหม เมื่อถูกอ่านแน่ๆ |

**อ่านผล** (สองโมเดลรวมกัน ต่างกันไม่เกิน 0.08 ถือว่าเท่ากัน)

| ผล | คำตัดสิน |
|---|---|
| forced และ full ดีกว่า off | เก็บ |
| forced ดีกว่า off แต่ full เท่ากับ off | เนื้อหาดี แต่โมเดลไม่เปิดเอง ให้แก้คำเรียก |
| forced เท่ากับ off | ไม่มีผล ให้ลบ |
| forced แย่กว่า off | ให้ลบ หรือตัดคำที่โมเดลทำตาม |

**รายงานบอกเหตุผลด้วย:** รายงานไม่ได้ให้แค่คะแนน ยังบอกว่าข้อตรวจข้อไหนขยับระหว่างสามแบบ และยกบรรทัดของสกิลที่โผล่ในงานแบบ forced แต่ไม่โผล่ในแบบ off เลย เหตุผลจึงอ่านได้จากงานจริง ไม่ต้องเดา

**ข้อสอบแบ่งตามหมวดในไฟล์เดียว:** `benchmarks/behavior/gate.json`
- **เปลี่ยนข้อสอบ:** แก้รหัสงานใต้ชื่อสกิลนั้น
- **เพิ่มหมวด:** เพิ่มหนึ่งรายการใน `categories`
- **เพิ่มสกิล:** ใส่ชื่อสกิลไว้ใต้หมวดของมัน พร้อมรหัสงานที่ใช้วัด
- **ตรวจความครบ:** `--list` บอกว่ามีสกิลไหนที่ยังไม่อยู่ในหมวดใด หรือมีรหัสงานไหนที่ไม่มีใน tasks.json

```
python scripts/skill-gate.py --list
python scripts/skill-gate.py aetox-database --build HEAD            # บิวด์สะอาดจาก commit แล้ววัด
python scripts/skill-gate.py ui-libraries --exe <aetox.exe>        # ทุกสกิลในหมวด
python scripts/skill-gate.py aetox-shadcn --report-only --root <โฟลเดอร์ผล>
```

**ค่าตั้งต้น**
- โมเดล Terra กับ Sol
- แบบละ 3 รอบ
- ใช้ 3 ช่อง และรวมทุกเซสชันไม่เกิน 6 ช่อง ถ้ามีเซสชันอื่นใช้อยู่เกินที่เหลือ ด่านจะรอก่อน
- เจอ `Chat failed` ครั้งแรกจะหยุดทั้งคิว แยกครั้งนั้นไป `_invalid/` และเขียนไฟล์ `STOP`

ผลอยู่ที่ `<โฟลเดอร์ผล>/gate-<สกิล>.md` และ `.json`
