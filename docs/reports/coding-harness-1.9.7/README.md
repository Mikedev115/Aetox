# Aetox 1.9.7 งานโค้ดจริง โมเดลเดียวกัน: เทียบ OpenCode · Codex CLI · omp · pi

> เอกสารบันทึกผล · 11 โจทย์ × 2 โมเดล × 3 รอบ = 66 รันต่อตัวครอบ · 7 ตัว (Aetox 1.9.7 · Aetox 1.9.3 · Aetox 1.9.0 · OpenCode · Codex CLI · omp · pi) = 462 ตัดออก 1 = **461 รัน**
> ฉบับนี้ต่อจาก[ฉบับ 1.9.3](../coding-harness-1.9.3) · Aetox 1.9.7 วัดวันที่ 4 ต.ค. 2026 ตัวครอบอื่นใช้ผลรอบเดิม (27–28 ก.ย.) โมเดลและบัญชีเดียวกัน
>
> คำถามเดียว: **สั่งงานคำเดียวกันกับโมเดลตัวเดียวกัน ตัวครอบ (harness) ไหนพาโมเดลส่งงานที่ผ่านเทสต์ได้มากกว่า**
> วัดคุณภาพงานเป็นหลัก ไม่ได้แข่งกันประหยัด — เวลาและ token แสดงไว้เป็นราคาที่จ่าย
> ทุกโจทย์ตัดสินด้วยเทสต์ที่ซ่อนไว้ ผู้แข่งไม่เห็นเทสต์ระหว่างทำ ไม่มีคนให้คะแนนด้วยความรู้สึก
>
> ทุกช่องรัน 3 รอบ ตัวเลขใหญ่คือค่าเฉลี่ย ตัวเล็กใต้ตัวเลขคือรอบที่ทำได้ดีที่สุด และเป็นรอบไหน
> ข้อสอบชุดเดียวกับ[รายงานฉบับ 1.9.0](../coding-harness-2026-09-27) ผลของตัวครอบอื่นมาจากรอบวัดเดียวกันนั้น

## เด่นอะไร อ่อนอะไร

สามรอบต่อช่องยังแกว่ง ตัวเลขที่ห่างกันไม่กี่เปอร์เซ็นต์อ่านเป็น "พอ ๆ กัน" ข้อสรุปด้านล่างคือเรื่องที่เห็นซ้ำทุกรอบ

**Aetox เด่น**

- **โค้ดที่ปลอดภัย (CWEval func-sec@1)** — ยังนำทุกตัวทั้งสองโมเดล: Luna 93.3% ต่อ 68.9% ของตัวอื่นที่ดีที่สุด · Terra 93.3% ต่อ 77.8%
- **งานโค้ดยาวหลายเทิร์นบน Terra (SlopCodeBench)** — % เทสต์ผ่านสูงสุดในตาราง (94.6% ต่อ 92.8% ของ OpenCode) และ checkpoint ผ่านครบเท่าตัวที่ดีที่สุด (6.7 / 14)
- **แก้บั๊กใน repo จริงบน Terra (SWE-bench)** — ผ่านเทสต์ทางการครบ 3 รอบ (เดิม 2 ใน 3) เท่ากับ pi
- **โจทย์ไทย** — Terra 100% · Luna 97.0% (โจทย์ที่ทีม Aetox เขียนเอง อ่านแยกจากชุดมาตรฐาน)

**เทียบ 1.9.3**

- **Terra ดีขึ้นทั้งคุณภาพและราคา** — SlopCodeBench 92.2 → 94.6% · checkpoint ผ่านครบ 6.0 → 6.7 · SWE-bench ทางการ 67 → 100% · เวลา 81 → 68 นาที · token 9.1 → 7.1 ล้าน
- **Luna แย่ลง** — SlopCodeBench 91.8 → 88.6% (ส่วนใหญ่มาจาก B1 และ S2) · checkpoint ผ่านครบ 4.0 → 3.3 · Web-Bench 5.0 → 4.3 · CWEval func-sec@1 97.8 → 93.3% · เวลาเท่าเดิม (47 → 46 นาที) token น้อยลง (5.7 → 4.9 ล้าน)
- **ตรวจงานตัวเองน้อยลง** — คำสั่งตรวจงานต่อรัน 7.2 → 5.9 · รันที่เขียนเทสต์เอง 15% → 12% · บน Terra ไม่กระทบคุณภาพ บน Luna น่าจะเป็นส่วนหนึ่งที่ทำให้งานหลายเทิร์นตก

**ราคาที่จ่าย**

- **token ยังมากกว่าตัวอื่น** — บน Luna มากที่สุด (4.9 ล้าน ต่อ 0.8–4.5 ล้าน) บน Terra รองจาก omp ราว 90% เป็นขาเข้าที่แคชไว้
- **เวลา** — Luna 46 นาที เท่า OpenCode ช้ากว่า Codex CLI และ pi (ราว 30 นาที) · Terra 68 นาที เร็วกว่า omp ช้ากว่าที่เหลือ

**Aetox อ่อน**

- **Luna บนงานหลายเทิร์น** — SlopCodeBench 88.6% เป็นอันดับ 3 รองจาก OpenCode (90.8%) และ omp (88.7%) ตกลงมาจากอันดับ 1 ในฉบับ 1.9.3
- **Web-Bench** — Luna 4.3 ต่ำสุดร่วมกับ OpenCode · Terra 5.0 ต่อ 5.7 ของ omp และ pi
- **Aetox + Luna ไม่ทัดเทียมตัวอื่น + Terra บนงานหลายเทิร์นแล้ว** — SlopCodeBench 88.6% ต่อ 91.3–92.8% (ฉบับ 1.9.3 ยังทัดเทียม)

**ยังสรุปไม่ได้**

- SWE-bench มีบั๊กเดียว ตามเทสต์ของชุดข้อมูลทุกตัวแกว่ง 0–100% ถ้าตรวจตามที่รายงานบั๊กขอ ทุกตัวแก้ได้แทบทุกรอบ (หัวข้อ 4)
- Web-Bench ต่างกันทีละ 1–2 งาน
- ตัวครอบอื่นวัดเมื่อ 27–28 ก.ย. ส่วน Aetox 1.9.7 วัด 4 ต.ค. ฝั่งผู้ให้บริการโมเดลอาจเปลี่ยนไประหว่างนั้น

## 5. กติกาการวัด

**รันที่ตัดและรันใหม่ — กฎเดียวกันทุกตัวครอบ** ของเดิมทุกรันเก็บไว้ในผลดิบ ไม่ได้ลบ

- ล้มเพราะสภาพแวดล้อม (เน็ตหลุด ล็อกอินชนกัน เครื่องปิดโปรแกรมกลางทาง) → ตัดแล้วรันใหม่
- รันที่ได้ต่ำกว่า 60% ของค่ากลางของอีกสองรอบในช่องเดียวกัน → รันใหม่หนึ่งครั้ง ใช้ผลรันใหม่ไม่ว่าจะดีขึ้นหรือไม่
- เทิร์นที่ชนเพดาน 30 นาทีไม่นับ
- ช่องที่ได้ 0 หรือตกทุกรอบ เปิดเทสต์ที่ตกเทียบกับโจทย์ก่อนยอมรับตัวเลข
- SWE-bench แสดงสองแบบ เพราะเทสต์ของชุดข้อมูลตรวจเกินกว่าที่รายงานบั๊กขอ · SlopCodeBench ติดตั้งตาม `requirements.txt` ของรันก่อนตรวจ ตามที่โจทย์สั่ง

รันที่ตัดออก 1 รัน: omp · C1 · Luna รอบ 1 — omp ทำงานเว็บครบ 5 จาก 6 งานในเทิร์น 1–5 แล้วค้างเองในเทิร์นที่ 6 จนชนเพดาน 30 นาที
(stderr ของ omp: `omp launch ended before completing`) ตามกฎข้างบน รันนี้ไม่นับ ช่องนั้นจึงเฉลี่ยจาก 2 รอบ
ถ้านับรันนี้ด้วยคะแนนตอนถูกตัด (เทสต์ผ่าน 20 / 23 · 5 งาน) ช่องนั้นจะเป็น 20.3 / 23 แทน 20.5 และ Web-Bench ของ omp บน Luna เป็น 4.7 / 6 แทน 4.5 — อันดับในตารางไม่เปลี่ยน
Aetox และตัวครอบอื่นไม่มีรันที่ชนเพดานในรอบวัดนี้

รายการรันที่รันใหม่ของตัวครอบอื่นและ Aetox 1.9.0 อยู่ใน[รายงานฉบับ 1.9.0](../coding-harness-2026-09-27)

**Aetox 1.9.7 ให้คะแนนใหม่ในสภาพแวดล้อมสะอาด** — เชลล์ที่เปิดคิววัดมีตัวแปร `PYTHONIOENCODING=utf-8:surrogateescape` ติดมา
โปรแกรมที่พิมพ์ข้อความภาษาไทยจึงส่ง UTF-8 ออกมา ขณะที่เทสต์ซ่อนถอดรหัสด้วย cp874 ของ Windows และได้ค่า `None`
รอบวัดก่อนหน้าให้คะแนนโดยไม่มีตัวแปรนี้ จึงให้คะแนนทุกรันของ 1.9.7 ใหม่ด้วยไฟล์งานเดิมและตัวให้คะแนนเดิม แต่ไม่มีตัวแปรนี้
