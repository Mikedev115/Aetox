# งานโค้ดจริง โมเดลเดียวกัน: Aetox · OpenCode · Codex CLI

> เอกสารบันทึกผล · วัดเมื่อ 27 ก.ย. 2026 · ข้อสอบ 11 โจทย์ × 2 โมเดล × 3 ตัวครอบ = 66 รัน
>
> คำถามเดียว: **ให้โมเดลตัวเดียวกันทำงานโค้ดชิ้นเดียวกัน ตัวครอบ (harness) ไหนส่งงานที่ผ่านเทสต์ได้มากกว่า**
> ทุกโจทย์ตัดสินด้วยเทสต์ที่ซ่อนไว้ ผู้แข่งไม่เห็นเทสต์ระหว่างทำ ไม่มีคนให้คะแนนด้วยความรู้สึก
>
> นี่คือรอบนำร่อง (pilot) ช่องละ 1 รัน ส่วนต่างเล็ก ๆ (1–3 เทสต์) แกว่งได้เมื่อรันซ้ำ
> ส่วนต่างที่ควรอ่านคือส่วนต่างที่ใหญ่ ข้อสอบ เทสต์ และผลรายรันอยู่ในโฟลเดอร์นี้ทั้งหมด ตรวจซ้ำได้

Aetox บน **GPT-6 Luna** (รุ่นเล็ก) เทียบกับอีกสองตัวบน **GPT-5.6 Terra** (รุ่นที่ใหญ่กว่า)

ใน 4 ตัวชี้วัดหลักของชุดมาตรฐาน Aetox บนรุ่นเล็กได้เท่าหรือสูงกว่าอีกสองตัวที่ใช้รุ่นใหญ่กว่า
ตัวครอบที่อ่านโค้ด รันตรวจ และแก้จนผ่านก่อนส่ง ดึงงานจากโมเดลเล็กได้มากกว่าที่ตัวโมเดลให้เอง

ราคาที่จ่ายคือเวลาและ token ที่มากขึ้น และยังมีช่องว่างให้ไปต่อ: checkpoint ที่ผ่านครบทุกเทสต์บน Luna ยังได้แค่ 2 จาก 14
(พลาดทีละไม่กี่เทสต์กระจายหลาย checkpoint) ขณะที่อีกสองตัวบน Terra ได้ 7

**ความยุติธรรมที่ควรรู้**

- ทั้งสามตัวใช้โมเดล บัญชี ระดับความคิด ข้อความ และไฟล์ตั้งต้นเดียวกัน ต่างกันแค่ตัวครอบ
- Aetox เปิดสกิลที่ติดมากับตัวติดตั้งตามที่ผู้ใช้ได้จริง OpenCode ไม่มีสกิลติดมา Codex ถูกปิดสกิลระบบ ปลั๊กอิน และค้นเว็บ
  ให้เหลือแค่ตัวครอบกับล็อกอิน เหมือนที่ OpenCode ได้
- Codex รอบแรกล้ม 3 รันตั้งแต่ก่อนทำงาน (ล็อกอินชนกับแอป Codex ที่เปิดอยู่บนเครื่อง ได้ error `refresh_token_reused`)
  ทั้ง 3 รันถูกทิ้งแล้วรันใหม่ทั้งหมด ไม่มีรันไหนในตารางที่ล้มเพราะล็อกอิน
- S4 (code_search) ได้สูงสุด 23/25 บน Windows แม้ใช้เฉลยของชุดข้อสอบเอง — ทุกตัวที่ได้ 23/25 คือเต็มเท่าที่ทำได้
- เวลาวัดขณะรันพร้อมกัน 3 รัน ใช้เทียบกันได้ แต่ตัวเลขเดี่ยวจะช้ากว่ารันทีละรัน
