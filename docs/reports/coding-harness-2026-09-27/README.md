## เด่นอะไร อ่อนอะไร

สามรอบต่อช่องยังแกว่ง ตัวเลขที่ห่างกันไม่กี่เปอร์เซ็นต์อ่านเป็น "พอ ๆ กัน" ข้อสรุปด้านล่างคือเรื่องที่เห็นซ้ำทุกรอบ

**Aetox เด่น**

- **โค้ดที่ปลอดภัย (CWEval func-sec@1)** — นำทุกตัวทั้งสองโมเดล: Luna 88.9% ต่อ 68.9% ของตัวอื่นที่ดีที่สุด · Terra 93.3% ต่อ 77.8% ของตัวอื่นที่ดีที่สุด
- **โจทย์ไทย** — ดีที่สุดหรือเท่าที่สุด (โจทย์ที่ทีม Aetox เขียนเอง และ Aetox มีสกิลภาษาไทยติดมา อ่านแยกจากชุดมาตรฐาน)
- **SlopCodeBench** — อยู่กลุ่มบนทุกรอบ บน Terra 1.9.1 ได้ % เทสต์ผ่านสูงสุดเท่า 1.9.0 (94.3%) และ checkpoint ผ่านครบเท่า OpenCode (6.7 / 14)

**ราคาที่จ่าย**

- **ใช้เวลาและ token มากกว่า** — 1.9.1 เร็วขึ้นจาก 1.9.0 (Luna 64 → 58 นาที · Terra 88 → 77 นาที) แต่ยังช้ากว่าตัวอื่น
  token รวมสูงกว่า 1.3–8 เท่า ราว 90% เป็นขาเข้าที่แคชไว้ ส่วนที่ไม่ได้แคชมากกว่าราว 1.3–2.7 เท่า
  เหตุผลมีสองส่วน: Aetox ตรวจงานตัวเองมากกว่า และ prompt ตั้งต้นมีกติกาการทำงานกับเครื่องมือมากกว่า (หัวข้อ 1 "ทำไมใช้มากกว่า")

**Aetox อ่อน**

- **บน Luna พลาดทีละน้อยกระจายหลายจุด** — % เทสต์ผ่านของ SlopCodeBench สูง แต่ checkpoint ที่ผ่านครบทุกเทสต์น้อยกว่า OpenCode

**ยังสรุปไม่ได้**

- SWE-bench มีบั๊กเดียว ตามเทสต์ของชุดข้อมูลทุกตัวแกว่ง 0–100% ถ้าตรวจตามที่รายงานบั๊กขอ เกือบทุกตัวแก้ได้แทบทุกรอบ (หัวข้อ 3)
- Web-Bench ต่างกันทีละ 1–2 เทสต์
- ส่วนต่างของ SlopCodeBench % เทสต์ผ่านระหว่างตัวที่อยู่กลุ่มบน เล็กกว่าการแกว่งระหว่างรอบ ต้องรันมากกว่า 3 รอบจึงจะแยกได้

### token แยกส่วนที่แคช (ค่าเฉลี่ยต่อรอบ 11 โจทย์)

ตัวเลข token ในตารางบนรวมขาเข้าที่ส่งซ้ำทุกรอบของบทสนทนา ส่วนใหญ่เป็นข้อความเดิมที่ผู้ให้บริการแคชไว้ (hit)
ซึ่งคิดราคาต่ำกว่าขาเข้าใหม่หลายเท่า (ตัวอย่าง DeepSeek V4.1 Flash: hit ถูกกว่า miss 50 เท่า)
ตัวเลขที่สะท้อนภาระจริงคือ **ไม่ได้แคช (miss)** กับ **ขาออก** — แต่ละตัวครอบรายงาน token ตามนิยามของตัวเอง อ่านเทียบกันได้คร่าว ๆ

  แต่ test_patch ของชุดข้อมูลตรวจทั้ง `client_ip` และ `remote_ip` ทุกรันที่แก้ `remote_ip` ไปด้วยผ่าน ทุกรันที่แก้แค่ `client_ip` ไม่ผ่าน
  เราให้คะแนนซ้ำทั้ง 36 รัน แบบทางการได้ผลตรงเดิมทุกรัน และเพิ่มคอลัมน์ † ที่ตัดเฉพาะกรณี `remote_ip` ออก คอลัมน์ทางการยังอยู่
- **SlopCodeBench:** โจทย์สั่งให้ประกาศ dependency ใน `requirements.txt` แต่ตัวตรวจรุ่นแรกใช้ `.venv` ที่ตัวแข่งทิ้งไว้โดยไม่ติดตั้งตามไฟล์นั้น
  omp 5 รันเขียน `cssselect` ไว้ใน `requirements.txt` แต่ไม่ได้ติดตั้งลง `.venv` จึงตกเกือบทุกเทสต์
  ให้คะแนนใหม่โดยติดตั้งตาม `requirements.txt` ก่อนตรวจ: S1 Terra รอบ 1–3 จาก 6 · 2 · 6 เป็น 3 · 48 · 46 / 51 · S1 Luna รอบ 2 จาก 2 เป็น 48 / 51 · S2 Luna รอบ 1 จาก 3 เป็น 33 / 44
  รันอื่นทุกตัวครอบมีแพ็กเกจครบใน `.venv` อยู่แล้ว การติดตั้งเพิ่มจึงไม่เปลี่ยนคะแนนของรันเหล่านั้น

**ตัดตามกฎเวลา:** เทิร์นที่ชนเพดาน 30 นาทีไม่นับ — เหลือ 1 รัน (omp C1 Luna รอบ 1) ช่องนั้นจึงเฉลี่ยจาก 2 รอบ
