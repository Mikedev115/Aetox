## ส่วนที่ 1 — ตกลงกันก่อนว่าหน้านี้เป็นอะไร

**ปัญหาที่แก้:** วันนี้ onboarding มี 6 ขั้น: เลือกภาษา → เลือกทางเชื่อมโมเดล → ใส่คีย์ → เลือกระดับอนุมัติ →
(ติดตั้งส่วนเสริม) → จอ "เสร็จแล้ว" 1.6 วินาทีแล้วปิด คนใหม่เข้ามาเจอโต๊ะเปล่าโดยไม่รู้ว่าผู้ช่วยกับโค้ด
ต่างกันยังไง พนักงานคืออะไร ทำไมมีการ์ด "ขอจำเรื่องนี้ไว้" โผล่มา และข้อมูลไปไหน — ปัญหาเดียวกับที่ทำให้
ผู้ใช้คนหนึ่งบอกว่า "ไม่รู้ว่าตัวหลักปรับแต่งได้" (DECISIONS §266)

**ที่วาง (เสนอ):** หลังเลือกภาษา ก่อนถามเรื่องโมเดล — เพราะขั้น "เลือกทางเชื่อมโมเดล" ถามคำถามที่คนใหม่
ยังตอบไม่ได้ (คีย์ / บัญชี / โมเดลในเครื่อง) ถ้ารู้ก่อนว่า Aetox ทำงานกับโมเดลเล็กในเครื่องได้ดี คำตอบจะต่างไป
ทางเลือกอีกทางคือวางเป็นหน้าสุดท้ายก่อนปิด — ข้อดีคือคนอยากใช้เร็วไม่ต้องรอ ข้อเสียคือถึงตอนนั้นเขาเลือก
ทางเชื่อมไปแล้ว **เจ้าของตัดสิน**

**กติกาของหน้า**
- ข้ามได้ทุกฉาก ("ข้าม" มุมขวาบน) ไม่มีฉากไหนบังคับดู — คนที่รู้แล้วไม่ควรจ่ายเวลา
- แต่ละฉากหนึ่งความคิด หนึ่งภาพเคลื่อนไหว ข้อความบนจอไม่เกิน 3 บรรทัด คำอธิบายยาวอยู่ในเอกสารนี้ ไม่ใช่บนจอ
- เล่นซ้ำได้จาก ตั้งค่า › เกี่ยวกับ ("ดูการแนะนำอีกครั้ง") — หน้าที่ดูได้ครั้งเดียวคือหน้าที่ไม่มีใครกล้าข้าม
- ใช้ rig หุ่นตัวจริง (lib/mascot) ไม่วาดรูปใหม่ — ตัวที่อยู่ในหน้าแนะนำต้องเป็นตัวเดียวกับที่นั่งอยู่บนโต๊ะทีหลัง
- ชื่อผู้ช่วยในฉากใช้ชื่อที่ตั้ง ถ้ายังไม่ตั้งใช้ "Aetox" (ค่าเดียวกับ prompt.go) — ไม่มีคำว่า "มัน" บนจอ

## ส่วนที่ 2 — บทของแต่ละฉาก

รูปแบบ: **บนจอ** = ข้อความที่คนเห็นจริง (สั้น) · **ภาพ** = อนิเมชันที่เล่น · **สอนอะไร** = สิ่งที่ต้องรู้เมื่อออกจากฉาก ·
**ที่มา** = ไฟล์/ตัวเลขที่ยืนยันได้

### ฉาก 0 — เปิด

**บนจอ**
> Aetox อยู่บนเครื่องคุณ
> ผู้ช่วยที่ลงมือทำ ไม่ใช่แค่ตอบ

**ภาพ:** หุ่นตัวเดียวเดินเข้ามากลางจอ (pose idle → wave) ฉากหลังเป็นหน้าต่างแอปจาง ๆ ที่ค่อย ๆ ชัดขึ้นเป็นสี่ห้อง
(สไลด์ · เบราว์เซอร์ · ไฟล์ · เทอร์มินัล) แล้วหุ่นชี้ไปทีละห้อง

**สอนอะไร:** Aetox ไม่ใช่กล่องแชท — เป็นแอปที่มีห้องทำงานอยู่ในหน้าต่างเดียวกับบทสนทนา และตัวช่วยทำงานในห้องที่คุณกำลังดู

**ที่มา:** README § Highlights ("Four rooms in the same window as the conversation")

### ฉาก 1 — ผู้ช่วยสองคน

**บนจอ**
> คุณมีผู้ช่วยสองคน
> **ผู้ช่วย** — คุยทุกวัน ทำได้ทุกอย่างบนเครื่อง
> **โค้ด** — เขียนโปรแกรม มีไฟล์ เชลล์ Git

**ภาพ:** หุ่นตัวเดียวจากฉาก 0 แยกตัวเป็นสอง (morph) ตัวซ้ายเป็นหัวผู้ช่วย ตัวขวาเป็นหัวโค้ด (headOf ของแต่ละโต๊ะ —
ตัวโค้ดมีเสาอากาศ/รอยขีดต่างกันตาม rig) ใต้แต่ละตัวมีป้ายชื่อโต๊ะ แล้วห้องที่แต่ละคนใช้สว่างขึ้นใต้ตัว:
ผู้ช่วย = สไลด์ เบราว์เซอร์ ไฟล์ เทอร์มินัล · โค้ด = เพิ่ม Git และไทม์ไลน์

**สอนอะไร:** สองโต๊ะ ไม่ใช่สองแอป สลับได้จากแถบบน แต่ละคนมีหน้าที่ คำสั่งประจำตัว สมอง และ**ความจำของตัวเอง**
(โต๊ะโค้ดไม่อ่านความจำของผู้ช่วย และกลับกัน — คำสั่งเรื่องโค้ดไม่ไปรกโต๊ะที่คุยเรื่องเอกสาร)

**ที่มา:** README § Two doors, one app · DECISIONS §266–267 · desk manifests ใน internal/mode

### ฉาก 2 — ตั้งชื่อกันได้

**บนจอ**
> ตั้งชื่อให้ผู้ช่วยได้ ถ้าไม่ตั้ง ชื่อ Aetox
> บอกชื่อคุณได้ — จะได้เรียกกันถูก

**ภาพ:** ป้ายชื่อใต้หุ่นผู้ช่วยกะพริบเป็นช่องพิมพ์ พิมพ์ตัวอย่างชื่อลงไป หุ่นหันมาโค้งรับ · แล้วช่องพิมพ์ที่สองโผล่ฝั่งผู้ใช้
("คุณชื่อ…") หุ่นพูด (บับเบิล) ทักด้วยชื่อนั้น — **ฉากนี้พิมพ์ได้จริง** เป็นช่องกรอกของ onboarding ไม่ใช่แค่ภาพ
ปล่อยว่างได้ทั้งสองช่อง

**สอนอะไร:** ชื่อผู้ช่วยตั้งที่ ตั้งค่า › ตัวหลัก › ตัวตน (แยกต่อโต๊ะ) · ชื่อของคุณอยู่ที่ ตั้งค่า › เกี่ยวกับคุณ และไปถึงผู้ช่วยทุกโต๊ะ
ทุกเอเจน (prompt `person()`) ผู้ช่วยจะเรียกชื่อแบบเพื่อนร่วมงาน ไม่ใช่ทุกประโยค — และ**ไม่ต้องขอจำชื่อ** เพราะรู้อยู่แล้ว

**ที่มา:** internal/prompt/prompt.go `identityFor` (ชื่อว่าง = "Aetox") และ `person()` · DECISIONS §270 · §273

### ฉาก 3 — เติบโตไปกับคุณ: ความจำสามชั้น

**บนจอ**
> ผู้ช่วยจำได้ข้ามแชท — แต่**ไม่มีอะไรถูกจำโดยคุณไม่อนุมัติ**
> ของคุณ · ของผู้ช่วย · สิ่งที่ผู้ช่วยเรียนรู้เอง

**ภาพ:** การ์ด "ขอจำเรื่องนี้ไว้" (MemoryCard ตัวจริง) ลอยขึ้นจากบทสนทนา มีปุ่ม อนุมัติ / ไม่เอา · กดอนุมัติ การ์ดบินไปเข้า
กล่องหนึ่งในสามกล่องที่เรียงอยู่:
- **เกี่ยวกับคุณ** (USER.md) — คุณเป็นใคร ทำอะไรอยู่ ชอบให้ทำงานด้วยแบบไหน → ทุกโต๊ะ ทุกเอเจนอ่านเหมือนกัน
- **ของผู้ช่วย** (MEMORY.md / โต๊ะโค้ดมีไฟล์ของตัวเอง) — เครื่องนี้เป็นยังไง และ**สิ่งที่งานสอนผู้ช่วยเอง**: วิธีไหนได้ผลกับคุณ
  กฎที่ตัวเองถือ
- **ของพนักงานแต่ละคน** — บทเรียนของงานที่คนนั้นทำ ไม่ปนกับคนอื่น
การ์ดใบที่สองกด "ไม่เอา" → หายไป และมีข้อความเล็ก "จะไม่ถูกขออีก"

**สอนอะไร:**
1. เครื่องมือ memory **เขียนไม่ได้** — ได้แค่เสนอ คุณเป็นคนกดเสมอ
2. มีผลตั้งแต่แชทถัดไป ไม่ใช่แชทนี้ (การ์ดบอกไว้แล้ว — เหตุผลทางเทคนิคคือ prefix cache ไม่ต้องพูดบนจอ)
3. ทุกอย่างเป็นไฟล์ markdown ธรรมดา เปิดแก้ ลบทีละบรรทัดได้ที่ ตั้งค่า › ตัวหลัก › ความจำ / เกี่ยวกับคุณ
4. ที่ปฏิเสธไปจะไม่ถูกขอซ้ำในคำอื่น ที่จำแล้วจะไม่ถูกขอสองรอบ
5. ปิดทั้งระบบได้ในสวิตช์เดียว (ตั้งค่า › ทั่วไป › ให้ Aetox เรียนรู้จากงานที่ทำ)

**ที่มา:** README § What it learns, and what you approve · internal/learned/tool.go (`about: user | self | machine`) · DECISIONS §266.1, §273

### ฉาก 4 — ข้อมูลอยู่ที่ไหน

**บนจอ**
> ทุกอย่างอยู่ในเครื่องคุณ — `%AppData%\aetox`
> ผู้พัฒนาไม่มีเซิร์ฟเวอร์ที่รับข้อความ ไฟล์ หรือคีย์ของคุณ

**ภาพ:** โฟลเดอร์หนึ่งใบตรงกลาง มีของไหลเข้าไป: บทสนทนา · ความจำ · ตั้งค่า · คีย์ (ไอคอนกุญแจล็อกด้วยโล่ = DPAPI)
รอบนอกวาดขอบเครื่องเป็นเส้นประ มีลูกศรออกจากขอบ**เส้นเดียว** ชี้ไป "ผู้ให้บริการโมเดลที่คุณเลือก" · แล้วสลับภาพ:
เลือก "โมเดลในเครื่อง (Ollama / LM Studio)" → ลูกศรเส้นนั้นหายไป ไม่มีอะไรออกจากขอบเลย

**สอนอะไร:**
- ไม่มีสถิติการใช้งานส่งออก ไม่มี analytics ไม่มีรายงานข้อผิดพลาดอัตโนมัติ (รายงานเมื่อคุณกดเองเท่านั้น)
- ที่ออกจากเครื่องคือข้อความ/ไฟล์ที่คุณส่งให้**ผู้ให้บริการโมเดลที่คุณตั้งเอง** ตรง ๆ ไม่ผ่านใคร ภายใต้นโยบายของเจ้านั้น
- คีย์เข้ารหัสด้วย Windows DPAPI ผูกกับบัญชี Windows ของคุณ ผู้ใช้อื่นบนเครื่องเดียวกันถอดไม่ได้
- ใช้โมเดลในเครื่อง = ไม่มีอะไรออกไปเลย
- ลบโฟลเดอร์นั้น = หายหมด
- ⚠ privacy.html มีข้อยกเว้นเรื่อง "ถ้ายังไม่ตั้ง provider ใช้ตัว built-in" และกรณีเครือข่ายอีก 5 กรณี (อัปเดต · ส่วนเสริม ·
  รายงานปัญหา · …) — บนจอพูดแค่หลักการ ลิงก์ "อ่านฉบับเต็ม" ไปที่หน้านั้น **ห้ามพูดเกินหน้านั้น**

**ที่มา:** docs/privacy.html (24 ส.ค. 2026) — ถ้อยคำบนจอต้องเป็นเซตย่อยของหน้านี้เท่านั้น

### ฉาก 5 — ยศสามระดับ

**บนจอ**
> หนึ่งบริษัทเล็ก ๆ บนเครื่องคุณ
> **ผู้ช่วย** สั่งงาน · **พนักงาน** ทำงานเฉพาะทาง · **ลูกมือ** วิ่งงานย่อย

**ภาพ:** ผังองค์กรโตขึ้นทีละชั้น หัวผู้ช่วยอยู่บน (ตราหัว RankPip แบบ E) → แถวพนักงานโผล่ใต้ (doc · sheet · github ·
automation · deepresearch · editor · video แต่ละตัวมีหน้าตาของตัวเองจาก agentLook) → แถวลูกมือเล็กกว่า (explore ·
general) ลูกศรวิ่ง**จากผู้ช่วยเท่านั้น** ไม่มีเส้นระหว่างพนักงานด้วยกัน (ดาวมีศูนย์เดียว)

**สอนอะไร — ทำไมต้องแบ่ง:**
- **พนักงานแต่ละคนปักโมเดลของตัวเองที่ผู้ให้บริการของตัวเอง** — คนที่เปิดหน้าเว็บยี่สิบหน้าใช้ของถูก คนที่ต้องชั่งน้ำหนักสิ่งที่พบ
  ใช้ของแรง **บิลตามงาน ไม่ตามงานที่ยากที่สุดในกอง**
- **ความจำแยกคน** — สิ่งที่ deepresearch เรียนรู้เรื่องแหล่งข้อมูล ไม่รั่วไปปนกับดุลยพินิจของ doc เรื่องสัญญา
- **เครื่องมือแคบลงได้** — พนักงานเลือกหยิบเฉพาะที่ใช้ บล็อกเครื่องมือเล็ก โมเดลเล็กจึงไม่หลง
- **ลูกมือประหยัดอะไร:** งานสำรวจ/อ่านไฟล์ยาว ๆ เกิดใน**บริบทของลูกมือ** ไม่ใช่ในแชทหลัก แชทหลักจึงไม่บวมด้วยผลลัพธ์ที่อ่านครั้งเดียว —
  ประหยัดโทเคนทุกรอบถัดไป และเป็นเหตุผลที่โมเดลเล็กคุมงานยาวได้
- **ปรับแต่งได้ลึกกว่า** — พนักงานหนึ่งคนคือหนึ่งโฟลเดอร์ (AGENT.md · MEMORY.md · STARTERS.md · skills/ ส่วนตัว)
  จ้างคนที่แปดคือวางโฟลเดอร์ ไม่ต้องรอรุ่นใหม่ · ลูกมือปรับได้เรื่องโมเดล พรอมต์ เพดานก้าว หน้าตา — แต่ไม่ใช่สิ่งที่มันเอื้อมถึง

### ฉาก 6 — ทีมเอเจน

**บนจอ**
> ทีม = รายชื่อพนักงานที่โต๊ะหนึ่งจ้าง
> แต่ละแชทจ้างจากทีมเดียวตลอดชีวิตของมัน — หรือไม่จ้างเลย

**ภาพ:** จากผังในฉาก 5 ลากกรอบล้อมพนักงาน 3 คนเป็น "ทีม" ป้ายชื่อทีมโผล่ (ตัวอย่างที่แอปมีให้: **ผู้ช่วยในคอมพิวเตอร์**)
แล้วชิปข้างช่องพิมพ์ในแชทเปลี่ยนเป็นชื่อทีมนั้น · โต๊ะโค้ดมีกรอบทีมของตัวเองอีกชุด

**สอนอะไร — ทีมดีตรงไหน:**
- โต๊ะละชุดทีม ผู้ช่วยกับโค้ดไม่ใช้ทีมร่วมกัน (งานคนละแบบ คนละคน)
- แชทหนึ่งจ้างจากทีมเดียว → ผู้ช่วยรู้ว่ามีใครให้เรียกบ้าง ไม่ต้องอ่านรายชื่อทั้งบริษัททุกรอบ (บล็อกเครื่องมือเล็กลง)
- ทีมเป็นไฟล์ธรรมดา (`teams/<ชื่อ>/TEAM.md`) เปลี่ยนชื่อ ตัด ลบได้ · จัดที่ ตั้งค่า › ทีม
- คุยกับพนักงานตรง ๆ ได้สามทาง: ให้ผู้ช่วยมอบงาน (สูงสุด 4 คนพร้อมกัน) · เปิดแชทกับคนนั้นเอง · `@ชื่อ` ในช่องพิมพ์ —
  ประโยคไปถึงตามตัวอักษร ไม่ถูกเรียบเรียงใหม่

### ฉาก 7 — จุดเด่นของ Aetox

**บนจอ**
> เบา · เร็ว · ทำงานกับโมเดลเล็กได้ดี
> เพราะความสามารถอยู่ในแอป ไม่ได้อยู่ในพารามิเตอร์ของโมเดล

**ภาพ:** มาตรวัดสองอัน (RAM · ขนาดบนดิสก์) เข็มตกลงมาที่ตัวเลขของ Aetox แล้วแถบเทียบของแอปอื่นยืดยาวออกไปข้าง ๆ ·
สลับเป็นภาพเบราว์เซอร์ที่ทุกปุ่มถูกแปะเลข → รายการข้อความส่งให้หุ่น → หุ่นกดถูกโดยไม่ต้อง "มอง"

**สอนอะไร — ที่วัดแล้ว (ตัวเลขจาก BENCHMARK.md ข้อ 13 / README § Measured):**
| | Aetox | ที่มา |
|---|---|---|
| ตัวติดตั้ง | 34.6 MB | README ตารางวัด |
| บนดิสก์ | 83.4 MB สองไฟล์ (`aetox.exe` 50.9 + `aetox-engine.exe` 32.5) | README ตารางวัด |
| RAM ที่ commit (เปิดเปล่า นิ่ง 60 วิ) | 252 MB ⁽ᵈ⁾ | README ตารางวัด — **หมายเหตุ (d) ต้องตามไปด้วย: วัดก่อนแยก engine, process ขาดไปหนึ่ง** |
| ประกอบหนึ่งเทิร์น | 0.32 ms | README |
| เทียบขนาด | Copilot CLI 2× · Claude Code 3× · Zed 5× · OpenCode 6× · Codex 8× | BENCHMARK.md §4 |

⚠ ตัวเลข RAM/CPU บนจอ **ต้องวัดใหม่ก่อนปล่อย** — เครื่องวัดคือ 32 GB เครื่องเดียว ยังไม่ทวนบนเครื่องสเปกต่ำ (BENCHMARK.md
บอกไว้เอง) และเลข RAM วัดก่อนแยก engine · ถ้าไม่วัดใหม่ บนจอพูดได้แค่ "ตัวติดตั้ง 34.6 MB" กับตัวคูณขนาด ซึ่งเป็นเลขที่ไม่ขึ้นกับเครื่อง

**ที่อธิบายได้ (ไม่ใช่ตัวเลข แต่เป็นกลไก):**
- **โมเดลเล็กคุมเบราว์เซอร์ได้แม่นเท่าโมเดลที่มองเห็น** — ชั้นควบคุมของเราแปะป้ายทุกองค์ประกอบบนหน้าเว็บแล้วส่งเป็นรายการข้อความ
  โมเดลกดด้วยเลขอ้างอิง ไม่ใช่เดาพิกัด → โมเดล text-only ไม่มี vision ก็ทำได้
- **OCR ไทย/อังกฤษ · ถอดเสียงออฟไลน์** เป็นเครื่องมือที่แอปขับ ไม่ใช่โมเดลทำ → โมเดล 9B/35B บน GPU ของคุณทำงานพวกนี้ได้เท่าโมเดลใหญ่
- **บล็อกเครื่องมือมีเพดาน** และไม่ขยับระหว่างแชท → prefix cache ของผู้ให้บริการทำงาน (DeepSeek วัดได้ ~97% cache hit)
- **แอปเป็น Go + WebView2 ไม่ใช่ Electron** — ไม่มี Chromium ของตัวเองแบกมาอีกตัว
- **24 ผู้ให้บริการ** cloud และในเครื่อง (Ollama · LM Studio) สลับกลางแชทได้โดยบริบทไม่หาย

**ที่มา:** README § Highlights, § Measured, not claimed · BENCHMARK.md · codex-prompt-cache-gap (memory)

### ฉาก 8 — ปิด

**บนจอ**
> พร้อมแล้ว — {ชื่อผู้ช่วย} รออยู่ที่โต๊ะ

**ภาพ:** หุ่นทั้งสองเดินกลับไปนั่งประจำโต๊ะของตัวเอง (ตัวผู้ช่วยนั่งโต๊ะที่กำลังจะเปิด) หน้าต่างแอปจริงเฟดเข้ามาแทนฉากหลัง
แล้ว onboarding เดินต่อไปขั้นเลือกทางเชื่อมโมเดล (หรือปิด ถ้าวางไว้ท้าย)

## ส่วนที่ 3 — "อะไรอีกดี" — จุดเด่นที่ผมเสนอเพิ่ม (เจ้าของเลือก)

เรียงจากที่มั่นใจว่าพูดได้เพราะมีของจริง → ที่ควรพูดแต่ต้องเลือกคำ

1. **ทุกอย่างเป็นไฟล์ที่คุณเปิดอ่านได้** — ความจำ พนักงาน ทีม สกิล คำสั่งประจำตัว ล้วนเป็น markdown ในโฟลเดอร์เดียว ไม่มีอะไรฝังใน
   ฐานข้อมูลที่อ่านไม่ออก · "ทำไมมันคิดแบบนั้น" ตอบได้เสมอเพราะทุกการตัดสินใจเรื่องความจำถูกบันทึก
2. **เครื่องยนต์แยกจากหน้าต่าง และย้ายไปเครื่องอื่นได้** — ตั้งค่า › เครื่องระยะไกล ใส่ Linux host หนึ่งเครื่อง แอปส่ง engine ไปทาง ssh
   ของคุณเอง แล้วแชท ไฟล์ เทอร์มินัล Git เป็นของเครื่องนั้น **คีย์ไม่เคยออกจากเครื่องที่หน้าต่างอยู่** (engine ขอให้หน้าต่างเซ็นทุกคำขอ) —
   จุดนี้แข็งมาก แต่เป็นเรื่องของคนที่มีเครื่องสองเครื่อง อาจไม่ใช่ฉากสำหรับคนเปิดครั้งแรก → เสนอเป็นบรรทัดเดียวในฉาก 7 หรือเก็บไว้ docs
3. **เพื่อนร่วมโต๊ะบนเดสก์ท็อป** — หุ่นออกจากหน้าต่างไปอยู่บนจอจริง (หน้าต่าง Win32 ไม่มีเบราว์เซอร์ข้างหลัง) ลากไปจอไหนก็ได้ ทักชื่อ
   อ่านคำตอบให้ฟัง → เป็นของที่**เห็นแล้วเข้าใจทันที** เหมาะจะโผล่ในฉาก 0 หรือ 8 มากกว่าเป็นหัวข้อ
4. **สร้างสไลด์เป็นไฟล์ .html ไฟล์เดียวที่เป็นของคุณ** — แก้มือได้ เปิดได้ทุกเครื่อง ส่งออก pdf/png/jpg
5. **ไม่มีอะไรถูกทำโดยไม่ผ่านระดับอนุมัติที่คุณเลือก** — ถาม / เฉพาะที่เสี่ยง / เต็มที่ เปลี่ยนได้จากช่องพิมพ์ทุกเมื่อ (คนใหม่กลัวเรื่องนี้มากกว่า
   เรื่องความจำ — เสนอแทรกในฉาก 4 หนึ่งบรรทัด)
6. **ภาษาไทยเป็นภาษาแรก ไม่ใช่คำแปล** — UI เอกสาร และวิธีที่ผู้ช่วยเขียนความจำ ใช้ภาษาที่คุณคุยด้วย
7. ที่**ไม่ควร**พูดบนจอ: "ประหยัดโทเคน X%" หรือ "เร็วกว่า X เท่า" ทุกตัวที่ยังไม่มีในตาราง BENCHMARK — กติกาของโปรเจกต์คือวัดก่อนอ้าง
   และหน้าแรกของแอปคือที่ที่คำอ้างจะถูกจับได้ง่ายที่สุด
